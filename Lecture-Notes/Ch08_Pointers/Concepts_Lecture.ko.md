## 1. 포인터 기초

### 1.1 포인터 개념

메모리는 **연속된 바이트**의 나열이며, 각 바이트는 고유한 **주소(address)** 를 갖는다. **포인터(pointer)** 란 주소 그 자체이고, **포인터 변수**란 주소를 저장하는 변수이다. 메모리 주소가 가질 수 있는 값의 범위를 **메모리 주소 공간(address space)** 이라 한다.

```text
메모리 구조 (간략화)
주소          값
┌──────────┬──────────┐
│  0x1000  │    10    │  ← int a = 10;
├──────────┼──────────┤
│  0x1004  │    20    │  ← int b = 20;
├──────────┼──────────┤
│  0x1008  │  0x1000  │  ← int *p = &a;  (p에 a의 주소 저장)
└──────────┴──────────┘
```

*그림 1. 변수 a, b와 a를 가리키는 포인터 p의 메모리 배치*

| 아키텍처 | 포인터 크기 | 주소 범위 |
|:---------|:-----------|:---------|
| 32비트 | 4바이트 | `0x00000000` ~ `0xFFFFFFFF` |
| 64비트 | 8바이트 | `0x0000000000000000` ~ `0xFFFFFFFFFFFFFFFF` |

*표 1. 아키텍처별 포인터 크기와 주소 범위*

> **핵심:** 포인터는 변수의 이름을 모르더라도 **주소를 통해** 해당 변수에 접근할 수 있게 해 준다. 이것이 포인터의 핵심 능력이다.

### 1.2 포인터 선언

**문법:**

```c
자료형 *포인터이름;
```

`자료형`은 포인터가 가리킬 변수의 타입이다. `*`는 이 변수가 포인터임을 나타내는 포인터 수식어이다. 어떤 데이터 타입의 변수를 가리키는지에 따라 포인터의 데이터 타입이 정해지며, 예를 들어 `int` 변수를 가리키는 포인터는 `int*`형이다.

```c
int *p;      // int를 가리키는 포인터
double *q;   // double을 가리키는 포인터
char *r;     // char를 가리키는 포인터
```

**`*`의 위치는 상관없으며 세 가지 형태가 모두 같다.**

```c
int* p;    // OK
int *p;    // OK (권장)
int * p;   // OK
```

> **주의:** `int *p` 스타일을 권장한다. `int* p, q;`라고 쓰면 `p`만 포인터이고 `q`는 일반 `int`이다. `int *p, *q;`라고 써야 둘 다 포인터임이 명확하다.

```c
int* p, q;    // p는 int*, q는 int   (혼동 유발!)
int *p, *q;   // p, q 모두 int*      (명확)
```

**포인터의 크기는 가리키는 타입에 관계없이 같다.**

```c
int *p;
double *q;
char *r;

printf("%zu\n", sizeof(p));  // 8 (64비트 시스템)
printf("%zu\n", sizeof(q));  // 8 (64비트 시스템)
printf("%zu\n", sizeof(r));  // 8 (64비트 시스템)
```

포인터는 데이터가 아니라 주소를 저장하므로, 포인터의 크기는 가리키는 데이터 타입이 아니라 플랫폼이 정한다. 일반적인 플랫폼에서 모든 포인터는 32비트에서 **4바이트**, 64비트에서 **8바이트**를 차지한다.

### 1.3 포인터 초기화

**`&`(주소 연산자)** 는 변수의 메모리 주소를 반환한다. `&` 연산의 결과는 `&` 다음에 쓴 변수에 대한 포인터형의 주소이며, `int` 변수 `a`에 대해 `&a`는 `int*`형이다.

```c
int a = 10;
int *p = &a;   // p에 a의 주소를 저장

printf("a의 주소: %p\n", (void *)&a);   // 예: 0x7ffee3c0
printf("p의 값:   %p\n", (void *)p);    // 같은 주소
```

**`&` 연산자의 제약:** `&`는 **변수(lvalue)** 에만 사용할 수 있으며, 다음과 같은 상수나 수식에는 사용할 수 없다.

```c
&10        // 오류: 리터럴 (주소 없음)
&(a + 1)   // 오류: 수식 결과 (임시값, 주소 없음)
#define MAX 100
&MAX       // 오류: 매크로 (전처리 시 치환됨, 주소 없음)
```

**NULL 포인터:** 아무것도 가리키지 않는 포인터이다. `NULL`은 표준 C 라이브러리 헤더에 정의된 매크로 상수로 값은 0이다(구현에 따라 `((void *)0)`으로 정의된다). `NULL`은 메모리 0번지를 가리킨다는 뜻이 아니라 포인터가 어떤 변수도 가리키지 않는다는 뜻이며, 포인터를 어떤 변수의 주소로 초기화할지 알 수 없을 때 `NULL`로 초기화한다.

```c
int *q = NULL;   // 명시적으로 아무것도 가리키지 않음
int *r = 0;      // NULL과 동일
```

> **참고:** **팁.** 포인터는 항상 초기화한다. 초기화되지 않은 포인터는 쓰레기 주소를 갖고 있으며, 역참조하면 **정의되지 않은 동작**(크래시, 데이터 손상 등)이 발생한다.

**형식 지정자 `%p`** 는 주소를 16진수로 출력한다.

```c
int x = 42;
int *p = &x;
printf("p = %p\n", (void *)p);   // p = 0x7ffee4b8 (예시)
```

### 1.4 역참조 연산자 `*`

**역참조(indirection)** 연산자 `*`는 포인터가 가리키는 주소에 저장된 값에 접근한다. 간접 참조 연산자라고도 하며, **읽기**와 **쓰기**가 모두 가능하다. `*` 연산의 결과는 포인터가 가리키는 변수 자체이다.

```c
int a = 10;
int *p = &a;

printf("%d\n", *p);   // 10 (읽기: p가 가리키는 주소의 값)

*p = 20;               // 쓰기: p가 가리키는 주소의 값을 변경
printf("%d\n", a);     // 20 (p를 통해 a가 수정됨)
```

`p`가 `a`를 가리킬 때, `*p`와 `a`는 **같은 메모리 위치의 다른 이름**이다. 즉 `*p`를 쓰면 그 자리에 `a`를 쓴 것처럼 처리된다. 포인터 변수 `p`도 변수이므로 자신의 주소 `&p`를 따로 갖는다.

```text
   p ──────► ┌───────┐
             │  20   │  ← *p와 a는 같은 위치를 가리킴
             └───────┘
             주소: 0x1000
```

*그림 2. 포인터 p가 가리키는 변수 a*

**`*` 연산자의 제약:** `*`는 **포인터**에만 사용할 수 있으며, 일반 변수나 정수 수식에는 사용할 수 없다.

```c
int a = 10;
*a         // 오류: a는 포인터가 아님
*(a + 1)   // 오류: (a + 1)은 포인터가 아님
```

> **핵심:** 포인터 문맥에서 `*` 기호는 두 가지 의미를 갖는다. (1) 선언문 `int *p;`에서는 `p`가 포인터임을 나타내고, (2) 수식 `*p`에서는 `p`를 역참조하여 `p`가 가리키는 주소의 값에 접근함을 나타낸다.

### 1.5 포인터의 용도

포인터를 왜 사용하는가? 교재는 두 가지 핵심 상황을 강조한다.

| 상황 | 설명 |
|:----|:----|
| 함수에서 2개 이상의 값을 반환해야 할 때 | C 함수는 `return`으로 하나의 값만 반환할 수 있다. 변수의 주소를 전달하면 함수 안에서 원본을 수정할 수 있다. |
| 함수에 배열을 전달할 때 | 배열은 전달할 때 포인터로 변환(decay)된다. 포인터를 사용하면 복사 없이 효율적으로 배열에 접근할 수 있다. |

*표 2. 포인터가 필요한 두 가지 상황*

```c
// 예제: 포인터를 통한 다중 값 반환
void divide(int a, int b, int *quotient, int *remainder) {
    *quotient = a / b;
    *remainder = a % b;
}

int main() {
    int q, r;
    divide(17, 5, &q, &r);
    printf("17 / 5 = %d 나머지 %d\n", q, r);  // 3 나머지 2
    return 0;
}
```

그 밖에 포인터를 이용하면 어떤 변수를 가리킬지 미리 알 수 없는 경우에도 포인터가 가리키는 변수에 대해 작업하는 코드를 작성할 수 있다. 즉 하나의 코드를 여러 변수에 공통으로 쓸 수 있다.

### 1.6 `const` 포인터

`const` 키워드는 포인터가 수정할 수 있는 대상을 제한한다. `const`의 위치에 따라 의미가 달라진다.

| 선언 | 의미 | `*p` 변경 가능 여부 | `p` 변경 가능 여부 |
|:----|:----|:---------------|:--------------|
| `const int *p` | 상수 int를 가리키는 포인터 | 불가 | 가능 |
| `int *const p` | int를 가리키는 상수 포인터 | 가능 | 불가 |
| `const int *const p` | 상수 int를 가리키는 상수 포인터 | 불가 | 불가 |

*표 3. `const`의 위치에 따른 세 가지 `const` 포인터*

```c
int a = 10, b = 20;

// 상수 int를 가리키는 포인터: *p1 수정 불가, p1 재대입 가능
const int *p1 = &a;
// *p1 = 30;    // 오류: p1을 통해 값을 수정할 수 없음
p1 = &b;        // OK: p1이 이제 b를 가리킴

// int를 가리키는 상수 포인터: *p2 수정 가능, p2 재대입 불가
int *const p2 = &a;
*p2 = 30;       // OK: a를 30으로 수정
// p2 = &b;     // 오류: p2가 가리키는 대상을 변경할 수 없음

// 상수 int를 가리키는 상수 포인터: 둘 다 불가
const int *const p3 = &a;
// *p3 = 40;    // 오류
// p3 = &b;     // 오류
```

`const int *p`는 가리키는 변수를 `const` 변수처럼 읽기만 하는 **읽기 전용 포인터**이고, `int *const p`는 선언할 때 특정 변수의 주소로 초기화한 뒤 다른 변수를 가리킬 수 없는 그 변수의 **전용 포인터**이다. `const int *const p`는 두 성질을 모두 가지므로 반드시 초기화해야 한다. 세 가지 중 실제로 주로 쓰이는 것은 읽기 전용 포인터이다.

> **참고:** **팁.** 선언을 **오른쪽에서 왼쪽으로** 읽으면 이해하기 쉽다. `const int *p`는 "p는 const인 int를 가리키는 포인터"(값이 상수)이고, `int *const p`는 "p는 int를 가리키는 const 포인터"(포인터 자체가 상수)이다.

### 1.7 포인터 사용 시 주의 사항

첫째, 포인터는 항상 특정 변수를 가리키게 하거나 널 포인터로 만든다. 널 포인터를 역참조하면 실행 오류가 발생하여 일반적으로 프로그램이 비정상 종료되므로, 널 포인터일 수 있는 포인터는 `NULL`이 아닌지 확인한 뒤에만 역참조한다.

```c
int *q = NULL;
if (q != NULL) {
    printf("%d\n", *q);   // q가 널 포인터가 아닐 때만 역참조
}
```

둘째, 포인터의 데이터 타입과 포인터가 가리키는 변수의 데이터 타입이 같아야 한다. 데이터 타입이 다르면 컴파일러가 경고(최신 컴파일러에서는 오류)를 내며, 경고를 무시하고 실행하면 메모리를 다른 데이터 타입으로 해석하여 잘못된 값을 읽거나 쓰게 된다.

```c
double d = 3.14;
int *pi = &d;   // 경고: 호환되지 않는 포인터형
```

셋째, 초기화하지 않은 포인터를 역참조하지 않는다. `int *p;`만 선언한 지역 포인터에는 쓰레기 주소가 들어 있으므로 `*p = 5;`는 어디인지 알 수 없는 메모리에 값을 쓴다. 이런 포인터를 흔히 **와일드 포인터(wild pointer)** 라고 하며, 운이 좋으면 즉시 비정상 종료되고 운이 나쁘면 다른 변수의 값을 조용히 망가뜨린다. 같은 이유로 `int *p = (int *)0x1000;`처럼 주소 값을 직접 정해 넣는 것도 피한다. 일반적인 운영체제에서 프로그램이 쓸 수 있는 메모리의 위치는 실행할 때마다 운영체제가 정하므로, 소스 코드에 적은 절대 주소가 유효한 변수를 가리킨다는 보장이 없다. 포인터에는 `&`로 얻은 변수의 주소나 `NULL`만 넣는다.

### 1.8 포인터 수식의 단계별 추적

포인터를 다루는 코드는 "포인터 자체의 값(주소)"이 바뀌는 문장과 "포인터가 가리키는 변수의 값"이 바뀌는 문장을 구분하여 추적한다. 다음 코드를 한 문장씩 실행하며 변수를 출력한다.

```c
int a = 10, b = 20;
int *p = &a, *q = &b;

*p = *q + 5;
printf("1: a = %d, b = %d, *p = %d, *q = %d\n", a, b, *p, *q);
p = q;
printf("2: a = %d, b = %d, *p = %d, *q = %d\n", a, b, *p, *q);
*p = 1;
printf("3: a = %d, b = %d, *p = %d, *q = %d\n", a, b, *p, *q);
(*q)++;
printf("4: a = %d, b = %d, *p = %d, *q = %d\n", a, b, *p, *q);
printf("p == q is %d\n", p == q);
```

```text
1: a = 25, b = 20, *p = 25, *q = 20
2: a = 25, b = 20, *p = 20, *q = 20
3: a = 25, b = 1, *p = 1, *q = 1
4: a = 25, b = 2, *p = 2, *q = 2
p == q is 1
```

| 문장 | 바뀌는 것 | `p`가 가리키는 변수 | `a` | `b` |
|:-----|:-----|:-----|-----:|-----:|
| 초기 상태 | 없음 | `a` | 10 | 20 |
| `*p = *q + 5;` | `p`가 가리키는 `a`의 값 | `a` | 25 | 20 |
| `p = q;` | 포인터 `p`의 값(주소) | `b` | 25 | 20 |
| `*p = 1;` | `p`가 가리키는 `b`의 값 | `b` | 25 | 1 |
| `(*q)++;` | `q`가 가리키는 `b`의 값 | `b` | 25 | 2 |

*표 4. 포인터 수식을 실행할 때 바뀌는 대상*

`p = q;`는 `b`의 값을 `a`에 복사하는 것이 아니라 `p`가 `b`를 가리키게 만들 뿐이므로 `a`는 25로 남는다. 그 뒤로 `p`와 `q`는 같은 주소를 가지므로 `p == q`는 참이고, `*p`와 `*q`는 모두 `b`를 뜻한다. `(*q)++`에 괄호가 필요한 이유는 후위 `++`가 `*`보다 우선순위가 높아서, `*q++`라고 쓰면 `*(q++)`가 되어 `b`가 아니라 포인터 `q`가 증가하기 때문이다.

### 1.9 포인터 변수의 메모리 그림

포인터도 메모리에 자리를 차지하는 변수이므로, 포인터에는 "자신의 주소"와 "저장한 값(다른 변수의 주소)"이 따로 있다. 다음 코드는 `int` 변수 `a`와 그 주소를 저장한 포인터 `p`의 주소, 값, 크기를 출력한다.

```c
int a = 10;
int *p = &a;

printf("&a = %p, a = %d\n", (void *)&a, a);
printf("&p = %p, p = %p, *p = %d\n", (void *)&p, (void *)p, *p);
printf("sizeof(a) = %zu, sizeof(p) = %zu\n", sizeof(a), sizeof(p));
```

```text
&a = 0x16f4feb18, a = 10
&p = 0x16f4feb10, p = 0x16f4feb18, *p = 10
sizeof(a) = 4, sizeof(p) = 8
```

```text
        주소           내용
      ┌──────────────┬────────────────────┐
p     │ 0x16f4feb10  │ 0x16f4feb18 ───────┼──┐   p의 값 = a의 주소 (8바이트)
      ├──────────────┼────────────────────┤  │
a     │ 0x16f4feb18  │ 10                 │◄─┘   *p는 이 칸 (4바이트)
      └──────────────┴────────────────────┘
```

*그림 3. 포인터 p와 변수 a의 메모리 배치*

출력에서 `p`의 값과 `&a`가 같으므로 `p`는 `a`를 가리킨다. `&p`는 그와 다른 주소로, 포인터 `p` 자신이 놓인 자리이다. `*p`는 `p`에 저장된 주소로 가서 읽은 값 10이다. `a`는 4바이트, `p`는 64비트 주소 하나를 담는 8바이트이다. 주소의 실제 값은 실행할 때마다 달라지지만, `p`의 값과 `&a`가 같다는 관계는 변하지 않는다. 교재의 예제는 32비트로 빌드한 결과여서 주소가 8자리 16진수(4바이트)로 출력되지만, 64비트로 빌드하면 포인터가 8바이트가 되므로 출력이 이 예처럼 길어진다.

`&`와 `*`는 서로 반대 방향의 연산이다. `&a`는 변수에서 주소로, `*p`는 주소에서 변수로 간다. 따라서 `*&a`는 `a`와 같고, `p`가 유효한 변수를 가리키면 `&*p`는 `p`와 같다. 이 관계를 이용하면 복잡한 수식도 한 단계씩 풀 수 있다. 예를 들어 위의 `p`에 대해 `*p + 1`은 `a + 1`인 11이고, `&a == p`는 참이며, `*&p`는 `p` 자신이다.

## 2. 배열과 포인터

### 2.1 포인터 연산

포인터에 정수를 더하거나 빼면, 컴파일러는 1바이트가 아니라 **가리키는 타입의 크기**만큼 이동한다. 즉 `p + N`은 `p`가 가리키는 데이터 타입 N개만큼 더한 주소이며, `p++`과 `++p`는 주소를 데이터 타입 1개 크기만큼 증가시킨다.

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;    // p는 arr[0]을 가리킴
```

```text
p     p+1    p+2    p+3    p+4
│      │      │      │      │
▼      ▼      ▼      ▼      ▼
┌──────┬──────┬──────┬──────┬──────┐
│  10  │  20  │  30  │  40  │  50  │
└──────┴──────┴──────┴──────┴──────┘
0x1000  0x1004  0x1008  0x100C  0x1010
        (+4B)   (+4B)   (+4B)   (+4B)
```

*그림 4. 포인터 연산으로 이동하는 int 배열 원소의 주소*

| 포인터 타입 | `p + 1` 이동량 |
|:-----------|:--------------|
| `int *` | 4바이트 (`sizeof(int)`) |
| `double *` | 8바이트 (`sizeof(double)`) |
| `char *` | 1바이트 (`sizeof(char)`) |

*표 5. 포인터 타입별 `p + 1`의 이동량*

**지원되는 연산:**

| 연산 | 의미 |
|:----|:----|
| `p + n` | n개 요소만큼 앞으로 이동 |
| `p - n` | n개 요소만큼 뒤로 이동 |
| `p++` | 다음 요소로 이동 |
| `p--` | 이전 요소로 이동 |
| `p1 - p2` | 두 포인터 사이의 요소 수 (바이트 수가 아님) |

*표 6. 포인터에 허용되는 연산*

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

printf("%d\n", *(p + 2));   // 30 (세 번째 요소)

p++;
printf("%d\n", *p);         // 20 (두 번째 요소)

int *q = &arr[4];
printf("%ld\n", q - p);     // 3 (요소 단위 거리, 바이트가 아님)
```

> **참고:** 두 포인터의 차는 `<stddef.h>`의 `ptrdiff_t`형이며, `printf`로 출력할 때 정확한 형식 지정자는 `%td`이다. 위의 `%ld`는 `long`과 `ptrdiff_t`의 크기가 같은 64비트 Linux와 macOS에서는 맞게 출력되지만, `long`이 4바이트인 64비트 Windows에서는 형식이 맞지 않는다.

> **주의:** 포인터 연산은 배열 범위 안(또는 배열 끝의 바로 다음 위치까지)에서만 유효하다. 범위를 벗어나면 **정의되지 않은 동작**이 발생한다.

### 2.2 포인터를 배열처럼 사용

`p + i` 연산은 포인터가 가리키는 주소에 마치 배열이 있는 것처럼 메모리에 접근한다. 따라서 `type*`형 포인터는 `type`형 변수뿐 아니라 `type`형 배열의 원소도 가리킬 수 있고, 포인터에 **첨자 연산자 `[]`** 를 사용할 수 있다. `p[i]`는 항상 `*(p + i)`로 처리된다.

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

printf("%d\n", p[0]);       // 10  (*(p + 0)과 동일)
printf("%d\n", p[2]);       // 30  (*(p + 2)과 동일)
printf("%d\n", *(p + 4));   // 50  (p[4]와 동일)
```

| 표기법 | 동치 | 의미 |
|:------|:----|:----|
| `p[i]` | `*(p + i)` | p에서 i번째 요소에 접근 |
| `&p[i]` | `p + i` | p에서 i번째 요소의 주소 |

*표 7. 첨자 표기와 포인터 표기의 대응*

### 2.3 배열을 포인터처럼 사용

인덱스 없이 쓴 **배열 이름**은 배열의 시작 주소, 즉 첫 번째 요소의 주소이다. 그래서 배열 이름은 **포인터 상수(pointer constant)** 처럼 동작하며, `arr[i]` 대신 `*(arr + i)`를 쓸 수 있다.

```c
int arr[5] = {10, 20, 30, 40, 50};

printf("%p\n", (void *)arr);       // arr[0]의 주소
printf("%p\n", (void *)&arr[0]);   // 같은 주소

printf("%d\n", *arr);         // 10  (arr[0]과 동일)
printf("%d\n", *(arr + 2));   // 30  (arr[2]과 동일)
```

**핵심 등가 관계:**

| 배열 표기법 | 포인터 표기법 |
|:----------|:-----------|
| `arr` | `&arr[0]` |
| `arr[i]` | `*(arr + i)` |
| `&arr[i]` | `arr + i` |

*표 8. 배열 표기와 포인터 표기의 등가 관계*

> **주의:** 배열 이름은 **상수**이므로 수정할 수 없다. 다음은 **불가능**하다.
> ```c
> arr++;          // 오류: 상수를 증가시킬 수 없음
> arr = other;    // 오류: 배열 이름에 재대입할 수 없음
> ```

### 2.4 배열과 포인터 비교

| 특성 | 배열 (`int arr[5]`) | 포인터 (`int *p`) |
|:----|:-------------------|:-----------------|
| 주소 | **고정** (변경 불가) | **가변** (재대입 가능) |
| `sizeof` | 배열 전체 크기 (`5 * 4 = 20`) | 포인터 크기 (`4` 또는 `8`) |
| 메모리 할당 | 선언 시 할당됨 | 기존 메모리를 가리켜야 함 |
| `++` 연산자 | 불가 (`arr++`는 오류) | 가능 (`p++`로 다음 요소 이동) |
| 정체성 | `arr`은 배열 그 자체 | `p`는 독립된 변수 |

*표 9. 배열과 포인터의 비교 (`int`가 4바이트인 경우)*

```c
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;

printf("%zu\n", sizeof(arr));   // 20 (5 * sizeof(int))
printf("%zu\n", sizeof(p));     // 8  (64비트에서 포인터 크기)

// arr++;   // 오류
p++;        // OK: p는 이제 arr[1]을 가리킴
```

> **핵심:** `arr`과 `p`는 많은 수식에서 같은 방식으로 사용할 수 있지만(`arr[i]`와 `p[i]`), 본질적으로 다르다. 배열 이름은 특정 배열의 전용 포인터처럼 고정된 시작 주소이고, `p`는 실행 중에 다른 주소를 저장할 수 있는 변수이다.

### 2.5 포인터 배열과 이중 포인터

포인터도 변수이므로 포인터를 원소로 갖는 배열을 만들 수 있고, 포인터의 주소를 저장하는 포인터도 만들 수 있다. **포인터 배열(array of pointers)** `int *list[3]`은 `int*`형 원소 3개로 이루어진 배열이고, **이중 포인터(double pointer)** `int **pp`는 `int*`형 변수의 주소를 저장하는 포인터이다.

```c
int x = 1, y = 2, z = 3;
int *list[3] = { &x, &y, &z };      // 포인터 배열
int *p = &x;
int **pp = &p;                      // 이중 포인터
int i;

for (i = 0; i < 3; i++)
    *list[i] *= 10;                 // 각 원소가 가리키는 변수를 10배로
printf("x = %d, y = %d, z = %d\n", x, y, z);

**pp = 99;                          // pp → p → x
printf("x = %d, *p = %d, **pp = %d\n", x, *p, **pp);
*pp = &y;                           // p가 y를 가리키게 바꾼다
printf("*p = %d\n", *p);
printf("sizeof list = %zu, sizeof pp = %zu\n", sizeof(list), sizeof(pp));
```

```text
x = 10, y = 20, z = 30
x = 99, *p = 99, **pp = 99
*p = 20
sizeof list = 24, sizeof pp = 8
```

`*list[i]`는 `[]`가 `*`보다 먼저 결합하므로 `*(list[i])`, 즉 `i`번째 원소가 가리키는 변수이다. 포인터 배열은 서로 떨어져 있는 변수 여러 개를 하나의 반복문으로 처리할 때 쓰며, 9장의 문자열 포인터 배열이 대표적인 예이다. `**pp`는 `pp`를 한 번 역참조하여 `p`를 얻고 다시 역참조하여 `x`에 이르므로 `**pp = 99`는 `x`를 바꾼다. `*pp = &y`는 `pp`가 가리키는 `p` 자체를 바꾸므로, 함수가 호출한 쪽의 포인터 변수를 바꾸어야 할 때 이중 포인터를 매개변수로 쓴다. 64비트 플랫폼에서 포인터는 8바이트이므로 `list`의 크기는 3 × 8 = 24바이트이다. 포인터 배열과 이중 포인터의 활용, 배열 포인터와의 차이는 11장에서 자세히 다룬다.

### 2.6 `arr`, `&arr[0]`, `&arr`의 차이

배열 이름 `arr`, 첫 원소의 주소 `&arr[0]`, 배열 전체의 주소 `&arr`는 같은 주소 값을 출력하지만 타입이 다르고, 그래서 1을 더했을 때 이동하는 양이 다르다.

```c
int arr[5] = { 1, 2, 3, 4, 5 };

printf("arr     = %p, arr + 1     = %p\n", (void *)arr, (void *)(arr + 1));
printf("&arr[0] = %p, &arr[0] + 1 = %p\n", (void *)&arr[0], (void *)(&arr[0] + 1));
printf("&arr    = %p, &arr + 1    = %p\n", (void *)&arr, (void *)(&arr + 1));
printf("sizeof arr = %zu, sizeof &arr[0] = %zu, sizeof *&arr = %zu\n",
       sizeof arr, sizeof &arr[0], sizeof *&arr);
```

```text
arr     = 0x16f0eeaf0, arr + 1     = 0x16f0eeaf4
&arr[0] = 0x16f0eeaf0, &arr[0] + 1 = 0x16f0eeaf4
&arr    = 0x16f0eeaf0, &arr + 1    = 0x16f0eeb04
sizeof arr = 20, sizeof &arr[0] = 8, sizeof *&arr = 20
```

| 수식 | 타입 | 가리키는 대상 | `+ 1`의 이동량 |
|:-----|:-----|:-----|-----:|
| `arr` (대부분의 수식에서) | `int *` | 첫 원소 `arr[0]` | 4바이트 |
| `&arr[0]` | `int *` | 첫 원소 `arr[0]` | 4바이트 |
| `&arr` | `int (*)[5]` | 원소 5개짜리 배열 전체 | 20바이트 |

*표 10. 배열 이름과 두 가지 주소의 비교*

`arr`는 수식에 쓰이면 첫 원소를 가리키는 `int *`로 바뀌므로 `&arr[0]`과 같고, 1을 더하면 `int` 하나만큼인 4바이트 뒤의 `arr[1]`을 가리킨다. `&arr`는 배열 전체를 하나의 대상으로 가리키는 주소이므로, 1을 더하면 배열 하나의 크기인 20바이트 뒤, 즉 배열이 끝난 바로 다음 위치가 된다. 0xaf0 + 0x14(20) = 0xb04이다. 배열 이름이 주소로 바뀌지 않는 예외도 있다. `sizeof arr`는 배열 전체의 크기 20이고, `&arr`의 `&`도 배열 전체에 적용된다. `int (*)[5]` 같은 배열 포인터는 2차원 배열을 함수에 넘길 때 실제로 쓰이는 타입이며 11장에서 자세히 다룬다.

### 2.7 원소의 타입에 따른 포인터 연산

2.1절의 규칙, 즉 `p + 1`이 가리키는 타입의 크기만큼 이동한다는 것을 네 가지 타입으로 확인한다. 이동한 바이트 수는 두 주소를 `char *`로 바꾸어 뺀 값이다. `char`는 1바이트이므로 `char *`끼리의 차는 바이트 수가 된다.

```c
char c[4];
short s[4];
int i[4];
double d[4];
char *pc = c;
short *ps = s;
int *pi = i;
double *pd = d;

printf("char:   %p -> %p (+%td)\n", (void *)pc, (void *)(pc + 1), (char *)(pc + 1) - (char *)pc);
printf("short:  %p -> %p (+%td)\n", (void *)ps, (void *)(ps + 1), (char *)(ps + 1) - (char *)ps);
printf("int:    %p -> %p (+%td)\n", (void *)pi, (void *)(pi + 1), (char *)(pi + 1) - (char *)pi);
printf("double: %p -> %p (+%td)\n", (void *)pd, (void *)(pd + 1), (char *)(pd + 1) - (char *)pd);
printf("pi + 3 - pi = %td\n", (pi + 3) - pi);
```

```text
char:   0x16b1b6ac8 -> 0x16b1b6ac9 (+1)
short:  0x16b1b6b00 -> 0x16b1b6b02 (+2)
int:    0x16b1b6af0 -> 0x16b1b6af4 (+4)
double: 0x16b1b6ad0 -> 0x16b1b6ad8 (+8)
pi + 3 - pi = 3
```

같은 `+ 1`이 `char *`에서는 1바이트, `short *`에서는 2바이트, `int *`에서는 4바이트, `double *`에서는 8바이트를 이동한다. 일반적으로 T형 포인터 p에 대해 `p + n`의 주소는 p + n × `sizeof(T)`이다. 반대로 같은 타입의 두 포인터의 차는 바이트 수를 원소 크기로 나눈 원소의 개수이므로 `(pi + 3) - pi`는 12바이트가 아니라 3이다. `%td`는 포인터의 차를 담는 정수 타입 `ptrdiff_t`의 형식 지정자이다. 포인터의 타입이 이동량을 정하므로, 1.7절처럼 `int` 변수를 `short *`로 가리키면 역참조할 때 읽는 바이트 수부터 달라진다.

> **참고:** **바이트 순서.** `int n = 0x11223344;`의 주소를 `unsigned char *`로 바꾸어 네 바이트를 차례로 출력하면 이 환경에서는 `44 33 22 11`이 나온다. 가장 낮은 자리의 바이트가 가장 낮은 주소에 놓이는 이런 배치를 리틀 엔디언이라고 하며, 반대 순서인 빅 엔디언을 쓰는 CPU도 있다. 바이트 순서에 의존하는 코드의 주의점은 13장에서 다룬다.

### 2.8 여러 가지 포인터의 선언

포인터는 원소, 배열, 포인터, 함수처럼 여러 대상을 가리키도록 선언할 수 있다. 교재는 처음 배울 때 이 기능을 모두 쓸 필요는 없고, 선언문을 보고 의미를 읽을 수 있으면 된다고 설명한다. 선언은 변수 이름에서 시작하여 오른쪽의 `[]`, `()`를 먼저 읽고 왼쪽의 `*`를 나중에 읽되, 괄호가 있으면 괄호 안을 먼저 읽는다.

| 선언 | 읽는 방법 | 의미 |
|:-----|:-----|:-----|
| `int *p;` | p는 포인터, 가리키는 것은 `int` | `int` 변수를 가리키는 포인터 |
| `int *arr[3];` | arr는 원소 3개의 배열, 원소는 `int` 포인터 | 포인터 배열 (2.5절) |
| `int (*pa)[3];` | pa는 포인터, 가리키는 것은 `int` 3개의 배열 | 배열 포인터 (2.6절의 `&arr` 타입) |
| `int **pp;` | pp는 포인터, 가리키는 것은 `int` 포인터 | 이중 포인터 (2.5절) |
| `int (*fp)(int);` | fp는 포인터, 가리키는 것은 `int`를 받아 `int`를 반환하는 함수 | 함수 포인터 |

*표 11. 여러 가지 포인터 선언과 읽는 방법*

`int *arr[3]`과 `int (*pa)[3]`은 괄호 하나 차이로 뜻이 완전히 달라진다. 앞의 것은 `[]`가 `*`보다 먼저 결합하므로 배열이고, 뒤의 것은 괄호 때문에 `*`가 먼저 결합하므로 포인터이다. `sizeof`로 확인하면 64비트 환경에서 `arr`는 포인터 3개인 24바이트, `pa`는 포인터 하나인 8바이트이다. 배열 포인터와 함수 포인터의 활용은 11장에서 다룬다.

### 2.9 포인터로 배열 훑기

인덱스 대신 포인터를 한 칸씩 옮기며 배열을 처리할 수도 있다. 다음 코드는 첫 원소를 가리키는 `p`를 배열의 끝 `end`(= `arr + 5`)에 이를 때까지 증가시키며 합계를 구한다.

```c
int arr[5] = { 3, 1, 4, 1, 5 };
int *p, *end = arr + 5, sum = 0;

for (p = arr; p < end; p++) {
    sum += *p;
    printf("p - arr = %td, *p = %d, sum = %d\n", p - arr, *p, sum);
}
printf("p == end: %d\n", p == end);

p = arr;
printf("%d ", *p++);
printf("%d ", *p++);
printf("%d\n", *p);
```

```text
p - arr = 0, *p = 3, sum = 3
p - arr = 1, *p = 1, sum = 4
p - arr = 2, *p = 4, sum = 8
p - arr = 3, *p = 1, sum = 9
p - arr = 4, *p = 5, sum = 14
p == end: 1
3 1 4
```

`p - arr`는 지금 가리키는 원소의 인덱스와 같으므로 이 반복은 `for (i = 0; i < 5; i++) sum += arr[i];`와 같은 일을 한다. `end`는 마지막 원소 `arr[4]`의 다음 위치를 가리킨다. C는 배열의 바로 다음 위치를 가리키는 포인터를 만들고 비교하는 것은 허용하지만, 그 위치를 역참조하는 것은 허용하지 않는다. 그래서 조건은 `p <= end`가 아니라 `p < end`이고, 반복이 끝난 뒤 `p`는 `end`와 같지만 `*p`는 읽지 않는다.

마지막 세 줄의 `*p++`는 문자열과 배열을 다루는 코드에서 자주 보는 관용구이다. 후위 `++`가 먼저 결합하므로 `*(p++)`이며, "현재 위치의 값을 쓰고 포인터를 다음으로 옮긴다"는 뜻이다. 따라서 첫 두 출력은 `arr[0]`의 3과 `arr[1]`의 1이고, 그 뒤 `p`는 `arr[2]`를 가리켜 4를 출력한다.

## 3. 함수와 포인터

### 3.1 값에 의한 전달 vs 주소에 의한 전달

| 방식 | 메커니즘 | 원본 수정 가능 여부 |
|:----|:--------|:-------------|
| 값에 의한 전달 (call by value) | 함수가 인수의 **복사본**을 받음 | 불가 |
| 주소에 의한 전달 (call by reference) | 함수가 포인터를 통해 **주소**를 받음 | 가능 |

*표 12. 값에 의한 전달과 주소에 의한 전달*

값에 의한 전달에서 함수의 매개변수는 함수가 호출될 때 생성되는 지역 변수이며 인자의 값으로 초기화된다. 주소에 의한 전달에서는 매개변수를 인자를 가리키는 포인터로 선언하고, 함수를 호출할 때 인자로 전달하려는 변수의 주소를 넘긴다.

```c
void by_value(int x) {
    x = 100;   // 지역 복사본만 수정
}

void by_reference(int *x) {
    *x = 100;  // 원본 변수를 수정
}

int main() {
    int a = 10;

    by_value(a);
    printf("%d\n", a);     // 10 (변경 안 됨)

    by_reference(&a);
    printf("%d\n", a);     // 100 (수정됨)

    return 0;
}
```

```text
값에 의한 전달                     주소에 의한 전달
┌──────────────┐                ┌───────────────┐
│ main         │                │ main          │
│  a = 10      │                │  a = 10 → 100 │
└──────┬───────┘                └───────┬───────┘
       │ 복사                            │ 주소
       ▼                                ▼
┌──────────────┐                ┌───────────────┐
│ by_value     │                │ by_reference  │
│  x = 10→100  │                │  x = &a       │
│  (지역 복사본)  │                │  *x = 100     │
└──────────────┘                └───────────────┘
   a 변경 안 됨                        a 변경됨!
```

*그림 5. 값에 의한 전달과 주소에 의한 전달의 비교*

> **참고:** C는 엄밀히 말하면 모든 인자를 값으로 전달하며, 포인터(주소)를 값으로 전달하는 방식으로 주소에 의한 전달을 구현한다. 교재는 이 방식을 참조에 의한 호출이라 부른다.

### 3.2 포인터를 통한 변수 수정

주소에 의한 전달이 왜 필요한지는 호출한 쪽의 변수에 10을 더하는 함수로 확인할 수 있다.

**잘못된 방법: 값에 의한 전달 (동작하지 않음)**

```c
void addTen_wrong(int x) {
    x = x + 10;
    // x는 지역 복사본: 원본은 변경되지 않음
}

int main() {
    int score = 85;
    addTen_wrong(score);
    printf("score = %d\n", score);   // score = 85 (수정 안 됨!)
    return 0;
}
```

```text
addTen_wrong 호출 전:       addTen_wrong 내부:          addTen_wrong 후:
  main: score=85             x=85→95                    main: score=85
         │                   (지역 복사본)                (변경 안 됨!)
         ▼
        복사
         │
         ▼
        x=85
```

*그림 6. 값에 의한 전달로 호출한 addTen_wrong의 동작*

**올바른 방법: 주소에 의한 전달 (정상 동작)**

```c
void addTen(int *p) {
    *p = *p + 10;   // 포인터를 통해 원본 변수를 수정
}

int main() {
    int score = 85;
    addTen(&score);
    printf("score = %d\n", score);   // score = 95 (수정됨!)
    return 0;
}
```

```text
addTen 호출 전:              addTen 내부:                addTen 후:
  main: score=85             *p=85→95                   main: score=95
         │                   (주소를 통해 원본 수정)       (수정됨!)
         ▼
       &score
         │
         ▼
        p=&score
       *p=85
```

*그림 7. 주소에 의한 전달로 호출한 addTen의 동작*

> **참고:** **대표 연습 문제.** 두 값을 교환하는 것은 이 패턴의 가장 대표적인 응용이며, 값에 의한 전달로는 구현할 수 없다. 함수가 호출한 쪽의 두 변수를 모두 수정할 수 있도록 두 개의 포인터 매개변수가 필요하다.

교환 함수는 매개변수를 인자에 대한 포인터형으로 선언하고, 호출할 때 교환할 두 변수의 주소를 전달한다.

```c
void swap(int *px, int *py) {
    int temp = *px;
    *px = *py;
    *py = temp;
}

int main() {
    int a = 3, b = 5;
    swap(&a, &b);
    printf("a = %d, b = %d\n", a, b);   // a = 5, b = 3
    return 0;
}
```

### 3.3 여러 값 반환

C 함수는 `return`으로 하나의 값만 반환할 수 있으므로, 포인터 매개변수를 사용하여 추가 값을 돌려준다.

```c
void sec_to_hms(int sec, int *h, int *m, int *s) {
    *h = sec / 3600;
    *m = (sec % 3600) / 60;
    *s = sec % 60;
}

int main() {
    int hours, minutes, seconds;
    int total_sec = 3723;

    sec_to_hms(total_sec, &hours, &minutes, &seconds);
    printf("%d초 = %d시간 %d분 %d초\n", total_sec, hours, minutes, seconds);
    // 3723초 = 1시간 2분 3초

    return 0;
}
```

> **핵심:** 호출하는 쪽은 변수의 **주소**를 전달한다. 함수는 해당 주소를 통해 `*`로 결과를 기록한다.

매개변수는 함수 안에서 하는 역할에 따라 세 가지로 나뉘며, 역할에 따라 인자 전달 방법을 정한다.

| 구분 | 역할 | 예 | 인자 전달 방법 |
|:----|:----|:----|:----|
| 입력 매개변수 | 함수 안에서 값이 사용될 뿐 변경되지 않는다. | `int add(int x, int y);` | 값에 의한 전달 |
| 출력 매개변수 | 함수 안에서 값이 사용되지는 않고 함수가 리턴하기 전에 변경된다. | `void get_sum_product(int x, int y, int *sum, int *product);` | 주소에 의한 전달 |
| 입출력 매개변수 | 함수 안에서 값이 사용되기도 하고 함수가 리턴하기 전에 변경되기도 한다. | `void swap(int *px, int *py);` | 주소에 의한 전달 |

*표 13. 매개변수의 역할에 따른 인자 전달 방법*

처리 결과를 출력 매개변수로 돌려주는 함수는 다음 순서로 작성한다. (1) 함수 원형에서 출력 매개변수를 처리 결과를 저장할 변수를 가리키는 포인터형으로 선언한다. (2) 함수를 호출할 때 처리 결과를 받아 올 변수를 준비하고 그 주소를 전달한다. (3) 함수를 정의할 때 포인터형 매개변수가 가리키는 곳에 처리 결과를 저장한다.

```c
void get_sum_product(int x, int y, int *psum, int *pproduct) {
    *psum = x + y;        // psum이 가리키는 변수에 합을 저장
    *pproduct = x * y;    // pproduct가 가리키는 변수에 곱을 저장
}

int main() {
    int sum, product;     // 처리 결과를 받아 올 변수
    get_sum_product(4, 5, &sum, &product);
    printf("합: %d, 곱: %d\n", sum, product);   // 합: 9, 곱: 20
    return 0;
}
```

### 3.4 함수에 배열 전달

배열을 함수에 전달하면, 배열 이름은 첫 번째 요소에 대한 포인터로 **변환(decay)** 된다. 함수는 배열의 복사본이 아니라 포인터를 받는다. 배열을 값으로 전달하면 배열 전체를 복사해야 하므로 시간과 공간 모두 성능이 떨어지기 때문에, 배열은 항상 주소로 전달한다.

**두 가지 동일한 함수 시그니처:**

```c
void print_array(int *arr, int size);    // 포인터 문법
void print_array(int arr[], int size);   // 배열 문법 (동일)
```

두 표현은 동일하다. 함수 매개변수에서 `int arr[]`는 `int *arr`로 취급된다.

```c
void print_array(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);   // arr[i]는 *(arr + i)와 동일
    }
    printf("\n");
}

int main() {
    int data[5] = {10, 20, 30, 40, 50};
    print_array(data, 5);   // 배열 이름이 포인터로 변환됨
    return 0;
}
```

> **주의:** 함수 안에서 `sizeof(arr)`는 배열 전체 크기가 아니라 **포인터 크기**(4 또는 8)를 반환한다. 그래서 크기를 별도의 매개변수로 전달해야 한다.

```c
void func(int arr[]) {
    printf("%zu\n", sizeof(arr));    // 8 (포인터 크기, 배열 크기가 아님!)
}

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    printf("%zu\n", sizeof(arr));    // 20 (배열 전체 크기)
    func(arr);
    return 0;
}
```

**포인터 매개변수를 통한 배열 요소 수정:**

```c
void double_elements(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        arr[i] *= 2;   // 원본 배열을 수정
    }
}

int main() {
    int nums[4] = {1, 2, 3, 4};
    double_elements(nums, 4);
    // nums는 이제 {2, 4, 6, 8}
    return 0;
}
```

> **참고:** **팁.** 함수가 배열을 수정하지 **않아야** 한다면, 즉 배열이 입력 매개변수라면 매개변수를 `const int *arr`로 선언한다. 컴파일러가 실수로 값을 변경하는 것을 막아 준다.

배열을 함수의 인자로 전달하는 방법을 정리하면 다음과 같다. (1) 함수 원형에서 매개변수를 크기를 생략한 배열(`int arr[]`)이나 원소에 대한 포인터형(`int *arr`)으로 선언한다. (2) 함수 안에서 배열의 크기가 필요하면 크기도 매개변수로 받는다. (3) 배열이 입력 매개변수이면 `const`를 지정한다. (4) 함수를 호출할 때 배열 이름을 인자로 전달한다. (5) 함수를 정의할 때 포인터인 매개변수를 배열처럼 사용한다.

매개변수 선언에서 `int arr[]`, `int arr[10]`, `int *arr`는 모두 같은 타입 `int *`로 처리된다. 그래서 `void f(int arr[]);`라는 원형과 `void f(int *arr);`라는 원형을 한 파일에 함께 써도 같은 함수의 선언이 되어 충돌하지 않으며, `int arr[10]`처럼 적은 크기 10은 무시된다. 다만 Clang은 `-Wall`에서 `int arr[10]`처럼 크기를 적은 선언 다음에 `int arr[]`처럼 크기가 다른 배열 표기의 선언이 오면, 타입은 같아도 `argument 'arr' of type 'int[]' with mismatched bound` 경고를 낸다. 배열 표기는 "이 매개변수로 배열이 온다"는 의도를 드러내고, 포인터 표기는 실제 타입을 드러낸다는 차이가 있을 뿐이므로, 한 프로그램 안에서는 한 가지 표기를 일관되게 쓴다. 함수 안에서 `arr++`가 허용되는 것도 매개변수 `arr`가 배열이 아니라 포인터 변수이기 때문이다.

### 3.5 주소를 반환하는 함수

함수는 포인터를 반환할 수도 있다. 이때 반환하는 주소가 함수가 끝난 뒤에도 유효한지 확인해야 한다. 지역 변수는 함수가 반환할 때 소멸하므로 그 주소를 반환하면, 호출한 쪽은 이미 사라진 변수를 가리키는 포인터를 받게 된다. 이런 포인터를 **댕글링 포인터(dangling pointer)** 라고 하며, 역참조하면 정의되지 않은 동작이다.

```c
int *bad(void)
{
    int local = 42;

    return &local;              // 함수가 끝나면 local은 소멸한다
}
```

```text
warning: address of stack memory associated with local variable 'local' returned [-Wreturn-stack-address]
```

반면 호출한 쪽이 넘겨준 배열의 원소 주소는 함수가 끝난 뒤에도 유효하다. 다음 함수는 배열에서 가장 큰 원소의 주소를 반환하며, 호출한 쪽은 그 주소로 원소를 직접 바꿀 수 있다.

```c
int *largest(int arr[], int size)
{
    int *best = &arr[0];
    int i;

    for (i = 1; i < size; i++)
        if (arr[i] > *best)
            best = &arr[i];
    return best;
}

int main(void)
{
    int data[5] = { 4, 9, 2, 9, 7 };
    int *m = largest(data, 5);

    *m = 0;
    printf("%d %d %d %d %d, index %d\n", data[0], data[1], data[2], data[3], data[4], (int)(m - data));
    return 0;
}
```

```text
4 0 2 9 7, index 1
```

최댓값 9가 두 번 나오지만 비교가 `>`이므로 먼저 나온 `data[1]`의 주소가 반환되고, `*m = 0`이 그 원소를 0으로 바꾼다. 같은 배열 안을 가리키는 두 포인터의 차 `m - data`는 두 위치 사이의 원소 개수이므로 인덱스 1이 된다(2.1절). 정리하면 함수가 반환해도 되는 주소는 인수로 받은 배열이나 변수의 주소, 전역 변수의 주소, 그리고 11장에서 배우는 동적으로 할당한 메모리의 주소이며, 함수의 지역 변수의 주소는 반환하지 않는다.

### 3.6 `swap` 호출의 메모리 추적

3.1절의 주소에 의한 전달을 주소로 확인한다. `swap`은 두 `int` 변수의 주소를 받아 `*x`와 `*y`를 맞바꾼다.

```c
void swap(int *x, int *y)
{
    int t;

    printf("in swap: x = %p, y = %p, *x = %d, *y = %d\n", (void *)x, (void *)y, *x, *y);
    t = *x;
    *x = *y;
    *y = t;
}

int main(void)
{
    int a = 3, b = 7;

    printf("in main: &a = %p, &b = %p\n", (void *)&a, (void *)&b);
    swap(&a, &b);
    printf("a = %d, b = %d\n", a, b);
    return 0;
}
```

```text
in main: &a = 0x16d982b08, &b = 0x16d982b04
in swap: x = 0x16d982b08, y = 0x16d982b04, *x = 3, *y = 7
a = 7, b = 3
```

```text
main의 영역                       swap의 영역
┌─────────────────────────┐         ┌──────────────────────────┐
│ a  @...b08 : 3 → 7      │◄────────┤ x : 0x...b08             │
│ b  @...b04 : 7 → 3      │◄────────┤ y : 0x...b04             │
└─────────────────────────┘         │ t : 3                    │
                                    └──────────────────────────┘
```

*그림 8. swap을 호출하는 동안 main과 swap의 변수*

`swap`의 매개변수 `x`와 `y`에는 `main`의 `&a`와 `&b`가 복사되므로 출력된 주소가 같다. 매개변수 자체는 여전히 값으로 전달된 복사본이지만, 그 값이 주소이기 때문에 `*x`로 `main`의 `a`에 접근할 수 있다. 세 문장을 차례로 따라가면 `t = *x`로 `t`가 3, `*x = *y`로 `a`가 7, `*y = t`로 `b`가 3이 된다. `swap`이 끝나면 `x`, `y`, `t`는 사라지지만 `a`와 `b`에 쓴 값은 남는다. 만약 `swap(a, b)`처럼 값을 넘기면 3과 7을 주소로 쓰게 되어 컴파일러가 `int`를 `int *`로 바꿀 수 없다는 진단을 낸다.

### 3.7 포인터의 흔한 실수

포인터의 실수는 컴파일 단계의 경고와 실행 중의 비정상 종료로 나타난다. 다음 코드는 경고가 나는 세 가지 실수를 담고 있다.

```c
int a = 5, *p, *q = &a;

*p = 3;                 // p를 초기화하지 않고 역참조
if (q == 5)             // 포인터와 정수를 비교
    printf("five\n");
printf("%d\n", q);      // 포인터를 %d로 출력
```

```text
warning: comparison between pointer and integer ('int *' and 'int') [-Wpointer-integer-compare]
warning: format specifies type 'int' but the argument has type 'int *' [-Wformat]
warning: variable 'p' is uninitialized when used here [-Wuninitialized]
```

세 경고는 모두 `*`를 빠뜨리거나 잘못 쓴 데서 나온다. `q == 5`와 `printf("%d", q)`는 `q`가 가리키는 값을 뜻했다면 `*q == 5`, `printf("%d", *q)`로 써야 한다. `*p = 3`은 1.7절의 와일드 포인터이다. 대입에서 `*`를 빠뜨린 `q = 7;`은 경고가 아니라 `incompatible integer to pointer conversion` 오류가 된다.

널 포인터의 역참조는 컴파일 경고 없이 실행 중에 드러난다. `int *p = NULL; *p = 1;`을 실행한 프로그램은 arm64 macOS에서 세그멘테이션 오류(SIGSEGV)로 비정상 종료되었고, 셸에 보고된 종료 상태는 139였다. 이런 오류는 역참조하는 줄 앞에 `if (p != NULL)` 검사를 두거나, 포인터를 쓰기 직전에 디버거로 값을 확인하여 찾는다.

## 점검 문제

1. **포인터 연산:** `int arr[5] = {10, 20, 30, 40, 50}; int *p = arr + 1;`일 때 `*(p + 2)`, `p[-1]`, `&arr[4] - p`의 값을 각각 구하라.

   <details>
   <summary>정답</summary>

   `p`는 `arr[1]`을 가리킨다. `*(p + 2)`는 `arr[3]`이므로 40, `p[-1]`은 `*(p - 1)`, 즉 `arr[0]`이므로 10이다. `&arr[4] - p`는 두 포인터 사이의 요소 수이므로 4 - 1 = 3이다(바이트 수 12가 아니다).

   </details>

2. **`const` 포인터:** `int a = 1, b = 2; const int *p = &a; int *const q = &a;` 다음에 오는 네 문장 `*p = 5;`, `p = &b;`, `*q = 5;`, `q = &b;` 중 컴파일 오류가 나는 것을 모두 고르고 이유를 쓰라.

   <details>
   <summary>정답</summary>

   `*p = 5;`와 `q = &b;`가 오류이다. `p`는 읽기 전용 포인터이므로 `p`를 통해 값을 바꿀 수 없지만 다른 변수를 가리키게 할 수는 있다. `q`는 `a`의 전용 포인터이므로 `*q`로 `a`를 바꿀 수는 있지만 `q`에 다른 주소를 대입할 수 없다.

   </details>

3. **교환 함수:** `void swap(int x, int y)`로 두 값을 교환하려고 하면 `main`의 변수가 바뀌지 않는 이유를 설명하고, 올바른 함수 원형과 호출문을 쓰라.

   <details>
   <summary>정답</summary>

   값에 의한 전달에서는 `x`와 `y`가 인자의 값으로 초기화된 지역 변수이므로, 함수 안에서 두 매개변수를 교환해도 `main`의 원본은 바뀌지 않는다. 올바른 원형은 `void swap(int *px, int *py);`이고, 호출은 `swap(&a, &b);`처럼 두 변수의 주소를 전달한다. 함수 안에서는 `*px`와 `*py`를 임시 변수를 이용해 교환한다.

   </details>

4. **배열과 `sizeof`:** 64비트 시스템에서 `int data[10];`을 선언한 `main`에서 `sizeof(data)`를 출력하고, `void f(int arr[])` 안에서 `sizeof(arr)`를 출력하면 각각 얼마인가? `int`는 4바이트로 가정한다.

   <details>
   <summary>정답</summary>

   `main`에서는 배열 전체 크기인 10 × 4 = 40이 출력된다. 함수 매개변수 `int arr[]`는 `int *arr`로 취급되므로 `f` 안에서는 포인터 크기인 8이 출력된다. 그래서 배열을 받는 함수에는 원소 개수를 별도의 매개변수로 전달해야 한다.

   </details>

5. **출력 매개변수:** 3.3절의 `sec_to_hms(7384, &h, &m, &s)`를 호출한 뒤 `h`, `m`, `s`의 값은 각각 얼마인가?

   <details>
   <summary>정답</summary>

   `h = 7384 / 3600 = 2`, `m = (7384 % 3600) / 60 = 184 / 60 = 3`, `s = 7384 % 60 = 4`이다. 즉 7384초는 2시간 3분 4초이다.

   </details>

6. **포인터 추적:** `int a = 3, b = 7; int *p = &a, *q = &b; *q = *p * 2; q = p; *q += 1;`을 실행한 뒤 `a`, `b`, `*p`, `*q`의 값을 쓰라.

   <details>
   <summary>정답</summary>

   `*q = *p * 2`로 `b`가 6이 된다. `q = p`로 `q`가 `a`를 가리키게 되고, `*q += 1`로 `a`가 4가 된다. 따라서 `a`는 4, `b`는 6, `*p`와 `*q`는 모두 `a`를 가리키므로 4이다.

   </details>

7. **이중 포인터:** `int x = 5, y = 8; int *p = &x; int **pp = &p;`에서 `**pp = **pp + 1; *pp = &y; **pp = 0;`을 차례로 실행한 뒤 `x`, `y`, `*p`의 값을 쓰라.

   <details>
   <summary>정답</summary>

   첫 문장은 `pp → p → x`를 거쳐 `x`를 6으로 만든다. 둘째 문장은 `p`가 `y`를 가리키게 바꾸고, 셋째 문장은 `pp → p → y`를 거쳐 `y`를 0으로 만든다. 따라서 `x`는 6, `y`는 0, `*p`는 `y`의 값인 0이다.

   </details>

8. **댕글링 포인터:** 다음 함수가 잘못된 이유를 설명하고, 같은 일을 하도록 고쳐라. `int *make_ten(void) { int n = 10; return &n; }`

   <details>
   <summary>정답</summary>

   `n`은 지역 변수이므로 함수가 반환할 때 소멸하고, 반환된 주소는 댕글링 포인터가 된다. 값 하나를 돌려주는 것이 목적이면 `int make_ten(void) { return 10; }`처럼 값을 반환하고, 호출한 쪽의 변수에 결과를 넣어야 하면 `void make_ten(int *out) { *out = 10; }`처럼 출력 매개변수를 쓴다.

   </details>
