## 1. 포인터 기초

### 1.1 포인터 개념

메모리는 **연속된 바이트**의 나열이며, 각 바이트는 고유한 **주소(address)** 를 갖는다. **포인터(pointer)** 란 주소 그 자체이고, **포인터 변수**란 주소를 저장하는 변수이다. 메모리 주소가 가질 수 있는 값의 범위를 **메모리 주소 공간(address space)** 이라 한다.

```text
메모리 구조 (간략화)
주소          값
┌──────────┬──────────┐
│  0x1000  │    10    │  ← int a = 10;
├──────────┼──────────┤
│  0x1004  │    20    │  ← int b = 20;
├──────────┼──────────┤
│  0x1008  │  0x1000  │  ← int *p = &a;  (p에 a의 주소 저장)
└──────────┴──────────┘
```

*그림 1. 변수 a, b와 a를 가리키는 포인터 p의 메모리 배치*

| 아키텍처 | 포인터 크기 | 주소 범위 |
|:---------|:-----------|:---------|
| 32비트 | 4바이트 | `0x00000000` ~ `0xFFFFFFFF` |
| 64비트 | 8바이트 | `0x0000000000000000` ~ `0xFFFFFFFFFFFFFFFF` |

*표 1. 아키텍처별 포인터 크기와 주소 범위*

> **핵심:** 포인터는 변수의 이름을 모르더라도 **주소를 통해** 해당 변수에 접근할 수 있게 해 준다. 이것이 포인터의 핵심 능력이다.

### 1.2 포인터 선언

**문법:**

```c
자료형 *포인터이름;
```

`자료형`은 포인터가 가리킬 변수의 타입이다. `*`는 이 변수가 포인터임을 나타내는 포인터 수식어이다. 어떤 자료형의 변수를 가리키는지에 따라 포인터의 자료형이 정해지며, 예를 들어 `int` 변수를 가리키는 포인터는 `int*`형이다.

```c
int *p;      // int를 가리키는 포인터
double *q;   // double을 가리키는 포인터
char *r;     // char를 가리키는 포인터
```

**`*`의 위치는 상관없으며 세 가지 형태가 모두 같다.**

```c
int* p;    // OK
int *p;    // OK (권장)
int * p;   // OK
```

> **주의:** `int *p` 스타일을 권장한다. `int* p, q;`라고 쓰면 `p`만 포인터이고 `q`는 일반 `int`이다. `int *p, *q;`라고 써야 둘 다 포인터임이 명확하다.

```c
int* p, q;    // p는 int*, q는 int   (혼동 유발!)
int *p, *q;   // p, q 모두 int*      (명확)
```

**포인터의 크기는 가리키는 타입에 관계없이 같다.**

```c
int *p;
double *q;
char *r;

printf("%zu\n", sizeof(p));  // 8 (64비트 시스템)
printf("%zu\n", sizeof(q));  // 8 (64비트 시스템)
printf("%zu\n", sizeof(r));  // 8 (64비트 시스템)
```

포인터는 데이터가 아니라 주소를 저장하므로, 포인터의 크기는 가리키는 자료형이 아니라 플랫폼이 정한다. 일반적인 플랫폼에서 모든 포인터는 32비트에서 **4바이트**, 64비트에서 **8바이트**를 차지한다.

### 1.3 포인터 초기화

**`&`(주소 연산자)** 는 변수의 메모리 주소를 반환한다. `&` 연산의 결과는 `&` 다음에 쓴 변수에 대한 포인터형의 주소이며, `int` 변수 `a`에 대해 `&a`는 `int*`형이다.

```c
int a = 10;
int *p = &a;   // p에 a의 주소를 저장

printf("a의 주소: %p\n", (void *)&a);   // 예: 0x7ffee3c0
printf("p의 값:   %p\n", (void *)p);    // 같은 주소
```

**`&` 연산자의 제약:** `&`는 **변수(lvalue)** 에만 사용할 수 있으며, 다음과 같은 상수나 수식에는 사용할 수 없다.

```c
&10        // 오류: 리터럴 (주소 없음)
&(a + 1)   // 오류: 수식 결과 (임시값, 주소 없음)
#define MAX 100
&MAX       // 오류: 매크로 (전처리 시 치환됨, 주소 없음)
```

**NULL 포인터:** 아무것도 가리키지 않는 포인터이다. `NULL`은 표준 C 라이브러리 헤더에 정의된 매크로 상수로 값은 0이다(구현에 따라 `((void *)0)`으로 정의된다). `NULL`은 메모리 0번지를 가리킨다는 뜻이 아니라 포인터가 어떤 변수도 가리키지 않는다는 뜻이며, 포인터를 어떤 변수의 주소로 초기화할지 알 수 없을 때 `NULL`로 초기화한다.

```c
int *q = NULL;   // 명시적으로 아무것도 가리키지 않음
int *r = 0;      // NULL과 동일
```

> **참고:** **팁.** 포인터는 항상 초기화한다. 초기화되지 않은 포인터는 쓰레기 주소를 갖고 있으며, 역참조하면 **정의되지 않은 동작**(크래시, 데이터 손상 등)이 발생한다.

**형식 지정자 `%p`** 는 주소를 16진수로 출력한다.

```c
int x = 42;
int *p = &x;
printf("p = %p\n", (void *)p);   // p = 0x7ffee4b8 (예시)
```

### 1.4 역참조 연산자 `*`

**역참조(indirection)** 연산자 `*`는 포인터가 가리키는 주소에 저장된 값에 접근한다. 간접 참조 연산자라고도 하며, **읽기**와 **쓰기**가 모두 가능하다. `*` 연산의 결과는 포인터가 가리키는 변수 자체이다.

```c
int a = 10;
int *p = &a;

printf("%d\n", *p);   // 10 (읽기: p가 가리키는 주소의 값)

*p = 20;               // 쓰기: p가 가리키는 주소의 값을 변경
printf("%d\n", a);     // 20 (p를 통해 a가 수정됨)
```

`p`가 `a`를 가리킬 때, `*p`와 `a`는 **같은 메모리 위치의 다른 이름**이다. 즉 `*p`를 쓰면 그 자리에 `a`를 쓴 것처럼 처리된다. 포인터 변수 `p`도 변수이므로 자신의 주소 `&p`를 따로 갖는다.

```text
   p ──────► ┌───────┐
             │  20   │  ← *p와 a는 같은 위치를 가리킴
             └───────┘
             주소: 0x1000
```

*그림 2. 포인터 p가 가리키는 변수 a*

**`*` 연산자의 제약:** `*`는 **포인터**에만 사용할 수 있으며, 일반 변수나 정수 수식에는 사용할 수 없다.

```c
int a = 10;
*a         // 오류: a는 포인터가 아님
*(a + 1)   // 오류: (a + 1)은 포인터가 아님
```

> **핵심:** 포인터 문맥에서 `*` 기호는 두 가지 의미를 갖는다. (1) 선언문 `int *p;`에서는 `p`가 포인터임을 나타내고, (2) 수식 `*p`에서는 `p`를 역참조하여 `p`가 가리키는 주소의 값에 접근함을 나타낸다.

### 1.5 포인터의 용도

포인터를 왜 사용하는가? 교재는 두 가지 핵심 상황을 강조한다.

| 상황 | 설명 |
|:----|:----|
| 함수에서 2개 이상의 값을 반환해야 할 때 | C 함수는 `return`으로 하나의 값만 반환할 수 있다. 변수의 주소를 전달하면 함수 안에서 원본을 수정할 수 있다. |
| 함수에 배열을 전달할 때 | 배열은 전달할 때 포인터로 변환(decay)된다. 포인터를 사용하면 복사 없이 효율적으로 배열에 접근할 수 있다. |

*표 2. 포인터가 필요한 두 가지 상황*

```c
// 예제: 포인터를 통한 다중 값 반환
void divide(int a, int b, int *quotient, int *remainder) {
    *quotient = a / b;
    *remainder = a % b;
}

int main() {
    int q, r;
    divide(17, 5, &q, &r);
    printf("17 / 5 = %d 나머지 %d\n", q, r);  // 3 나머지 2
    return 0;
}
```

그 밖에 포인터를 이용하면 어떤 변수를 가리킬지 미리 알 수 없는 경우에도 포인터가 가리키는 변수에 대해 작업하는 코드를 작성할 수 있다. 즉 하나의 코드를 여러 변수에 공통으로 쓸 수 있다.

### 1.6 `const` 포인터

`const` 키워드는 포인터가 수정할 수 있는 대상을 제한한다. `const`의 위치에 따라 의미가 달라진다.

| 선언 | 의미 | `*p` 변경 가능? | `p` 변경 가능? |
|:----|:----|:---------------|:--------------|
| `const int *p` | 상수 int를 가리키는 포인터 | 불가 | 가능 |
| `int *const p` | int를 가리키는 상수 포인터 | 가능 | 불가 |
| `const int *const p` | 상수 int를 가리키는 상수 포인터 | 불가 | 불가 |

*표 3. `const`의 위치에 따른 세 가지 `const` 포인터*

```c
int a = 10, b = 20;

// 상수 int를 가리키는 포인터: *p1 수정 불가, p1 재대입 가능
const int *p1 = &a;
// *p1 = 30;    // 오류: p1을 통해 값을 수정할 수 없음
p1 = &b;        // OK: p1이 이제 b를 가리킴

// int를 가리키는 상수 포인터: *p2 수정 가능, p2 재대입 불가
int *const p2 = &a;
*p2 = 30;       // OK: a를 30으로 수정
// p2 = &b;     // 오류: p2가 가리키는 대상을 변경할 수 없음

// 상수 int를 가리키는 상수 포인터: 둘 다 불가
const int *const p3 = &a;
// *p3 = 40;    // 오류
// p3 = &b;     // 오류
```

`const int *p`는 가리키는 변수를 `const` 변수처럼 읽기만 하는 **읽기 전용 포인터**이고, `int *const p`는 선언할 때 특정 변수의 주소로 초기화한 뒤 다른 변수를 가리킬 수 없는 그 변수의 **전용 포인터**이다. `const int *const p`는 두 성질을 모두 가지므로 반드시 초기화해야 한다. 세 가지 중 실제로 주로 쓰이는 것은 읽기 전용 포인터이다.

> **참고:** **팁.** 선언을 **오른쪽에서 왼쪽으로** 읽으면 이해하기 쉽다. `const int *p`는 "p는 const인 int를 가리키는 포인터"(값이 상수)이고, `int *const p`는 "p는 int를 가리키는 const 포인터"(포인터 자체가 상수)이다.

### 1.7 포인터 사용 시 주의 사항

첫째, 포인터는 항상 특정 변수를 가리키게 하거나 널 포인터로 만든다. 널 포인터를 역참조하면 실행 오류가 발생하여 일반적으로 프로그램이 비정상 종료되므로, 널 포인터일 수 있는 포인터는 `NULL`이 아닌지 확인한 뒤에만 역참조한다.

```c
int *q = NULL;
if (q != NULL) {
    printf("%d\n", *q);   // q가 널 포인터가 아닐 때만 역참조
}
```

둘째, 포인터의 자료형과 포인터가 가리키는 변수의 자료형이 같아야 한다. 자료형이 다르면 컴파일러가 경고(최신 컴파일러에서는 오류)를 내며, 경고를 무시하고 실행하면 메모리를 다른 자료형으로 해석하여 잘못된 값을 읽거나 쓰게 된다.

```c
double d = 3.14;
int *pi = &d;   // 경고: 호환되지 않는 포인터형
```

## 2. 배열과 포인터

### 2.1 포인터 연산

포인터에 정수를 더하거나 빼면, 컴파일러는 1바이트가 아니라 **가리키는 타입의 크기**만큼 이동한다. 즉 `p + N`은 `p`가 가리키는 자료형 N개만큼 더한 주소이며, `p++`과 `++p`는 주소를 자료형 1개 크기만큼 증가시킨다.

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;    // p는 arr[0]을 가리킴
```

```text
p     p+1    p+2    p+3    p+4
│      │      │      │      │
▼      ▼      ▼      ▼      ▼
┌──────┬──────┬──────┬──────┬──────┐
│  10  │  20  │  30  │  40  │  50  │
└──────┴──────┴──────┴──────┴──────┘
0x1000  0x1004  0x1008  0x100C  0x1010
        (+4B)   (+4B)   (+4B)   (+4B)
```

*그림 3. 포인터 연산으로 이동하는 int 배열 원소의 주소*

| 포인터 타입 | `p + 1` 이동량 |
|:-----------|:--------------|
| `int *` | 4바이트 (`sizeof(int)`) |
| `double *` | 8바이트 (`sizeof(double)`) |
| `char *` | 1바이트 (`sizeof(char)`) |

*표 4. 포인터 타입별 `p + 1`의 이동량*

**지원되는 연산:**

| 연산 | 의미 |
|:----|:----|
| `p + n` | n개 요소만큼 앞으로 이동 |
| `p - n` | n개 요소만큼 뒤로 이동 |
| `p++` | 다음 요소로 이동 |
| `p--` | 이전 요소로 이동 |
| `p1 - p2` | 두 포인터 사이의 요소 수 (바이트 수가 아님) |

*표 5. 포인터에 허용되는 연산*

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

printf("%d\n", *(p + 2));   // 30 (세 번째 요소)

p++;
printf("%d\n", *p);         // 20 (두 번째 요소)

int *q = &arr[4];
printf("%ld\n", q - p);     // 3 (요소 단위 거리, 바이트가 아님)
```

> **참고:** 두 포인터의 차는 `<stddef.h>`의 `ptrdiff_t`형이며, `printf`로 출력할 때 정확한 형식 지정자는 `%td`이다. 위의 `%ld`는 `long`과 `ptrdiff_t`의 크기가 같은 64비트 Linux와 macOS에서는 맞게 출력되지만, `long`이 4바이트인 64비트 Windows에서는 형식이 맞지 않는다.

> **주의:** 포인터 연산은 배열 범위 안(또는 배열 끝의 바로 다음 위치까지)에서만 유효하다. 범위를 벗어나면 **정의되지 않은 동작**이 발생한다.

### 2.2 포인터를 배열처럼 사용

`p + i` 연산은 포인터가 가리키는 주소에 마치 배열이 있는 것처럼 메모리에 접근한다. 따라서 `type*`형 포인터는 `type`형 변수뿐 아니라 `type`형 배열의 원소도 가리킬 수 있고, 포인터에 **첨자 연산자 `[]`** 를 사용할 수 있다. `p[i]`는 항상 `*(p + i)`로 처리된다.

```c
int arr[5] = {10, 20, 30, 40, 50};
int *p = arr;

printf("%d\n", p[0]);       // 10  (*(p + 0)과 동일)
printf("%d\n", p[2]);       // 30  (*(p + 2)과 동일)
printf("%d\n", *(p + 4));   // 50  (p[4]와 동일)
```

| 표기법 | 동치 | 의미 |
|:------|:----|:----|
| `p[i]` | `*(p + i)` | p에서 i번째 요소에 접근 |
| `&p[i]` | `p + i` | p에서 i번째 요소의 주소 |

*표 6. 첨자 표기와 포인터 표기의 대응*

### 2.3 배열을 포인터처럼 사용

인덱스 없이 쓴 **배열 이름**은 배열의 시작 주소, 즉 첫 번째 요소의 주소이다. 그래서 배열 이름은 **포인터 상수(pointer constant)** 처럼 동작하며, `arr[i]` 대신 `*(arr + i)`를 쓸 수 있다.

```c
int arr[5] = {10, 20, 30, 40, 50};

printf("%p\n", (void *)arr);       // arr[0]의 주소
printf("%p\n", (void *)&arr[0]);   // 같은 주소

printf("%d\n", *arr);         // 10  (arr[0]과 동일)
printf("%d\n", *(arr + 2));   // 30  (arr[2]과 동일)
```

**핵심 등가 관계:**

| 배열 표기법 | 포인터 표기법 |
|:----------|:-----------|
| `arr` | `&arr[0]` |
| `arr[i]` | `*(arr + i)` |
| `&arr[i]` | `arr + i` |

*표 7. 배열 표기와 포인터 표기의 등가 관계*

> **주의:** 배열 이름은 **상수**이므로 수정할 수 없다. 다음은 **불가능**하다.
> ```c
> arr++;          // 오류: 상수를 증가시킬 수 없음
> arr = other;    // 오류: 배열 이름에 재대입할 수 없음
> ```

### 2.4 배열과 포인터 비교

| 특성 | 배열 (`int arr[5]`) | 포인터 (`int *p`) |
|:----|:-------------------|:-----------------|
| 주소 | **고정** (변경 불가) | **가변** (재대입 가능) |
| `sizeof` | 배열 전체 크기 (`5 * 4 = 20`) | 포인터 크기 (`4` 또는 `8`) |
| 메모리 할당 | 선언 시 할당됨 | 기존 메모리를 가리켜야 함 |
| `++` 연산자 | 불가 (`arr++`는 오류) | 가능 (`p++`로 다음 요소 이동) |
| 정체성 | `arr`은 배열 그 자체 | `p`는 독립된 변수 |

*표 8. 배열과 포인터의 비교 (`int`가 4바이트인 경우)*

```c
int arr[5] = {1, 2, 3, 4, 5};
int *p = arr;

printf("%zu\n", sizeof(arr));   // 20 (5 * sizeof(int))
printf("%zu\n", sizeof(p));     // 8  (64비트에서 포인터 크기)

// arr++;   // 오류
p++;        // OK: p는 이제 arr[1]을 가리킴
```

> **핵심:** `arr`과 `p`는 많은 수식에서 같은 방식으로 사용할 수 있지만(`arr[i]`와 `p[i]`), 본질적으로 다르다. 배열 이름은 특정 배열의 전용 포인터처럼 고정된 시작 주소이고, `p`는 실행 중에 다른 주소를 저장할 수 있는 변수이다.

## 3. 함수와 포인터

### 3.1 값에 의한 전달 vs 주소에 의한 전달

| 방식 | 메커니즘 | 원본 수정 가능? |
|:----|:--------|:-------------|
| 값에 의한 전달 (call by value) | 함수가 인수의 **복사본**을 받음 | 불가 |
| 주소에 의한 전달 (call by reference) | 함수가 포인터를 통해 **주소**를 받음 | 가능 |

*표 9. 값에 의한 전달과 주소에 의한 전달*

값에 의한 전달에서 함수의 매개변수는 함수가 호출될 때 생성되는 지역 변수이며 인자의 값으로 초기화된다. 주소에 의한 전달에서는 매개변수를 인자를 가리키는 포인터로 선언하고, 함수를 호출할 때 인자로 전달하려는 변수의 주소를 넘긴다.

```c
void by_value(int x) {
    x = 100;   // 지역 복사본만 수정
}

void by_reference(int *x) {
    *x = 100;  // 원본 변수를 수정
}

int main() {
    int a = 10;

    by_value(a);
    printf("%d\n", a);     // 10 (변경 안 됨)

    by_reference(&a);
    printf("%d\n", a);     // 100 (수정됨)

    return 0;
}
```

```text
값에 의한 전달                     주소에 의한 전달
┌──────────────┐                ┌───────────────┐
│ main         │                │ main          │
│  a = 10      │                │  a = 10 → 100 │
└──────┬───────┘                └───────┬───────┘
       │ 복사                            │ 주소
       ▼                                ▼
┌──────────────┐                ┌───────────────┐
│ by_value     │                │ by_reference  │
│  x = 10→100  │                │  x = &a       │
│  (지역 복사본)  │                │  *x = 100     │
└──────────────┘                └───────────────┘
   a 변경 안 됨                        a 변경됨!
```

*그림 4. 값에 의한 전달과 주소에 의한 전달의 비교*

> **참고:** C는 엄밀히 말하면 모든 인자를 값으로 전달하며, 포인터(주소)를 값으로 전달하는 방식으로 주소에 의한 전달을 구현한다. 교재는 이 방식을 참조에 의한 호출이라 부른다.

### 3.2 포인터를 통한 변수 수정

주소에 의한 전달이 왜 필요한지는 호출한 쪽의 변수에 10을 더하는 함수로 확인할 수 있다.

**잘못된 방법: 값에 의한 전달 (동작하지 않음)**

```c
void addTen_wrong(int x) {
    x = x + 10;
    // x는 지역 복사본: 원본은 변경되지 않음
}

int main() {
    int score = 85;
    addTen_wrong(score);
    printf("score = %d\n", score);   // score = 85 (수정 안 됨!)
    return 0;
}
```

```text
addTen_wrong 호출 전:       addTen_wrong 내부:          addTen_wrong 후:
  main: score=85             x=85→95                    main: score=85
         │                   (지역 복사본)                (변경 안 됨!)
         ▼
        복사
         │
         ▼
        x=85
```

*그림 5. 값에 의한 전달로 호출한 addTen_wrong의 동작*

**올바른 방법: 주소에 의한 전달 (정상 동작)**

```c
void addTen(int *p) {
    *p = *p + 10;   // 포인터를 통해 원본 변수를 수정
}

int main() {
    int score = 85;
    addTen(&score);
    printf("score = %d\n", score);   // score = 95 (수정됨!)
    return 0;
}
```

```text
addTen 호출 전:              addTen 내부:                addTen 후:
  main: score=85             *p=85→95                   main: score=95
         │                   (주소를 통해 원본 수정)       (수정됨!)
         ▼
       &score
         │
         ▼
        p=&score
       *p=85
```

*그림 6. 주소에 의한 전달로 호출한 addTen의 동작*

> **참고:** **대표 연습 문제.** 두 값을 교환하는 것은 이 패턴의 가장 대표적인 응용이며, 값에 의한 전달로는 구현할 수 없다. 함수가 호출한 쪽의 두 변수를 모두 수정할 수 있도록 두 개의 포인터 매개변수가 필요하다.

교환 함수는 매개변수를 인자에 대한 포인터형으로 선언하고, 호출할 때 교환할 두 변수의 주소를 전달한다.

```c
void swap(int *px, int *py) {
    int temp = *px;
    *px = *py;
    *py = temp;
}

int main() {
    int a = 3, b = 5;
    swap(&a, &b);
    printf("a = %d, b = %d\n", a, b);   // a = 5, b = 3
    return 0;
}
```

### 3.3 여러 값 반환

C 함수는 `return`으로 하나의 값만 반환할 수 있으므로, 포인터 매개변수를 사용하여 추가 값을 돌려준다.

```c
void sec_to_hms(int sec, int *h, int *m, int *s) {
    *h = sec / 3600;
    *m = (sec % 3600) / 60;
    *s = sec % 60;
}

int main() {
    int hours, minutes, seconds;
    int total_sec = 3723;

    sec_to_hms(total_sec, &hours, &minutes, &seconds);
    printf("%d초 = %d시간 %d분 %d초\n", total_sec, hours, minutes, seconds);
    // 3723초 = 1시간 2분 3초

    return 0;
}
```

> **핵심:** 호출하는 쪽은 변수의 **주소**를 전달한다. 함수는 해당 주소를 통해 `*`로 결과를 기록한다.

매개변수는 함수 안에서 하는 역할에 따라 세 가지로 나뉘며, 역할에 따라 인자 전달 방법을 정한다.

| 구분 | 역할 | 예 | 인자 전달 방법 |
|:----|:----|:----|:----|
| 입력 매개변수 | 함수 안에서 값이 사용될 뿐 변경되지 않는다. | `int add(int x, int y);` | 값에 의한 전달 |
| 출력 매개변수 | 함수 안에서 값이 사용되지는 않고 함수가 리턴하기 전에 변경된다. | `void get_sum_product(int x, int y, int *sum, int *product);` | 주소에 의한 전달 |
| 입출력 매개변수 | 함수 안에서 값이 사용되기도 하고 함수가 리턴하기 전에 변경되기도 한다. | `void swap(int *px, int *py);` | 주소에 의한 전달 |

*표 10. 매개변수의 역할에 따른 인자 전달 방법*

처리 결과를 출력 매개변수로 돌려주는 함수는 다음 순서로 작성한다. (1) 함수 원형에서 출력 매개변수를 처리 결과를 저장할 변수를 가리키는 포인터형으로 선언한다. (2) 함수를 호출할 때 처리 결과를 받아 올 변수를 준비하고 그 주소를 전달한다. (3) 함수를 정의할 때 포인터형 매개변수가 가리키는 곳에 처리 결과를 저장한다.

```c
void get_sum_product(int x, int y, int *psum, int *pproduct) {
    *psum = x + y;        // psum이 가리키는 변수에 합을 저장
    *pproduct = x * y;    // pproduct가 가리키는 변수에 곱을 저장
}

int main() {
    int sum, product;     // 처리 결과를 받아 올 변수
    get_sum_product(4, 5, &sum, &product);
    printf("합: %d, 곱: %d\n", sum, product);   // 합: 9, 곱: 20
    return 0;
}
```

### 3.4 함수에 배열 전달

배열을 함수에 전달하면, 배열 이름은 첫 번째 요소에 대한 포인터로 **변환(decay)** 된다. 함수는 배열의 복사본이 아니라 포인터를 받는다. 배열을 값으로 전달하면 배열 전체를 복사해야 하므로 시간과 공간 모두 성능이 떨어지기 때문에, 배열은 항상 주소로 전달한다.

**두 가지 동일한 함수 시그니처:**

```c
void print_array(int *arr, int size);    // 포인터 문법
void print_array(int arr[], int size);   // 배열 문법 (동일)
```

두 표현은 동일하다. 함수 매개변수에서 `int arr[]`는 `int *arr`로 취급된다.

```c
void print_array(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        printf("%d ", arr[i]);   // arr[i]는 *(arr + i)와 동일
    }
    printf("\n");
}

int main() {
    int data[5] = {10, 20, 30, 40, 50};
    print_array(data, 5);   // 배열 이름이 포인터로 변환됨
    return 0;
}
```

> **주의:** 함수 안에서 `sizeof(arr)`는 배열 전체 크기가 아니라 **포인터 크기**(4 또는 8)를 반환한다. 그래서 크기를 별도의 매개변수로 전달해야 한다.

```c
void func(int arr[]) {
    printf("%zu\n", sizeof(arr));    // 8 (포인터 크기, 배열 크기가 아님!)
}

int main() {
    int arr[5] = {1, 2, 3, 4, 5};
    printf("%zu\n", sizeof(arr));    // 20 (배열 전체 크기)
    func(arr);
    return 0;
}
```

**포인터 매개변수를 통한 배열 요소 수정:**

```c
void double_elements(int *arr, int size) {
    for (int i = 0; i < size; i++) {
        arr[i] *= 2;   // 원본 배열을 수정
    }
}

int main() {
    int nums[4] = {1, 2, 3, 4};
    double_elements(nums, 4);
    // nums는 이제 {2, 4, 6, 8}
    return 0;
}
```

> **참고:** **팁.** 함수가 배열을 수정하지 **않아야** 한다면, 즉 배열이 입력 매개변수라면 매개변수를 `const int *arr`로 선언한다. 컴파일러가 실수로 값을 변경하는 것을 막아 준다.

배열을 함수의 인자로 전달하는 방법을 정리하면 다음과 같다. (1) 함수 원형에서 매개변수를 크기를 생략한 배열(`int arr[]`)이나 원소에 대한 포인터형(`int *arr`)으로 선언한다. (2) 함수 안에서 배열의 크기가 필요하면 크기도 매개변수로 받는다. (3) 배열이 입력 매개변수이면 `const`를 지정한다. (4) 함수를 호출할 때 배열 이름을 인자로 전달한다. (5) 함수를 정의할 때 포인터인 매개변수를 배열처럼 사용한다.

| NULL 포인터 | `int *p = NULL;`은 아무것도 가리키지 않는 포인터이며, 포인터는 항상 초기화해야 한다. |
| `%p` | 주소를 16진수로 출력하는 형식 지정자이다. |
| `const` 포인터 | `const int *p`는 값이 상수인 읽기 전용 포인터, `int *const p`는 포인터 자체가 상수인 전용 포인터이며, 둘을 함께 쓸 수도 있다. |
| 포인터 사용 시 주의 | 널 포인터일 수 있으면 역참조 전에 검사하고, 포인터와 가리키는 변수의 자료형을 일치시킨다. |
| 포인터 연산 | `p + 1`은 1바이트가 아니라 `sizeof(*p)`바이트만큼 이동한다. |
| `p[i]` vs `*(p+i)` | 첨자 표기와 포인터 연산은 같은 뜻이며 서로 바꿔 쓸 수 있다. |
| 배열 이름 | 배열 이름은 첫 번째 요소의 주소이며 수정할 수 없는 포인터 **상수**로 동작한다. |
| 배열 vs 포인터 | 배열은 주소가 고정되고 `sizeof`가 전체 크기이며, 포인터는 주소를 바꿀 수 있고 `sizeof`가 4 또는 8이다. |
| 값에 의한 전달 | 함수가 복사본을 받으므로 원본을 변경할 수 없다. |
| 주소에 의한 전달 | 함수가 포인터로 주소를 받으므로 원본을 수정할 수 있다. |
| 포인터를 통한 수정 | 호출한 쪽의 변수를 수정하려면 주소를 전달해야 하며(`int *p`), 값에 의한 전달로는 수정할 수 없다. |
| 다중 값 반환 | 함수에 결과를 받을 변수의 주소를 전달하고, 함수는 `*`를 통해 값을 기록한다. |
| 매개변수의 역할 | 입력 매개변수는 값으로, 출력 매개변수와 입출력 매개변수는 주소로 전달한다. |
| 함수에 배열 전달 | 배열은 포인터로 변환되어 함수 안의 `sizeof(arr)`가 포인터 크기이므로, 크기를 따로 전달한다. |

## 점검 문제

1. **포인터 연산:** `int arr[5] = {10, 20, 30, 40, 50}; int *p = arr + 1;`일 때 `*(p + 2)`, `p[-1]`, `&arr[4] - p`의 값을 각각 구하라.

   <details>
   <summary>정답</summary>

   `p`는 `arr[1]`을 가리킨다. `*(p + 2)`는 `arr[3]`이므로 40, `p[-1]`은 `*(p - 1)`, 즉 `arr[0]`이므로 10이다. `&arr[4] - p`는 두 포인터 사이의 요소 수이므로 4 - 1 = 3이다(바이트 수 12가 아니다).

   </details>

2. **`const` 포인터:** `int a = 1, b = 2; const int *p = &a; int *const q = &a;` 다음에 오는 네 문장 `*p = 5;`, `p = &b;`, `*q = 5;`, `q = &b;` 중 컴파일 오류가 나는 것을 모두 고르고 이유를 쓰라.

   <details>
   <summary>정답</summary>

   `*p = 5;`와 `q = &b;`가 오류이다. `p`는 읽기 전용 포인터이므로 `p`를 통해 값을 바꿀 수 없지만 다른 변수를 가리키게 할 수는 있다. `q`는 `a`의 전용 포인터이므로 `*q`로 `a`를 바꿀 수는 있지만 `q`에 다른 주소를 대입할 수 없다.

   </details>

3. **교환 함수:** `void swap(int x, int y)`로 두 값을 교환하려고 하면 `main`의 변수가 바뀌지 않는 이유를 설명하고, 올바른 함수 원형과 호출문을 쓰라.

   <details>
   <summary>정답</summary>

   값에 의한 전달에서는 `x`와 `y`가 인자의 값으로 초기화된 지역 변수이므로, 함수 안에서 두 매개변수를 교환해도 `main`의 원본은 바뀌지 않는다. 올바른 원형은 `void swap(int *px, int *py);`이고, 호출은 `swap(&a, &b);`처럼 두 변수의 주소를 전달한다. 함수 안에서는 `*px`와 `*py`를 임시 변수를 이용해 교환한다.

   </details>

4. **배열과 `sizeof`:** 64비트 시스템에서 `int data[10];`을 선언한 `main`에서 `sizeof(data)`를 출력하고, `void f(int arr[])` 안에서 `sizeof(arr)`를 출력하면 각각 얼마인가? `int`는 4바이트로 가정한다.

   <details>
   <summary>정답</summary>

   `main`에서는 배열 전체 크기인 10 × 4 = 40이 출력된다. 함수 매개변수 `int arr[]`는 `int *arr`로 취급되므로 `f` 안에서는 포인터 크기인 8이 출력된다. 그래서 배열을 받는 함수에는 원소 개수를 별도의 매개변수로 전달해야 한다.

   </details>

5. **출력 매개변수:** 3.3절의 `sec_to_hms(7384, &h, &m, &s)`를 호출한 뒤 `h`, `m`, `s`의 값은 각각 얼마인가?

   <details>
   <summary>정답</summary>

   `h = 7384 / 3600 = 2`, `m = (7384 % 3600) / 60 = 184 / 60 = 3`, `s = 7384 % 60 = 4`이다. 즉 7384초는 2시간 3분 4초이다.

   </details>
