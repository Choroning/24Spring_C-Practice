## 연습 문제 1: 데이터 타입에 대한 설명

**교재 문항:** 3장 연습 문제 1번

**문제:** 데이터 타입의 크기, 유효 범위, 정밀도에 대한 열 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 1](Exercises.ko.md#연습-문제-1-데이터-타입에-대한-설명)에 있다.

### 풀이

**정답:** ①, ②, ③, ⑥, ⑧, ⑨, ⑩

**해설:** 데이터 타입은 값을 저장하는 메모리의 크기와 저장된 비트의 해석 방식을 결정한다([3장 1절](Concepts_Lecture.ko.md#1-데이터-타입)). 정수형은 크기가 고정되어 있으므로 범위를 벗어난 값이 유효 범위 안으로 순환하고, 실수형은 가수가 정밀도를, 지수가 범위를 결정하며 대부분의 값을 근삿값으로 저장한다.

- **① (잘못됨):** 데이터 타입의 크기는 플랫폼에 따라 다르다. 예를 들어 `long`은 32비트 플랫폼과 64비트 Windows에서 4바이트이지만 64비트 Linux와 macOS에서는 8바이트이다. C 표준은 `sizeof(short)` ≤ `sizeof(int)` ≤ `sizeof(long)` 같은 크기의 순서만 보장하므로, 실제 크기는 `sizeof` 연산자로 확인한다([3장 1.1절](Concepts_Lecture.ko.md#11-정수형), [7절](Concepts_Lecture.ko.md#7-sizeof-연산자)).
- **② (잘못됨):** `char`형의 크기는 1바이트이다. C 표준은 `sizeof(char)`를 어느 플랫폼에서나 1로 정한다.
- **③ (잘못됨):** `unsigned`는 정수형에만 붙일 수 있으며, `unsigned float`과 `unsigned double`은 잘못된 문법이다. 실수형은 부호 비트를 가진 한 가지 형태뿐이다([3장 1.2절](Concepts_Lecture.ko.md#12-실수형)).
- **④ (옳음):** 정수형은 크기가 클수록 값을 나타내는 비트가 많으므로 유효 범위가 넓다. 2바이트 `short`는 -32,768 ~ 32,767을, 4바이트 `int`는 -2,147,483,648 ~ 2,147,483,647을 표현한다.
- **⑤ (옳음):** `char`형 변수에는 문자의 정수 코드가 저장되므로 `char`는 1바이트 크기의 정수형이다. 그래서 `'M' + 1`처럼 산술 연산을 할 수 있고, 작은 정수를 저장하는 데에도 쓴다([3장 1.3절](Concepts_Lecture.ko.md#13-문자형)).
- **⑥ (잘못됨):** 변수의 크기는 데이터 타입으로 정해지며 저장하는 값에 따라 늘어나지 않는다. 최댓값보다 큰 값을 저장하면 상위 비트가 잘려 유효 범위 안의 값으로 설정된다(오버플로). 예를 들어 `char n = 128;`이면 `n`은 -128이 된다([3장 1.1절의 오버플로와 언더플로](Concepts_Lecture.ko.md#오버플로와-언더플로)).
- **⑦ (옳음):** 최솟값보다 작은 값을 저장할 때도 상위 비트가 잘려 값이 유효 범위 안에서 순환한다(언더플로). 연습 문제 8의 `short b = SHRT_MIN - 1;`에서 `b`는 `short`의 최댓값 32767이 된다.
- **⑧ (잘못됨):** 실수형 변수에 표현 가능한 최댓값보다 큰 값을 저장하면 0이 아니라 무한대(`INF`)로 설정된다. 0이 되는 것은 0이 아닌 최솟값보다 절댓값이 작은 값을 저장하는 언더플로의 경우이다([3장 1.2절의 실수형 오버플로와 언더플로](Concepts_Lecture.ko.md#실수형-오버플로와-언더플로)).
- **⑨ (잘못됨):** 실수의 정밀도, 즉 유효숫자의 개수는 가수 부분의 비트 수로 정해지고, 지수 부분은 표현할 수 있는 범위를 정한다. `float`는 가수가 23비트여서 유효숫자가 약 7자리이고, `double`은 52비트여서 약 15자리이다([3장 2.3절](Concepts_Lecture.ko.md#23-실수의-2진-표현-ieee-754)).
- **⑩ (잘못됨):** 0.1처럼 2진수로 나타내면 끝없이 반복되는 소수는 가수의 비트 수에서 반올림한 근삿값으로 저장되므로 표현 오차가 생긴다. 0.5나 23.625처럼 2의 거듭제곱의 합으로 유한하게 나타나고 가수의 비트 수 안에 들어가는 값만 정확히 표현된다([3장 1.2절의 표현 오차](Concepts_Lecture.ko.md#표현-오차)).

> **참고:** **범위를 벗어난 정수의 저장.** ⑥과 ⑦에서 값이 유효 범위 안으로 순환한다는 설명은 2의 보수를 쓰는 일반적인 시스템의 동작이다. C 표준은 범위를 벗어난 값을 부호 없는 정수형으로 변환한 결과를 $2^N$($N$은 비트 수)으로 나눈 나머지로 정하지만, 부호 있는 정수형으로 변환한 결과는 구현에 따라 정해지는 동작(implementation-defined behavior)으로 둔다. gcc, clang, Visual C++는 이때도 상위 비트를 잘라 내므로 위와 같이 순환한다. 한편 `INT_MAX + 1`처럼 부호 있는 정수의 산술 연산 결과가 범위를 넘는 것은 정의되지 않은 동작(undefined behavior)이므로, 순환을 가정하는 코드를 쓰지 않는다.

## 연습 문제 2: 이스케이프 시퀀스의 의미

**교재 문항:** 3장 연습 문제 2번

**문제:** 이스케이프 시퀀스 `'\0'`, `'\a'`, `'\b'`, `'\t'`, `'\n'`, `'\\'`를 각각의 의미와 연결하라. 보기는 [연습 문제 2](Exercises.ko.md#연습-문제-2-이스케이프-시퀀스의-의미)에 있다.

### 풀이

**정답:** (1) ②, (2) ④, (3) ⑥, (4) ③, (5) ①, (6) ⑤

**해설:** 이스케이프 시퀀스는 역슬래시(`\`)와 정해진 문자로, 출력할 수 없는 제어 문자나 문자열 안에서 특별하게 표기해야 하는 문자를 나타낸다([3장 1.3절의 이스케이프 시퀀스](Concepts_Lecture.ko.md#이스케이프-시퀀스)). 두 글자로 쓰지만 각각 문자 하나이다.

- **(1) `'\0'` → ② 널 문자:** ASCII 코드 0인 문자이며, 문자열의 끝을 표시하는 데 쓰인다.
- **(2) `'\a'` → ④ 경고음:** ASCII 코드 7인 제어 문자(alert)이다. 출력하면 화면에 글자가 나타나지 않고 터미널 설정에 따라 경고음이 울린다.
- **(3) `'\b'` → ⑥ 백스페이스:** ASCII 코드 8인 제어 문자이며, 출력 위치를 한 칸 왼쪽으로 옮긴다. 그 뒤에 출력하는 문자는 앞 글자 위에 덮어 쓰인다.
- **(4) `'\t'` → ③ 수평 탭:** ASCII 코드 9인 제어 문자이며, 출력 위치를 다음 탭 위치로 옮긴다.
- **(5) `'\n'` → ① 줄바꿈:** ASCII 코드 10인 제어 문자이며, 출력 위치를 다음 줄의 처음으로 옮긴다.
- **(6) `'\\'` → ⑤ 역슬래시:** 역슬래시는 이스케이프 시퀀스의 시작을 뜻하므로, 역슬래시 문자 자체(ASCII 코드 92)를 나타내려면 두 번 쓴다.

## 연습 문제 3: 변수에 대한 설명

**교재 문항:** 3장 연습 문제 3번

**문제:** 변수의 선언, 메모리 할당, 초기화에 대한 일곱 가지 설명 중 올바른 것을 모두 고르라. 보기는 [연습 문제 3](Exercises.ko.md#연습-문제-3-변수에-대한-설명)에 있다.

### 풀이

**정답:** ②, ③

**해설:** 변수는 프로그램 실행 중 값을 변경할 수 있는 이름이 붙은 메모리 영역이다([3장 3절](Concepts_Lecture.ko.md#3-변수)). 변수를 쓰려면 먼저 데이터 타입과 이름을 선언해야 하며, 선언하면 데이터 타입의 크기만큼 메모리가 할당된다.

- **① (잘못됨):** C에서 모든 변수는 사용하기 전에 데이터 타입을 선언해야 한다. 컴파일러는 데이터 타입으로 할당할 바이트 수와 저장된 비트의 해석 방식을 정한다.
- **② (옳음):** 변수에 저장된 값은 `printf("%d", x)`나 `y = x + 1`처럼 언제든 읽어 와서 쓸 수 있다.
- **③ (옳음):** 변수는 메모리 영역에 이름을 붙인 것이므로, 선언하면 데이터 타입의 크기만큼 메모리가 할당된다. `int` 변수는 대개 4바이트를 차지한다.
- **④ (잘못됨):** 변수 선언은 데이터 타입과 이름으로 이루어지며, 이름은 식별자 규칙을 따라야 한다. 프로그램은 이 이름으로 변수의 메모리 영역에 접근한다.
- **⑤ (잘못됨):** 변수의 값은 실행 중에 대입문으로 몇 번이든 바꿀 수 있다. 값을 바꿀 수 없는 것은 상수이며, 변수 중에서는 `const`를 붙인 변수만 예외적으로 값을 바꿀 수 없다.
- **⑥ (잘못됨):** 초기화는 변수가 메모리에 할당될 때, 즉 선언할 때 초기값을 지정하는 것이다(`int y = 10;`). 이미 만들어진 변수에 값을 저장하는 것(`x = 5;`)은 대입이다([3장 3.1절](Concepts_Lecture.ko.md#31-선언과-초기화)).
- **⑦ (잘못됨):** 초기화하지 않은 지역 변수에는 이전에 그 메모리에 있던 쓰레기 값이 들어 있고, 이를 읽으면 정의되지 않은 동작이 된다. 함수 밖에 선언한 전역 변수는 자동으로 0으로 초기화되지만, 이는 변수 일반에 대한 규칙이 아니다.

## 연습 문제 4: 올바른 변수 선언문

**교재 문항:** 3장 연습 문제 4번

**문제:** 여섯 개의 변수 선언문 중 올바른 것을 모두 고르라. 보기는 [연습 문제 4](Exercises.ko.md#연습-문제-4-올바른-변수-선언문)에 있다.

### 풀이

**정답:** ③, ⑤

**해설:** 변수 선언문은 데이터 타입 다음에 변수 이름을 쓰고 세미콜론으로 끝내며, 변수 이름은 식별자 규칙을 따라야 한다. 식별자는 영문자, 숫자, 밑줄(`_`)만 쓰고, 숫자로 시작할 수 없으며, 키워드와 같을 수 없고, 공백을 포함할 수 없다([3장 3.2절](Concepts_Lecture.ko.md#32-식별자와-이름-규칙)). 여섯 보기를 `gcc -std=c99`로 컴파일하면 ③과 ⑤만 오류 없이 컴파일된다.

- **① (잘못됨):** `default`는 `switch` 문에서 쓰는 키워드이므로 변수 이름으로 쓸 수 없다.
- **② (잘못됨):** 식별자에는 밑줄 외의 기호를 쓸 수 없으므로 `%`가 들어간 `%_of_market`은 변수 이름이 될 수 없다. `percent_of_market`처럼 바꾸어야 한다.
- **③ (옳음):** `unsigned short`는 부호 없는 2바이트 정수형이고, `maxCount`는 연결되는 단어의 첫 글자를 대문자로 쓴 camelCase 이름이다.
- **④ (잘못됨):** 같은 블록 안에서 같은 이름의 변수를 두 번 선언할 수 없다. 데이터 타입이 달라도 마찬가지이며, 컴파일러는 `num`을 다른 타입으로 다시 정의했다는 오류를 낸다.
- **⑤ (옳음):** 같은 타입의 변수를 콤마로 나열하여 한 번에 선언하면서 일부만 초기화할 수 있다. `x`는 100, `z`는 200으로 초기화되고 `y`는 선언만 된다.
- **⑥ (잘못됨):** 변수 이름에 공백을 넣을 수 없다. `elapsed sec`은 두 단어로 해석되어 문법 오류가 나므로 `elapsed_sec`이나 `elapsedSec`으로 써야 한다.

## 연습 문제 5: 상수에 대한 설명

**교재 문항:** 3장 연습 문제 5번

**문제:** 리터럴 상수, 매크로 상수, `const` 변수에 대한 여덟 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 5](Exercises.ko.md#연습-문제-5-상수에-대한-설명)에 있다.

### 풀이

**정답:** ③, ④, ⑤, ⑦

**해설:** 상수는 값이 변경되지 않는 요소이며, 소스 코드에 값을 직접 쓰는 리터럴 상수와 값에 이름을 붙인 기호 상수로 나뉜다. 기호 상수는 `#define`으로 만드는 매크로 상수와 `const` 변수로 만든다([3장 4절](Concepts_Lecture.ko.md#4-상수와-리터럴)).

- **① (옳음):** 상수는 값을 바꿀 수 없으므로 대입 연산자 `=`의 왼쪽에 올 수 없다. `10 = x;`나 `const` 변수에 값을 대입하는 문장은 컴파일 에러이다(연습 문제 7).
- **② (옳음):** 리터럴 상수의 성질을 설명한 것이다. 수식에 쓴 리터럴 상수는 변수처럼 이름이 붙은 메모리에 저장되지 않고 한 번 사용된 다음 없어지는 임시값으로 쓰인다([3장 4.1절](Concepts_Lecture.ko.md#41-리터럴-상수)). 같은 상수라도 `const` 변수는 메모리에 할당되므로(⑦), 이 설명은 리터럴 상수에 대해 성립한다.
- **③ (잘못됨):** 이름이 있는 상수는 기호 상수이다. 리터럴 상수는 `10`, `3.14`, `'A'`처럼 소스 코드에 값을 직접 쓴 상수이며 이름이 없다.
- **④ (잘못됨):** 코드를 알아보기 쉽고 수정하기 쉽게 하는 것은 리터럴 상수가 아니라 기호 상수이다(연습 문제 6). 같은 리터럴을 여러 곳에 쓰면 값이 바뀔 때 모든 곳을 찾아 고쳐야 하고, 숫자만으로는 그 값의 의미가 드러나지 않는다.
- **⑤ (잘못됨):** `#define`문은 C 문장이 아니라 전처리기 문장이며, `#define PI 3.141592`처럼 이름과 대치할 값만 쓰고 데이터 타입은 쓰지 않는다. 대치된 뒤의 타입은 리터럴 자체가 정하며, `3.141592`는 `double`이다([3장 4.2절](Concepts_Lecture.ko.md#42-매크로-상수-define)).
- **⑥ (옳음):** 전처리기는 식별자로 쓰인 매크로 이름만 대치하고 문자열 안의 글자는 대치하지 않는다. `printf("HOURLY_WAGE\n");`는 `HOURLY_WAGE`를 그대로 출력한다.
- **⑦ (잘못됨):** `const` 변수는 값을 바꿀 수 없을 뿐 여전히 변수이므로 메모리에 할당되며, `&`로 그 주소를 구할 수도 있다([3장 4.3절](Concepts_Lecture.ko.md#43-const-변수)).
- **⑧ (옳음):** `const` 변수에 값을 대입하면 컴파일러가 오류를 낸다(연습 문제 7의 12번 줄).

> **참고:** **리터럴 값이 놓이는 곳.** ②의 "메모리에 저장되지 않는다"는 리터럴 상수에 이름이 붙은 메모리 공간이 따로 할당되지 않는다는 뜻이다. 값 자체는 컴파일러가 기계어 명령어 안에 직접 넣거나 읽기 전용 데이터 영역에 둔다. 특히 문자열 리터럴 `"hello"`는 프로그램이 실행되는 동안 계속 유지되는 `char` 배열로 메모리에 저장된다.

## 연습 문제 6: 기호 상수의 장점

**교재 문항:** 3장 연습 문제 6번

**문제:** 리터럴 상수 대신 기호 상수를 사용할 때의 장점을 두 가지 쓰라. 문제 전문은 [연습 문제 6](Exercises.ko.md#연습-문제-6-기호-상수의-장점)에 있다.

### 풀이

**정답:** (1) 프로그램을 수정하기 쉽다. (2) 프로그램을 이해하기 쉽다.

**해설:** 기호 상수는 값에 이름을 붙인 상수이며, 매크로 상수와 `const` 변수가 있다([3장 4.3절](Concepts_Lecture.ko.md#43-const-변수)).

- **(1) 수정하기 쉽다:** 값이 바뀌면 기호 상수를 정의한 한 곳만 고치면 된다. 리터럴 상수를 쓰면 같은 값이 쓰인 모든 곳을 찾아 고쳐야 하고, 한 곳이라도 빠뜨리면 프로그램이 잘못 동작한다.
- **(2) 이해하기 쉽다:** 숫자 대신 의미 있는 이름이 드러난다. `wage = 8350 * hours;`보다 `wage = HOURLY_WAGE * hours;`가 8350이 시급이라는 것을 분명히 보여 준다.

## 연습 문제 7: 컴파일 에러가 발생하는 줄

**교재 문항:** 3장 연습 문제 7번

**문제:** 매크로 상수 `MAX`, `MIN`과 `const` 변수 `y`를 쓰는 14줄의 소스 코드에서 컴파일 에러가 발생하는 줄을 모두 찾으라. 소스 코드는 [연습 문제 7](Exercises.ko.md#연습-문제-7-컴파일-에러가-발생하는-줄)에 있다.

### 풀이

**정답:** 10번 줄, 12번 줄, 13번 줄

**해설:** 매크로 상수와 `const` 변수는 값을 바꿀 수 없고, `#define`문의 끝에 세미콜론을 쓰면 세미콜론까지 대치된다([3장 4.2절](Concepts_Lecture.ko.md#42-매크로-상수-define), [4.3절](Concepts_Lecture.ko.md#43-const-변수)). 이 코드를 `gcc -std=c99 -Wall`로 컴파일하면 세 줄에서만 오류가 보고된다.

- **10번 줄 (에러):** 전처리기가 `MAX`를 `1000`으로 대치하므로 이 문장은 `1000 = 2000;`이 된다. 리터럴 상수에는 값을 대입할 수 없다.
- **11번 줄 (정상):** `x = 1000 - 1;`이 되어 일반 변수 `x`에 999를 대입한다.
- **12번 줄 (에러):** `y`는 `const` 변수이므로 8번 줄에서 초기화한 뒤에는 값을 바꿀 수 없다.
- **13번 줄 (에러):** 3번 줄의 `#define MIN 0;`은 `MIN`을 `0;`으로 정의하므로, 전처리 뒤의 문장은 `printf("range: %d ~ %d\n", 0;, 1000);`이 된다. 함수 호출의 인자 목록 안에 세미콜론이 들어가 문법 오류가 난다. 3번 줄 자체는 오류가 아니며, 오류는 매크로가 쓰인 13번 줄에서 보고된다.
- **나머지 줄 (정상):** 2번 줄의 매크로 정의와 7번, 8번 줄의 선언과 초기화는 올바르다. `main`이 `return` 문 없이 14번 줄에서 끝나지만, C99부터는 `main`의 끝에 도달하면 0이 반환되므로 오류가 아니다.

## 연습 문제 8: 범위를 벗어난 값의 출력

**교재 문항:** 3장 연습 문제 8번

**문제:** `char a = CHAR_MIN - 1;`, `short b = SHRT_MIN - 1;`, `char ch = '\t';`를 `printf("%d, %d, %x\n", a, b, ch);`로 출력하는 프로그램의 실행 결과를 쓰라. 소스 코드는 [연습 문제 8](Exercises.ko.md#연습-문제-8-범위를-벗어난-값의-출력)에 있다.

### 풀이

**정답:** `127, 32767, 9`

**해설:** `a`와 `b`에는 각 데이터 타입의 최솟값보다 1 작은 값이 저장되어 언더플로가 일어나고, `ch`에는 탭 문자의 ASCII 코드 9가 저장된다([3장 1.1절의 오버플로와 언더플로](Concepts_Lecture.ko.md#오버플로와-언더플로)).

- **`a`:** `CHAR_MIN - 1`은 `int`로 계산되어 -129가 된다. -129는 32비트 2의 보수로 `0xFFFFFF7F`이고, `char`에 저장할 때 상위 3바이트가 잘려 하위 1바이트 `0x7F`만 남으므로 `a`는 `char`의 최댓값 127이 된다.
- **`b`:** `SHRT_MIN - 1`도 `int`로 계산되어 -32769(`0xFFFF7FFF`)가 되고, 하위 2바이트 `0x7FFF`만 남으므로 `b`는 `short`의 최댓값 32767이 된다.
- **`ch`:** `'\t'`의 ASCII 코드는 9이고, `%x`는 이를 16진수로 출력한다. 9는 16진수로도 한 자리 `9`이다.
- **출력:** `printf`에 넘긴 `char`와 `short` 값은 `int`로 변환되어 전달되므로, `%d`로 127과 32767이 출력된다.

**실행 결과:** 이 코드를 `gcc -std=c99 -Wall`로 컴파일하면 `a`와 `b`를 초기화하는 두 줄에서 값이 -129에서 127로, -32769에서 32767로 바뀐다는 경고(`-Wconstant-conversion`)가 나오고, 실행하면 다음과 같이 출력된다.

```text
127, 32767, 9
```

> **참고:** **범위를 벗어난 값의 변환 규칙.** `<limits.h>`의 `CHAR_MIN`과 `SHRT_MIN`은 `int`형 상수이므로 `CHAR_MIN - 1`과 `SHRT_MIN - 1`은 먼저 `int`로 계산되며, -129와 -32769는 `int`의 범위 안에 있으므로 뺄셈 자체에서는 오버플로가 일어나지 않는다. 범위를 벗어나는 것은 그 결과를 `char`와 `short`에 저장하는 변환 단계이고, 범위를 벗어난 값을 부호 있는 정수형으로 변환한 결과는 C 표준에서 구현에 따라 정해진다(implementation-defined). gcc, clang, Visual C++는 상위 비트를 잘라 내므로 127과 32767이 나온다. 이와 달리 `int`끼리의 연산 결과가 `int`의 범위를 넘는 부호 있는 정수의 산술 오버플로는 정의되지 않은 동작(undefined behavior)이다. 또 `CHAR_MIN`이 -128인 것은 `char`가 부호 있는 형인 시스템의 경우이며, `char`가 부호 없는 형인 ARM Linux에서는 `CHAR_MIN`이 0이므로 `a`는 -1을 부호 없는 `char`로 변환한 255가 된다.

## 연습 문제 9: 정사각형의 넓이와 둘레

**교재 문항:** 3장 프로그래밍 과제 1번

**문제:** 한 변의 길이를 정수로 입력받아 정사각형의 넓이와 둘레를 출력하라. 문제 전문과 실행 예시는 [연습 문제 9](Exercises.ko.md#연습-문제-9-정사각형의-넓이와-둘레)에 있다.

### 풀이

**접근 방법:** 한 변의 길이를 a라 하면 정사각형의 넓이는 a × a, 둘레는 4 × a이다. 실행 예시의 입력과 출력이 모두 정수이므로 세 변수를 `int`로 선언한다([3장 1.1절](Concepts_Lecture.ko.md#11-정수형)).

- **입력:** `scanf("%d", &side);`로 정수 하나를 읽는다. `scanf`에는 변수의 주소를 넘겨야 하므로 변수 이름 앞에 `&`를 붙인다([3장 5.3절](Concepts_Lecture.ko.md#53-scanf)).
- **계산:** `side * side`와 `4 * side`는 `int`끼리의 곱셈이므로 결과도 `int`이다.
- **출력:** `%d`로 두 값을 10진 정수로 출력한다. 프롬프트 `"한 변의 길이 ? "`는 실행 예시처럼 물음표 앞에 공백을 둔다.
- **`_CRT_SECURE_NO_WARNINGS`:** Visual Studio는 `scanf`에 보안 경고 C4996을 내고 새 프로젝트의 기본 설정에서는 이를 오류로 처리하므로, 첫 줄에 이 매크로를 정의하여 `scanf`를 쓸 수 있게 한다. 다른 컴파일러에서는 아무 영향이 없다. 이 장의 다른 프로그램도 같은 줄로 시작한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int side;          // length of one side
    int area;          // area of the square
    int perimeter;     // perimeter of the square

    printf("한 변의 길이 ? ");
    scanf("%d", &side);

    area = side * side;
    perimeter = 4 * side;

    printf("정사각형의 넓이: %d\n", area);
    printf("정사각형의 둘레: %d\n", perimeter);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall square.c -o square`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
한 변의 길이 ? 5
정사각형의 넓이: 25
정사각형의 둘레: 20
```

> **주의:** `side * side`는 `int`로 계산되므로, 한 변의 길이가 46341 이상이면 넓이가 `int`의 최댓값 2,147,483,647을 넘는다($46341^2 = 2{,}147{,}488{,}281$). 이는 부호 있는 정수의 산술 오버플로이므로 정의되지 않은 동작이다. 더 큰 값을 다루려면 `long long area = (long long)side * side;`처럼 `long long`으로 계산하고 `%lld`로 출력한다. 또 이 프로그램은 입력을 검사하지 않으므로 음수를 입력하면 넓이는 양수로, 둘레는 음수로 출력된다.

## 연습 문제 10: 직사각형의 넓이와 둘레

**교재 문항:** 3장 프로그래밍 과제 2번

**문제:** 가로와 세로의 길이를 정수로 입력받아 직사각형의 넓이와 둘레를 출력하라. 문제 전문과 실행 예시는 [연습 문제 10](Exercises.ko.md#연습-문제-10-직사각형의-넓이와-둘레)에 있다.

### 풀이

**접근 방법:** 가로를 w, 세로를 h라 하면 직사각형의 넓이는 w × h, 둘레는 2 × (w + h)이다. 연습 문제 9와 같이 정수형 변수를 쓰고, 프롬프트를 출력한 뒤 `scanf`로 읽는 과정을 가로와 세로에 대해 한 번씩 수행한다.

- **선언:** `int width, height;`처럼 같은 타입의 변수는 콤마로 나열하여 한 번에 선언할 수 있다([3장 3.1절](Concepts_Lecture.ko.md#31-선언과-초기화)).
- **넓이:** `width * height`는 10 × 20 = 200이다.
- **둘레:** `2 * (width + height)`는 괄호 안의 덧셈을 먼저 계산하여 2 × 30 = 60이 된다. 괄호 없이 `2 * width + height`로 쓰면 곱셈이 먼저 계산되어 2 × 10 + 20 = 40이 된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int width, height;     // lengths of the two sides
    int area, perimeter;

    printf("가로의 길이? ");
    scanf("%d", &width);
    printf("세로의 길이? ");
    scanf("%d", &height);

    area = width * height;
    perimeter = 2 * (width + height);

    printf("직사각형의 넓이: %d\n", area);
    printf("직사각형의 둘레: %d\n", perimeter);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall rectangle.c -o rectangle`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
가로의 길이? 10
세로의 길이? 20
직사각형의 넓이: 200
직사각형의 둘레: 60
```

> **주의:** 연습 문제 9와 마찬가지로 `width * height`가 `int`의 최댓값을 넘으면(예: 50000 × 50000) 정의되지 않은 동작이 되므로, 큰 값을 다루려면 `long long`으로 계산한다.

## 연습 문제 11: 위치 에너지의 계산

**교재 문항:** 3장 프로그래밍 과제 3번

**문제:** kg 단위의 질량과 m 단위의 높이를 입력받아 위치 에너지 9.8 × 질량 × 높이를 출력하라. 문제 전문과 실행 예시는 [연습 문제 11](Exercises.ko.md#연습-문제-11-위치-에너지의-계산)에 있다.

### 풀이

**접근 방법:** 질량과 높이는 실수일 수 있고 위치 에너지는 9.8을 곱한 실수이므로 세 변수를 모두 `double`로 선언한다([3장 1.2절](Concepts_Lecture.ko.md#12-실수형)).

- **입력:** `double` 변수를 `scanf`로 읽을 때는 `%lf`를 쓴다. `10`처럼 소수점 없이 입력해도 10.0으로 읽힌다.
- **계산:** `9.8 * mass * height`에서 `9.8`은 `double` 리터럴이다. 9.8 × 10 × 5 = 490이다.
- **출력:** `printf`에서는 `double` 값을 `%f`로 출력하며, `%.2f`로 소수점 이하 2자리까지 출력하여 `490.00`을 만든다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double mass;       // mass in kg
    double height;     // height in m
    double energy;     // potential energy in J

    printf("질량(kg)? ");
    scanf("%lf", &mass);
    printf("높이(m)? ");
    scanf("%lf", &height);

    energy = 9.8 * mass * height;

    printf("위치에너지: %.2f J\n", energy);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall energy.c -o energy`로 경고 없이 컴파일되며, 첫 번째 실행은 실행 예시와 같다. 두 번째 실행은 질량과 높이를 실수로 입력한 경우이며, 9.8 × 2.5 × 1.2 = 29.4이다.

```text
질량(kg)? 10
높이(m)? 5
위치에너지: 490.00 J
```

```text
질량(kg)? 2.5
높이(m)? 1.2
위치에너지: 29.40 J
```

> **주의:** `printf`와 달리 `scanf`에서는 `%f`와 `%lf`를 구분해야 한다. `double` 변수를 `%f`로 읽으면 8바이트 변수의 일부에 4바이트 `float`의 비트 패턴을 쓰게 되어 값이 잘못 저장되며, 이는 정의되지 않은 동작이다. gcc와 clang은 `-Wall`에서 이런 형식 불일치를 경고한다.

## 연습 문제 12: 직각삼각형의 넓이

**교재 문항:** 3장 프로그래밍 과제 4번

**문제:** 밑변과 높이를 입력받아 직각삼각형의 넓이를 소수점 이하 2자리로 출력하라. 문제 전문과 실행 예시는 [연습 문제 12](Exercises.ko.md#연습-문제-12-직각삼각형의-넓이)에 있다.

### 풀이

**접근 방법:** 직각삼각형의 넓이는 밑변 × 높이 ÷ 2이다. 밑변과 높이가 정수여도 넓이는 3 × 7 ÷ 2 = 10.5처럼 소수가 될 수 있으므로, 넓이를 실수형으로 저장하고 나눗셈이 실수 나눗셈이 되게 하는 것이 이 문제의 핵심이다([3장 6절](Concepts_Lecture.ko.md#6-형-변환)).

- **데이터 타입:** 밑변과 높이도 실수로 입력할 수 있게 `double`로 선언하고 `%lf`로 읽는다. `scanf` 하나에 `%lf %lf`를 쓰면 공백으로 구분한 두 값을 한 줄에서 읽는다.
- **계산:** `base * height`가 `double`이므로 `/ 2`의 정수 `2`가 `double`로 변환되어 실수 나눗셈이 된다. 21.0 ÷ 2 = 10.5이다.
- **출력:** `%.2f`로 `10.50`을 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double base, height;   // base and height of the right triangle
    double area;

    printf("밑변과 높이? ");
    scanf("%lf %lf", &base, &height);

    area = base * height / 2;

    printf("직각삼각형의 면적: %.2f\n", area);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall triangle.c -o triangle`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
밑변과 높이? 3 7
직각삼각형의 면적: 10.50
```

> **주의:** **정수 나눗셈.** 밑변과 높이를 `int`로 선언하고 `%d %d`로 읽은 뒤 같은 식 `area = base * height / 2;`를 쓰면, 오른쪽이 모두 `int`이므로 21 / 2가 정수 나눗셈으로 먼저 계산되어 10이 되고, 그 값이 `double`로 변환되어 `area`에 저장된다. 이렇게 고친 프로그램의 실행 결과는 다음과 같이 `10.00`이다. 정수로 입력받으려면 `base * height / 2.0`이나 `(double)base * height / 2`로 실수 나눗셈을 하게 한다([3장 6.2절](Concepts_Lecture.ko.md#62-명시적-형-변환-캐스팅)).

```text
밑변과 높이? 3 7
직각삼각형의 면적: 10.00
```

## 연습 문제 13: 달러의 원화 환산

**교재 문항:** 3장 프로그래밍 과제 5번

**문제:** 달러 금액과 원/달러 환율을 입력받아 몇 원인지 출력하라. 문제 전문과 실행 예시는 [연습 문제 13](Exercises.ko.md#연습-문제-13-달러의-원화-환산)에 있다.

### 풀이

**접근 방법:** 원화 금액은 달러 × 환율이다. 실행 예시에서 달러는 `USD 150`처럼 정수로, 원화는 `181500.00`처럼 소수점 이하 2자리로 출력되므로, 달러는 `int`로, 환율과 원화는 `double`로 선언한다. 환율은 1210.5처럼 소수가 될 수 있다.

- **입력:** 달러는 `%d`로, 환율은 `%lf`로 읽는다. 실행 예시의 순서대로 달러를 먼저 묻는다.
- **계산:** `usd * rate`는 `int`와 `double`의 곱이므로 `usd`가 `double`로 변환되어 실수 곱셈이 된다([3장 6.1절](Concepts_Lecture.ko.md#61-묵시적-형-변환)). 150 × 1210 = 181500이다.
- **출력:** 한 `printf`에 `%d`와 `%.2f`를 함께 써서 `USD 150 = KRW 181500.00`을 출력한다. 형식 지정자와 인자는 순서와 타입이 맞아야 한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int usd;           // amount in US dollars
    double rate;       // won per dollar
    double krw;        // amount in won

    printf("USD? ");
    scanf("%d", &usd);
    printf("원/달러 환율? ");
    scanf("%lf", &rate);

    krw = usd * rate;

    printf("USD %d = KRW %.2f\n", usd, krw);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall usd2krw.c -o usd2krw`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
USD? 150
원/달러 환율? 1210
USD 150 = KRW 181500.00
```

> **주의:** **정수 변수에 소수 입력.** 달러를 `%d`로 읽으므로 `150.5`처럼 소수를 입력하면 `scanf`는 `150`까지만 읽고 `.5`를 입력 버퍼에 남긴다. 그러면 다음 `scanf("%lf", &rate)`가 사용자의 입력을 기다리지 않고 남은 `.5`를 환율 0.5로 읽으므로, 다음 실행처럼 잘못된 결과가 나온다. 센트 단위까지 다루려면 달러도 `double`로 선언하고 `%lf`로 읽는다.

```text
USD? 150.5
원/달러 환율? USD 150 = KRW 75.00
```

## 연습 문제 14: 원화의 달러 환산

**교재 문항:** 3장 프로그래밍 과제 6번

**문제:** 원화 금액과 원/달러 환율을 입력받아 몇 달러인지 출력하라. 문제 전문과 실행 예시는 [연습 문제 14](Exercises.ko.md#연습-문제-14-원화의-달러-환산)에 있다.

### 풀이

**접근 방법:** 달러 금액은 원화 ÷ 환율이다. 연습 문제 13과 같이 원화는 `int`로, 환율과 달러는 `double`로 선언한다. 이 문제는 나눗셈이므로 정수 나눗셈이 되지 않게 하는 것이 중요하다.

- **계산:** `krw / rate`는 `rate`가 `double`이므로 `krw`가 `double`로 변환되어 실수 나눗셈이 된다. 500000 ÷ 1210은 약 413.2231이다. 환율까지 `int`로 선언하면 정수 나눗셈이 되어 413이 되고, `413.00`이 출력된다.
- **출력:** `%.2f`는 소수점 이하 셋째 자리에서 반올림하므로 `413.22`를 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int krw;           // amount in won
    double rate;       // won per dollar
    double usd;        // amount in US dollars

    printf("KRW? ");
    scanf("%d", &krw);
    printf("원/달러 환율? ");
    scanf("%lf", &rate);

    usd = krw / rate;

    printf("KRW %d = USD %.2f\n", krw, usd);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall krw2usd.c -o krw2usd`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
KRW? 500000
원/달러 환율? 1210
KRW 500000 = USD 413.22
```

> **주의:** 환율에 0을 입력하면 0으로 나누게 된다. `rate`가 `double`이므로 이 식은 실수 나눗셈이고, IEEE 754를 따르는 gcc와 clang 환경에서는 결과가 무한대가 되어 다음과 같이 `inf`가 출력된다. 정수를 0으로 나누는 것은 정의되지 않은 동작이며, 0 같은 잘못된 입력은 [5장 2.1절](../Ch05_Control-Statements/Concepts_Lecture.ko.md#21-if)의 `if` 문으로 검사할 수 있다.

```text
KRW? 500000
원/달러 환율? 0
KRW 500000 = USD inf
```

## 연습 문제 15: 야드를 미터로 변환

**교재 문항:** 3장 프로그래밍 과제 7번

**문제:** 야드 단위의 길이를 입력받아 미터로 변환하여 출력하라. 1 yd는 0.9144 m이다. 문제 전문과 실행 예시는 [연습 문제 15](Exercises.ko.md#연습-문제-15-야드를-미터로-변환)에 있다.

### 풀이

**접근 방법:** 미터 단위의 길이는 야드 × 0.9144이다. 이 문제의 주제에 맞게 변환 계수 0.9144를 식 안에 리터럴 상수로 직접 쓴다([3장 4.1절](Concepts_Lecture.ko.md#41-리터럴-상수)).

- **데이터 타입:** 실행 예시에서 야드는 `100`처럼 정수로 출력되므로 `int`로, 미터는 소수이므로 `double`로 선언한다.
- **계산:** 리터럴 `0.9144`의 타입은 `double`이므로 `yard * 0.9144`는 실수 곱셈이다. 100 × 0.9144 = 91.44이다.
- **출력:** `%f`는 소수점 이하 6자리를 출력하므로 `91.440000`이 된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int yard;          // length in yards
    double meter;      // length in meters

    printf("길이(yd)? ");
    scanf("%d", &yard);

    meter = yard * 0.9144;     // 1 yd = 0.9144 m

    printf("%d yd = %f m\n", yard, meter);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall yard.c -o yard`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
길이(yd)? 100
100 yd = 91.440000 m
```

> **참고:** 리터럴 상수를 직접 쓰면 코드가 짧지만, 같은 값을 여러 곳에서 쓰거나 값의 의미를 드러내야 할 때는 연습 문제 16의 매크로 상수나 연습 문제 17의 `const` 변수 같은 기호 상수를 쓰는 편이 수정하기 쉽고 이해하기 쉽다(연습 문제 6).

## 연습 문제 16: 인치를 센티미터로 변환

**교재 문항:** 3장 프로그래밍 과제 8번

**문제:** 인치 단위의 길이를 입력받아 센티미터로 변환하여 출력하라. 1 in은 2.54 cm이며, 변환 계수는 매크로 상수로 정의한다. 문제 전문과 실행 예시는 [연습 문제 16](Exercises.ko.md#연습-문제-16-인치를-센티미터로-변환)에 있다.

### 풀이

**접근 방법:** `#define CM_PER_INCH 2.54`로 변환 계수에 이름을 붙이고, 센티미터 단위의 길이를 인치 × `CM_PER_INCH`로 구한다([3장 4.2절](Concepts_Lecture.ko.md#42-매크로-상수-define)). 실행 예시가 인치를 `10.00`처럼 소수점 이하 2자리로 출력하므로 인치와 센티미터를 모두 `double`로 선언한다.

- **매크로 정의:** `#define`문은 전처리기 문장이므로 끝에 세미콜론을 쓰지 않는다. `#define CM_PER_INCH 2.54;`로 쓰면 이 프로그램에서는 `cm = inch * 2.54;;`가 되어 빈 문장이 하나 더 생길 뿐이지만, 연습 문제 7의 13번 줄처럼 식 중간에서 쓰면 문법 오류가 난다.
- **대치:** 전처리기가 `inch * CM_PER_INCH`를 `inch * 2.54`로 바꾼 뒤 컴파일하므로, 실행할 때의 동작은 리터럴을 직접 쓴 것과 같다.
- **출력:** `%.2f in = %.2f cm`로 10.00과 25.40을 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

#define CM_PER_INCH 2.54       // 1 in = 2.54 cm

int main(void)
{
    double inch;       // length in inches
    double cm;         // length in centimeters

    printf("길이(in)? ");
    scanf("%lf", &inch);

    cm = inch * CM_PER_INCH;

    printf("%.2f in = %.2f cm\n", inch, cm);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall inch.c -o inch`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
길이(in)? 10
10.00 in = 25.40 cm
```

## 연습 문제 17: 제곱미터를 평으로 변환

**교재 문항:** 3장 프로그래밍 과제 9번

**문제:** 아파트의 면적을 제곱미터 단위로 입력받아 몇 평인지 출력하라. 1 m²는 0.3025평이며, 변환 계수는 기호 상수로 정의한다. 문제 전문과 실행 예시는 [연습 문제 17](Exercises.ko.md#연습-문제-17-제곱미터를-평으로-변환)에 있다.

### 풀이

**접근 방법:** 기호 상수에는 매크로 상수와 `const` 변수가 있다. 연습 문제 16에서 매크로 상수를 썼으므로 여기서는 `const double PYEONG_PER_SQM = 0.3025;`로 `const` 변수를 쓰고, 평 단위의 면적을 제곱미터 × `PYEONG_PER_SQM`으로 구한다([3장 4.3절](Concepts_Lecture.ko.md#43-const-변수)).

- **`const` 변수:** 선언할 때 초기화해야 하며, 이후 값을 바꾸려 하면 컴파일 에러가 난다. 매크로 상수와 달리 데이터 타입(`double`)이 있어 컴파일러의 타입 검사를 받는다.
- **이름:** 일반 변수와 구분되도록 기호 상수의 이름은 대문자와 밑줄로 짓는다.
- **계산과 출력:** 113 × 0.3025 = 34.1825이고, `%.2f`가 소수점 이하 셋째 자리에서 반올림하여 `34.18`을 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    const double PYEONG_PER_SQM = 0.3025;  // 1 square meter = 0.3025 pyeong
    double sqm;        // area in square meters
    double pyeong;     // area in pyeong

    printf("아파트의 면적(제곱미터)? ");
    scanf("%lf", &sqm);

    pyeong = sqm * PYEONG_PER_SQM;

    printf("%.2f 제곱미터 = %.2f 평\n", sqm, pyeong);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall pyeong.c -o pyeong`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
아파트의 면적(제곱미터)? 113
113.00 제곱미터 = 34.18 평
```

> **참고:** `const` 변수 대신 `#define PYEONG_PER_SQM 0.3025`로 매크로 상수를 정의해도 실행 결과는 같다. 두 방법은 타입 검사를 받는지, 디버거에서 이름이 보이는지, 이름을 쓸 수 있는 범위가 정의한 곳부터 파일 끝까지인지 블록 안인지에서 다르다([3장 4.3절](Concepts_Lecture.ko.md#43-const-변수)).

## 연습 문제 18: 실수의 제곱과 세제곱

**교재 문항:** 3장 프로그래밍 과제 10번

**문제:** 소수 표기나 지수 표기로 실수 값을 입력받아 그 값의 제곱과 세제곱을 지수 표기로 출력하라. 문제 전문과 실행 예시는 [연습 문제 18](Exercises.ko.md#연습-문제-18-실수의-제곱과-세제곱)에 있다.

### 풀이

**접근 방법:** 실수 값을 `double` 변수에 `%lf`로 읽고, 결과는 지수 표기 형식 지정자 `%e`로 출력한다([3장 5.1절](Concepts_Lecture.ko.md#51-주요-지정자)).

- **입력:** `scanf`의 `%lf`는 `12.34` 같은 소수 표기와 `1.234e2` 같은 지수 표기를 모두 실수로 읽으므로, 두 표기를 따로 처리할 필요가 없다. `1.234e2`는 $1.234 \times 10^{2}$, 즉 123.4이며, 소스 코드의 실수 리터럴 표기(`5.678e1`)와 같다([3장 4.1절](Concepts_Lecture.ko.md#41-리터럴-상수)).
- **계산:** `x * x`와 `x * x * x`로 제곱과 세제곱을 구한다. 0.3을 입력하면 제곱은 0.09, 세제곱은 0.027이다.
- **출력:** `%e`는 값을 `d.dddddde±dd` 형태, 즉 정수 부분 한 자리, 소수점 이하 6자리, 두 자리 이상의 지수로 출력한다. 0.09는 $9 \times 10^{-2}$이므로 `9.000000e-02`가 된다. `%E`를 쓰면 `9.000000E-02`처럼 대문자 `E`로 출력된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double x;          // input value
    double square, cube;

    printf("실수? ");
    scanf("%lf", &x);  // accepts both 12.34 and 1.234e2

    square = x * x;
    cube = x * x * x;

    printf("제곱: %e\n", square);
    printf("세제곱: %e\n", cube);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall power.c -o power`로 경고 없이 컴파일되며, 첫 번째 실행은 실행 예시와 같다. 두 번째와 세 번째 실행은 문제에 나온 소수 표기 12.34와 지수 표기 1.234e2를 입력한 경우이며, 각각 $12.34^2 = 152.2756$, $12.34^3 = 1879.080904$와 $123.4^2 = 15227.56$, $123.4^3 = 1879080.904$가 소수점 이하 6자리로 반올림되어 출력된다.

```text
실수? 3.0e-1
제곱: 9.000000e-02
세제곱: 2.700000e-02
```

```text
실수? 12.34
제곱: 1.522756e+02
세제곱: 1.879081e+03
```

```text
실수? 1.234e2
제곱: 1.522756e+04
세제곱: 1.879081e+06
```

> **주의:** 결과가 `double`의 최댓값(약 $1.8 \times 10^{308}$)을 넘으면 실수형 오버플로가 일어나 무한대가 된다. `1e200`을 입력하면 제곱이 $10^{400}$이 되므로 두 값 모두 `inf`로 출력된다([3장 1.2절의 실수형 오버플로와 언더플로](Concepts_Lecture.ko.md#실수형-오버플로와-언더플로)).

```text
실수? 1e200
제곱: inf
세제곱: inf
```
