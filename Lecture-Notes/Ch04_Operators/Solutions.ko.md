## 연습 문제 1: 헬멧의 체적과 표면적 계산

**문제:** 정수로 입력받은 헬멧의 높이 h와 밑면 반지름 a로 체적 $V = \frac{\pi}{6} h (3a^2 + h^2)$와 표면적 $S = 2\pi \left(\frac{h}{3} + \frac{V}{\pi h^2}\right) h$를 계산하라. π는 `#define`으로 정의한 3.14159265를 쓰고, 정수 나눗셈이 일어나지 않게 한다. 문제 전문과 실행 예시는 [연습 문제 1](Exercises.ko.md#연습-문제-1-헬멧의-체적과-표면적-계산)에 있다.

### 풀이

**접근 방법:** 입력은 `int`이지만 계산 결과는 소수이므로, 나눗셈이 들어가는 모든 곳에서 피연산자 하나 이상이 실수형이 되게 한다([4장 2.2절](Concepts_Lecture.ko.md#22-정수-나눗셈-vs-실수-나눗셈)).

- **매크로 상수:** `#define PI 3.14159265`로 π를 정의한다. 전처리기가 `PI`를 실수 리터럴 `3.14159265`로 바꾸므로 `PI`가 들어간 식은 `double`로 계산된다.
- **체적:** `(PI / 6.0 * height)`는 `double`이고, 두 번째 괄호 `(3 * base_radius * base_radius + height * height)`는 `int`로 계산된 뒤 곱셈에서 `double`로 변환된다. 나눗셈은 `PI / 6.0` 하나뿐이고 두 피연산자가 모두 실수이다.
- **표면적:** `height / 3.0`처럼 분모를 실수 리터럴로 써서 정수 나눗셈을 피한다. `height / 3`으로 쓰면 높이가 1일 때 0이 되어 결과가 틀린다. `volume / (PI * height * height)`는 분자와 분모가 모두 `double`이다.
- **출력:** `printf`의 `%lf`는 C99부터 `%f`와 같은 뜻이며 소수점 아래 6자리를 출력한다.

공식을 정리하면 $\frac{V}{\pi h^2} = \frac{3a^2 + h^2}{6h}$이므로 $S = 2\pi h \cdot \frac{a^2 + h^2}{2h} = \pi (a^2 + h^2)$, 즉 구관(spherical cap)의 곡면 넓이가 된다. 매크로 값 3.14159265를 π로 쓰면 h = 1, a = 1에서 $2 \times 3.14159265 \approx 6.283185$이고, h = 12, a = 20에서 $544 \times 3.14159265 \approx 1709.026402$로 실행 예시와 같다.

**코드:** [Lab_Q1.c](../../Coursework/Lab04_Operators/Lab_Q1.c)

```c
/**
 * @file    A10104-1_C04Q1.c
 * @brief   Q1. 헬멧의 체적과 표면적 계산
 * @author  박철원 (Cheolwon Park)
 * @date    2024-03-26
 * 
 * @note    소스 코드에 사용된 scanf_s는 Visual Studio 이외의
 * 	    IDE에서 실행이 불가할 수 있음에 주의하시기 바랍니다.
 */

#include <stdio.h>
#define PI 3.14159265

int main()
{
	int height, base_radius;
	double volume, surface_area;

	printf("헬멧의 높이: ");
	scanf_s(" %d", &height);

	printf("base 반지름 입력: ");
	scanf_s(" %d", &base_radius);

	volume = (PI / 6.0 * height) * (3 * base_radius * base_radius + height * height);
	surface_area = 2.0 * PI * ((height / 3.0) + (volume / (PI * height * height))) * height;

	printf("헬멧의 체적: %lf \n", volume);
	printf("헬멧의 표면적: %lf \n", surface_area);
}
```

**실행 결과:** 두 실행 예시와 같은 값을 입력하면 같은 체적과 표면적이 출력된다. 코드는 형식 문자열 끝의 `" \n"` 때문에 각 줄 끝에 공백을 하나 남긴다. 실행 예시의 마지막 줄 `Program ended with exit code: 0`은 프로그램의 출력이 아니라 Xcode 콘솔이 덧붙이는 종료 메시지이다.

```text
헬멧의 높이: 1
base 반지름 입력: 1
헬멧의 체적: 2.094395 
헬멧의 표면적: 6.283185 
```

```text
헬멧의 높이: 12
base 반지름 입력: 20
헬멧의 체적: 8444.601043 
헬멧의 표면적: 1709.026402 
```

> **참고:** **`scanf_s`와 실행 환경.** 이 장의 코드가 쓰는 `scanf_s`는 Visual Studio(MSVC)가 제공하는 함수이다. C11의 선택 사항인 부록 K(Annex K)에도 같은 이름의 함수가 정의되어 있지만, gcc와 clang이 쓰는 표준 라이브러리 대부분은 이를 제공하지 않으므로 그대로 컴파일하면 선언되지 않은 함수라는 오류가 난다. 위의 실행 결과는 코드를 바꾸지 않고 `gcc -std=c99 -Wall -Dscanf_s=scanf`로 `scanf_s`를 `scanf`로 대체하여 컴파일한 것이다. `%d`, `%x`처럼 숫자를 읽는 변환에서는 두 함수의 동작이 같다.

> **주의:** 높이로 0을 입력하면 `volume / (PI * height * height)`가 0을 0으로 나누므로 표면적이 `nan`(Not a Number)으로 출력된다. 실수 나눗셈은 0으로 나누어도 프로그램이 멈추지 않고 무한대나 `nan`을 낸다. 또 `3 * base_radius * base_radius`는 `int`로 계산되므로, a가 26754보다 크면 `int`의 범위를 넘는다.

```text
헬멧의 높이: 0
base 반지름 입력: 5
헬멧의 체적: 0.000000 
헬멧의 표면적: nan 
```

## 연습 문제 2: 시간과 초의 환산

**교재 문항:** 4장 프로그래밍 과제 8번 응용

**문제:** 시, 분, 초를 입력받아 전체 초로 환산하고, 이어서 전체 초를 입력받아 시, 분, 초로 환산하라. 기호 상수 `SEC_PER_HOUR`(3600)와 `SEC_PER_MIN`(60)을 사용한다. 문제 전문과 실행 예시는 [연습 문제 2](Exercises.ko.md#연습-문제-2-시간과-초의-환산)에 있다.

### 풀이

**접근 방법:** 앞의 환산은 곱셈과 덧셈으로, 뒤의 환산은 정수 나눗셈의 몫과 나머지로 한다([4장 2.3절](Concepts_Lecture.ko.md#23-나머지-연산자)). 여기서는 소수 부분을 버리는 정수 나눗셈이 바로 필요한 연산이다.

- **시, 분, 초 → 초:** `hour * SEC_PER_HOUR + min * SEC_PER_MIN + sec`이다. 2시간 10분 47초는 7200 + 600 + 47 = 7847초이다.
- **초 → 시:** `second_sum2 / SEC_PER_HOUR`는 3600초 단위의 몫이다. 3989초이면 1시간이다.
- **초 → 분:** 시간을 빼고 남은 초 `second_sum2 % SEC_PER_HOUR`를 60으로 나눈 몫이다. 3989 % 3600 = 389이고 389 / 60 = 6분이다.
- **초 → 초:** `second_sum2 % SEC_PER_MIN`이다. 3600은 60의 배수이므로 60으로 나눈 나머지는 시간을 뺀 뒤의 나머지와 같다. 3989 % 60 = 29초이다.

**코드:** [Lab_Q2.c](../../Coursework/Lab04_Operators/Lab_Q2.c)

```c
/**
 * @file    A10104-1_C04Q2.c
 * @brief   Q2. 시간 - 초 환산
 * @author  박철원 (Cheolwon Park)
 * @date    2024-03-27
 *  
 * @note    소스 코드에 사용된 scanf_s는 Visual Studio 이외의
 * 	    IDE에서 실행이 불가할 수 있음에 주의하시기 바랍니다.
 */

#define SEC_PER_HOUR 3600
#define SEC_PER_MIN 60
#include <stdio.h>

int main()
{
	int hour, min, sec;
	int hour_cal, min_cal, sec_cal;
	int second_sum1, second_sum2;

	printf("시간을 차례로 입력하세요(시,분,초): ");
	scanf_s(" %d %d %d", &hour, &min, &sec);

	second_sum1 = hour * SEC_PER_HOUR + min * SEC_PER_MIN + sec;

	printf("%d시간 %d분 %d초는 총 %d초입니다. \n", hour, min, sec, second_sum1);
	printf("\n---------------------------------\n");

	printf("환산할 초를 입력하세요: ");
	scanf_s(" %d", &second_sum2);

	hour_cal = (second_sum2 / SEC_PER_HOUR);
	min_cal = (second_sum2 % SEC_PER_HOUR) / SEC_PER_MIN;
	sec_cal = (second_sum2 % SEC_PER_MIN);

	printf("%d초는 %d시간 %d분 %d초입니다. \n", second_sum2, hour_cal, min_cal, sec_cal);
}
```

**실행 결과:** 환산 값은 두 실행 예시와 같다. 다만 코드는 구분선 앞에 `"\n"`을 하나 더 출력하므로 구분선 위에 빈 줄이 생기고, 구분선의 `-`는 실행 예시의 35개가 아니라 33개이다. 각 결과 줄 끝에는 공백이 하나 남는다.

```text
시간을 차례로 입력하세요(시,분,초): 2 10 47
2시간 10분 47초는 총 7847초입니다. 

---------------------------------
환산할 초를 입력하세요: 3989
3989초는 1시간 6분 29초입니다. 
```

```text
시간을 차례로 입력하세요(시,분,초): 7 1 55
7시간 1분 55초는 총 25315초입니다. 

---------------------------------
환산할 초를 입력하세요: 25315
25315초는 7시간 1분 55초입니다. 
```

> **참고:** 음수 초를 입력하면 C99의 정수 나눗셈이 0 방향으로 절삭하고 나머지의 부호가 피제수를 따르므로, 시, 분, 초가 모두 음수로 출력된다. 문제는 0 이상의 입력을 가정한다.

```text
시간을 차례로 입력하세요(시,분,초): 0 0 0
0시간 0분 0초는 총 0초입니다. 

---------------------------------
환산할 초를 입력하세요: -3725
-3725초는 -1시간 -2분 -5초입니다. 
```

## 연습 문제 3: Red, Green, Blue 값을 16진수 RGB 값으로 변환

**문제:** 0~255의 Red, Green, Blue 값을 입력받아 그림 2의 배치대로 하나의 4바이트 RGB 값으로 합치고 6자리 16진수로 출력하라. 문제 전문과 실행 예시는 [연습 문제 3](Exercises.ko.md#연습-문제-3-red-green-blue-값을-16진수-rgb-값으로-변환)에 있다.

### 풀이

**접근 방법:** 각 채널을 자기 자리로 왼쪽 시프트한 뒤 비트 OR로 합친다([4장 6.3절](Concepts_Lecture.ko.md#63-실전-예제-rgb-색상)). Red는 0비트, Green은 8비트, Blue는 16비트만큼 옮긴다.

- **결합:** `RGB = red | green << 8 | blue << 16;`은 괄호가 없지만, `<<`가 `|`보다 우선순위가 높으므로 `red | (green << 8) | (blue << 16)`으로 계산된다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)). 세 값의 1인 비트가 서로 겹치지 않으므로 OR는 덧셈과 같은 결과를 낸다. 주석으로 남긴 `|=` 세 줄도 같은 과정을 복합 대입으로 쓴 것이다.
- **출력:** `%#08X`에서 `#`은 16진수 앞에 `0X`를 붙이고, `0`은 빈자리를 0으로 채우며, 폭 8은 `0X`를 포함한 전체 글자 수이다. 따라서 16진수 부분은 6자리가 되어 `0X8200FF`, `0X0DC843`처럼 출력된다.

**코드:** [Lab_Q3.c](../../Coursework/Lab04_Operators/Lab_Q3.c)

```c
/**
 * @file    A10104-1_C04Q3.c
 * @brief   Q3. 4바이트 RGB값을 16진수 RGB값으로 변환
 * @author  박철원 (Cheolwon Park)
 * @date    2024-03-27
 *  
 * @note    소스 코드에 사용된 scanf_s는 Visual Studio 이외의
 * 	    IDE에서 실행이 불가할 수 있음에 주의하시기 바랍니다.
 */

#include <stdio.h>

int main()
{
	int red, green, blue;
	int RGB = 0;

	printf("Red 값 입력(0~255): ");
	scanf_s(" %d", &red);
	printf("Green 값 입력(0~255): ");
	scanf_s(" %d", &green);
	printf("Blue 값 입력(0~255): ");
	scanf_s(" %d", &blue);

	RGB = red | green << 8 | blue << 16;

	/* 위와 동일한 과정
	RGB |= blue << 16;
	RGB |= green << 8;
	RGB |= red; */

	printf("RGB = %#08X", RGB);
}
```

**실행 결과:** RGB 값은 두 실행 예시와 같다. 입력 안내 문구는 `(0-255)`가 아니라 `(0~255)`이고, 코드가 `RGB =` 앞에 빈 줄을 출력하지 않으며 마지막 줄 뒤에 줄바꿈도 출력하지 않는다.

```text
Red 값 입력(0~255): 255
Green 값 입력(0~255): 0
Blue 값 입력(0~255): 130
RGB = 0X8200FF
```

```text
Red 값 입력(0~255): 67
Green 값 입력(0~255): 200
Blue 값 입력(0~255): 13
RGB = 0X0DC843
```

> **주의:** **경계 입력.** `#` 플래그는 값이 0이면 접두사를 붙이지 않으므로, 세 값이 모두 0이면 `0X000000`이 아니라 `00000000`이 출력된다. 또 범위 검사가 없으므로 255보다 큰 값을 입력하면 이웃 채널의 비트를 침범한다. Red에 256을 입력하면 비트 8이 켜져 Green이 1인 것과 같은 `0X000100`이 된다.


## 연습 문제 4: 16진수 RGB 값을 Red, Green, Blue 값으로 변환

**문제:** 6자리 16진수 RGB 값을 입력받아 Red, Green, Blue 값을 추출하고 각각 2자리 16진수와 10진수로 출력하라. 문제 전문과 실행 예시는 [연습 문제 4](Exercises.ko.md#연습-문제-4-16진수-rgb-값을-red-green-blue-값으로-변환)에 있다.

### 풀이

**접근 방법:** 원하는 채널을 하위 8비트로 오른쪽 시프트한 뒤 `& 0xFF`로 나머지 비트를 지운다([4장 6.3절](Concepts_Lecture.ko.md#63-실전-예제-rgb-색상)).

- **입력:** `%x`는 16진수를 읽으며 대문자와 소문자를 모두 받는다. `A73803`은 10진수 10958851로 저장된다.
- **Red:** `RGB & 0xFF`로 하위 8비트 `0x03`을 꺼낸다.
- **Green:** `(RGB >> 8) & 0xFF`로 비트 8~15를 하위로 옮긴 뒤 꺼낸다. `0xA738`의 하위 8비트인 `0x38`이 남는다.
- **Blue:** `RGB >> 16`만 하고 마스크는 하지 않는다. 6자리 이하의 입력이면 비트 24 이상이 0이므로 `0xA7`만 남는다.
- **출력:** `%#04x`는 `0x`를 포함하여 폭 4로 출력하므로 16진수 부분이 2자리가 된다.

**코드:** [Lab_Q4.c](../../Coursework/Lab04_Operators/Lab_Q4.c)

```c
/**
 * @file    A10104-1_C04Q4.c
 * @brief   Q4. 16진수 RGB값을 4바이트 RGB값으로 변환
 * @author  박철원 (Cheolwon Park)
 * @date    2024-03-27
 *  
 * @note    소스 코드에 사용된 scanf_s는 Visual Studio 이외의
 * 	    IDE에서 실행이 불가할 수 있음에 주의하시기 바랍니다.
 */

#include <stdio.h>

int main()
{
	int RGB = 0;
	int red, green, blue;

	printf("RGB 값을 입력(16진수 6자리): ");
	scanf_s(" %x", &RGB);

	red = (RGB & 0xFF);
    // AND 연산을 이용하여 0~7번째 비트(하위 8비트) 추출
    // 예: 00000000 00000000 11111111 => 0x0000FF => 255

    green = ((RGB >> 8) & 0xFF);
    // RGB를 오른쪽으로 8비트 시프트한 뒤
    // AND 연산으로 0~7번째 비트(녹색 정보) 추출

    blue = (RGB >> 16);
    // RGB를 오른쪽으로 16비트 시프트하여
    // 하위 8비트(파란색 정보)만 남김

	printf("\nRed    = %#04x (%d) \n", red, red);
	printf("Green  = %#04x (%d) \n", green, green);
	printf("Blue   = %#04x (%d) \n", blue, blue);
} 
```

**실행 결과:** 추출한 값은 두 실행 예시와 같다. 출력 형식에는 다음 차이가 있다. 형식 지정자가 소문자 `x`이므로 `0X03`이 아니라 `0x03`처럼 소문자로 출력되고, `Red`, `Green`, `Blue` 뒤의 공백 수와 괄호 앞의 공백, 줄 끝의 공백도 실행 예시와 다르다. Green이 0인 두 번째 실행에서는 `#` 플래그가 0에 접두사를 붙이지 않으므로 `0x00`이 아니라 `0000`이 출력된다. 입력 안내 문구는 `RGB 값을 입력`이다.

```text
RGB 값을 입력(16진수 6자리): A73803

Red    = 0x03 (3) 
Green  = 0x38 (56) 
Blue   = 0xa7 (167) 
```

```text
RGB 값을 입력(16진수 6자리): FF00DD

Red    = 0xdd (221) 
Green  = 0000 (0) 
Blue   = 0xff (255) 
```

> **참고:** `scanf`의 `%x`는 `unsigned int *`를 기대하므로 `RGB`는 `unsigned int`로 선언하는 것이 정확하다. 또 Blue에 마스크를 하지 않았기 때문에 7자리 이상을 입력하면 Blue에 위쪽 비트가 섞인다. `1A73803`을 입력하면 Blue가 `0x1a7`(423)이 되며, `(RGB >> 16) & 0xFF`로 마스크하면 이런 경우에도 하위 8비트만 남는다.

```text
RGB 값을 입력(16진수 6자리): 1A73803

Red    = 0x03 (3) 
Green  = 0x38 (56) 
Blue   = 0x1a7 (423) 
```

## 연습 문제 5: 연산자에 대한 설명

**교재 문항:** 4장 연습 문제 1번

**문제:** 연산자, 피연산자, 연산식에 대한 여덟 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 5](Exercises.ko.md#연습-문제-5-연산자에-대한-설명)에 있다.

### 풀이

**정답:** ④, ⑤, ⑥, ⑧

**해설:** 연산자는 하나 이상의 피연산자에 대해 연산을 수행하는 기호이고, 연산자와 피연산자로 이루어진 연산식은 값을 가지는 수식이다([4장 1.1절](Concepts_Lecture.ko.md#11-수식), [1.2절](Concepts_Lecture.ko.md#12-연산자와-피연산자)).

- **① (옳음):** 연산자는 `+`, `=`, `&&`처럼 연산을 나타내는 기호이다. `sizeof`처럼 키워드로 된 연산자도 있다.
- **② (옳음):** `a + b`의 `a`와 `b`처럼 연산의 대상이 되는 값을 피연산자라고 한다.
- **③ (옳음):** 연산식은 수식이고, 모든 수식에는 타입과 값이 있다. `x = 5` 같은 대입식도 값이 5인 수식이다.
- **④ (잘못됨):** 피연산자는 연산의 대상이므로 피연산자가 없는 연산자는 없다. C의 연산자는 종류에 따라 피연산자를 1개(단항), 2개(이항), 3개(삼항) 가진다.
- **⑤ (잘못됨):** C에서는 프로그래머가 새 연산자를 정의할 수 없다. `#`은 `#include`, `#define` 같은 전처리기 지시자를 나타내는 기호이며, 매크로 정의 안에서 쓰는 `#`도 전처리기가 미리 정해 둔 기능이다.
- **⑥ (잘못됨):** `^`는 두 피연산자의 비트를 비교하는 비트 XOR 연산자이므로 이항 연산자이다([4장 6.1절](Concepts_Lecture.ko.md#61-비트-and-or-xor-not)).
- **⑦ (옳음):** 콤마(`,`)는 우선순위가 가장 낮은 연산자이다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)). `a, b`는 `a`를 먼저 평가한 뒤 `b`를 평가하고, 수식 전체의 값은 `b`의 값이다. 다만 `int x, y;`처럼 선언에서 변수를 나누거나 함수의 인자를 나누는 콤마는 구분자이고 연산자가 아니다.
- **⑧ (잘못됨):** 연산식은 값을 가지므로 다른 수식의 일부로 쓸 수 있다. `y = (x = 5) + 1;`은 대입식 `x = 5`의 값 5에 1을 더하여 `y`에 6을 대입하고, `printf("%d\n", x = 5);`는 대입식의 값 5를 출력한다.

> **참고:** ③은 값을 내는 연산자를 기준으로 한 설명이다. 반환형이 `void`인 함수를 호출하는 수식은 함수 호출 연산자 `()`를 포함하지만 값이 없으므로, 다른 수식의 피연산자로 쓸 수 없다. 함수의 반환형은 6장에서 다룬다.

## 연습 문제 6: 단항 연산자

**교재 문항:** 4장 연습 문제 2번

**문제:** 열 개의 연산자 중 단항 연산자를 모두 고르라. 보기는 [연습 문제 6](Exercises.ko.md#연습-문제-6-단항-연산자)에 있다.

### 풀이

**정답:** ①, ②, ③, ④, ⑤, ⑧

**해설:** 단항 연산자는 피연산자가 1개인 연산자이다([4장 1.2절](Concepts_Lecture.ko.md#12-연산자와-피연산자)). 우선순위 표의 2순위에 모인 `++x`, `--x`, `+x`, `-x`, `!`, `~`, `(type)`, `sizeof` 등과 1순위의 후위 증감 연산자 `x++`, `x--`가 단항 연산자이다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)).

- **① (단항):** `+x`처럼 부호 연산자로 쓰면 단항 연산자이다. `a + b`처럼 피연산자가 2개이면 덧셈을 하는 이항 연산자이다([4장 2.1절](Concepts_Lecture.ko.md#21-연산자-종류)).
- **② (단항):** `-x`처럼 부호를 반전하는 연산자로 쓰면 단항 연산자이다. `a - b`의 뺄셈은 이항 연산자이다.
- **③ (단항):** 증가 연산자 `++`는 `++x`, `x++`처럼 변수 하나에 작용한다.
- **④ (단항):** 논리 NOT `!`는 피연산자 하나의 참과 거짓을 반전한다.
- **⑤ (단항):** `sizeof`는 키워드로 된 단항 연산자이며, 피연산자 하나(`sizeof x`, `sizeof(int)`)의 크기를 바이트 수로 낸다.
- **⑥ (이항):** 시프트 연산자 `<<`는 `x << n`처럼 피연산자 2개를 가진다.
- **⑦ (이항):** 논리 AND `&&`는 두 피연산자를 결합한다.
- **⑧ (단항):** 비트 NOT `~`는 피연산자 하나의 모든 비트를 반전한다.
- **⑨ (이항):** 복합 대입 연산자 `*=`는 `x *= y`처럼 왼쪽의 변수와 오른쪽의 값을 피연산자로 가진다.
- **⑩ (이항):** 동등 비교 연산자 `==`는 두 값을 비교한다.

## 연습 문제 7: 산술 연산자에 대한 설명

**교재 문항:** 4장 연습 문제 3번

**문제:** 산술 연산자에 대한 일곱 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 7](Exercises.ko.md#연습-문제-7-산술-연산자에-대한-설명)에 있다.

### 풀이

**정답:** ③, ④, ⑥

**해설:** 산술 연산자에는 이항 연산자 `+`, `-`, `*`, `/`, `%`와 단항 연산자 `+x`, `-x`가 있으며, 피연산자의 형에 따라 정수 연산과 실수 연산이 구분된다([4장 2.1절](Concepts_Lecture.ko.md#21-연산자-종류), [2.2절](Concepts_Lecture.ko.md#22-정수-나눗셈-vs-실수-나눗셈)).

- **① (옳음):** 이항 산술 연산자로 `+`, `-`, `*`, `/`, `%`가 있다. 이 보기는 부호 연산자까지 나열하지는 않지만, 산술 연산자가 이 다섯 개뿐이라고 말하지 않으며 나열한 다섯 연산자는 모두 산술 연산자이므로 옳은 설명이다.
- **② (옳음):** `+`와 `-`는 피연산자가 하나이면 부호 연산자(`+x`, `-x`)로 쓰인다.
- **③ (잘못됨):** 두 피연산자가 모두 정수이면 정수 나눗셈을 하여, 소수 부분을 절삭한 정수 몫을 구한다. `7 / 2`는 3.5가 아니라 3이다.
- **④ (잘못됨):** `%`는 정수 피연산자에만 쓸 수 있으며, `7.5 % 2.0`은 컴파일 에러이다([4장 2.3절](Concepts_Lecture.ko.md#23-나머지-연산자)). 실수의 나머지는 `<math.h>`의 `fmod` 함수로 구한다.
- **⑤ (옳음):** 이항 연산자의 두 피연산자 중 하나가 실수형이면 다른 피연산자도 실수형으로 변환된 뒤 연산한다. `5 + 2.5`에서 5는 5.0으로 변환된다([4장 9.1절](Concepts_Lecture.ko.md#91-묵시적-승격)).
- **⑥ (잘못됨):** 두 피연산자의 형이 같아도 `char`와 `short`는 정수 승격에 의해 `int`로 변환된 뒤 연산한다. `char a = 10, b = 20;`일 때 `a + b`의 형은 `char`가 아니라 `int`이다([4장 9.1절](Concepts_Lecture.ko.md#91-묵시적-승격), [9.3절](Concepts_Lecture.ko.md#93-수식-결과의-sizeof)).
- **⑦ (옳음):** `*`, `/`, `%`는 우선순위 3, `+`, `-`는 우선순위 4이므로 곱셈 계열이 먼저 결합한다. `2 + 3 * 4`는 14이다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)).

## 연습 문제 8: 연산식의 결과 형

**교재 문항:** 4장 연습 문제 4번

**문제:** 상수와 `char`, `short` 변수로 이루어진 여섯 연산식의 결과 형을 쓰라. 연산식은 [연습 문제 8](Exercises.ko.md#연습-문제-8-연산식의-결과-형)에 있다.

### 풀이

**정답:** (1) `double`, (2) `double`, (3) `double`, (4) `int`, (5) `int`, (6) `int`

**해설:** 접미사가 없는 실수 상수는 `double`형, 접미사 `F`가 붙은 실수 상수는 `float`형, 정수 상수는 `int`형이다. 이항 연산의 두 피연산자는 더 큰 형으로 맞춰지고, `char`와 `short`는 먼저 `int`로 승격된다([4장 9.1절](Concepts_Lecture.ko.md#91-묵시적-승격)).

- **(1) `double`:** `1`은 `int`, `0.5`는 `double`이므로 `1`이 `double`로 변환된다.
- **(2) `double`:** `1.01F`는 `float`, `0.5`는 `double`이므로 `float` 값이 `double`로 변환된다.
- **(3) `double`:** `0.5F`는 `float`, `2.4`는 `double`이므로 결과는 `double`이다. 결과 형은 피연산자의 순서와 관계없이 더 큰 형으로 정해진다.
- **(4) `int`:** 두 피연산자가 모두 `int`이므로 결과도 `int`이다.
- **(5) `int`:** `ch`는 `int`로 승격되고 `1`은 `int`이므로 결과는 `int`이다. 값은 `'a'`의 ASCII 코드 97에 1을 더한 98이다.
- **(6) `int`:** `a`와 `b`는 둘 다 `short`이지만 정수 승격으로 `int`가 되므로 결과는 `int`이다. 값은 -10이다.

각 수식에 `sizeof`를 적용하면 결과 형의 크기로 이를 확인할 수 있다([4장 9.3절](Concepts_Lecture.ko.md#93-수식-결과의-sizeof)). `double`이 8바이트, `int`가 4바이트인 환경에서 여섯 수식의 `sizeof`는 차례로 8, 8, 8, 4, 4, 4이다.

## 연습 문제 9: 연산 후 수식과 변수의 값

**교재 문항:** 4장 연습 문제 5번

**문제:** `int x = 1, y = 2, z = 3;`에서 출발하여 열두 연산을 각각 수행한 뒤 연산식의 값과 `x`, `y`, `z`의 값을 쓰라. 연산식은 [연습 문제 9](Exercises.ko.md#연습-문제-9-연산-후-수식과-변수의-값)에 있다.

### 풀이

**정답:** 각 연산의 결과는 표 1과 같다.

| 항목 | 연산식 | 연산식의 값 | `x` | `y` | `z` |
|:-----|:-----|:-----:|:-----:|:-----:|:-----:|
| (1) | `z % y` | 1 | 1 | 2 | 3 |
| (2) | `++y` | 3 | 1 | 3 | 3 |
| (3) | `z = x--` | 1 | 0 | 2 | 1 |
| (4) | `z = y = x` | 1 | 1 | 1 | 1 |
| (5) | `z *= x` | 3 | 1 | 2 | 3 |
| (6) | `z *= y + 1` | 9 | 1 | 2 | 9 |
| (7) | `x > z && y < z` | 0 | 1 | 2 | 3 |
| (8) | `! x \|\| y < z` | 1 | 1 | 2 | 3 |
| (9) | `x && y` | 1 | 1 | 2 | 3 |
| (10) | `z << y` | 12 | 1 | 2 | 3 |
| (11) | `x \|= z` | 3 | 3 | 2 | 3 |
| (12) | `y = x + 1 > z ? y : y - 1` | 1 | 1 | 1 | 3 |

*표 1. 각 연산 후의 연산식 값과 변수 값*

**해설:** 대입식과 복합 대입식의 값은 대입된 값이고, 관계식과 논리식의 값은 1 또는 0이다([4장 4.2절](Concepts_Lecture.ko.md#42-결과-타입), [5.4절](Concepts_Lecture.ko.md#54-c에서의-참과-거짓)).

- **(1):** `%`는 나머지 연산자이므로 3 % 2 = 1이다. 변수는 바뀌지 않는다([4장 2.3절](Concepts_Lecture.ko.md#23-나머지-연산자)).
- **(2):** 전위 증가 `++y`는 `y`를 3으로 늘린 뒤 늘어난 값 3을 수식의 값으로 낸다([4장 3.1절](Concepts_Lecture.ko.md#31-전위-vs-후위)).
- **(3):** 후위 감소 `x--`는 `x`의 현재 값 1을 수식의 값으로 낸 뒤 `x`를 0으로 줄인다. 따라서 `z`에 1이 대입되고, 대입식의 값도 1이다.
- **(4):** 대입 연산자는 오른쪽에서 왼쪽으로 결합하므로 `z = (y = x)`이다. `y`에 1이 대입되고, 그 대입식의 값 1이 다시 `z`에 대입된다([4장 7.2절](Concepts_Lecture.ko.md#72-연쇄-대입)).
- **(5):** `z *= x`는 `z = z * x`이므로 3 * 1 = 3이 `z`에 대입되어 값이 그대로이다.
- **(6):** 복합 대입 연산자는 `+`보다 우선순위가 낮으므로 `z *= (y + 1)`, 즉 `z = z * (y + 1)` = 3 * 3 = 9이다([4장 7.1절](Concepts_Lecture.ko.md#71-단순-대입과-복합-대입)). `z = z * y + 1`(= 7)과는 다르다.
- **(7):** `x > z`는 1 > 3이므로 거짓(0)이다. `&&`의 왼쪽 피연산자가 0이면 오른쪽 `y < z`는 평가하지 않고 결과가 0으로 정해진다([4장 5.3절](Concepts_Lecture.ko.md#53-단락-평가)).
- **(8):** `!`가 `<`와 `||`보다 우선순위가 높으므로 `(!x) || (y < z)`이다. `!x`는 `!1` = 0이므로 오른쪽 `y < z`(2 < 3, 참)를 평가하며, 결과는 1이다.
- **(9):** `x`와 `y`가 모두 0이 아니므로 참이고, 논리 연산의 결과는 1이다. 결과는 `y`의 값 2가 아니라 1이다.
- **(10):** `z << y`는 3을 왼쪽으로 2비트 시프트하므로 이진수 `11`이 `1100`이 되어 $3 \times 2^2 = 12$이다([4장 6.2절](Concepts_Lecture.ko.md#62-시프트-연산자)). 시프트는 `z`를 바꾸지 않는다.
- **(11):** `x |= z`는 `x = x | z`이므로 이진수 `01 | 11` = `11`, 즉 3이 `x`에 대입된다([4장 6.1절](Concepts_Lecture.ko.md#61-비트-and-or-xor-not)).
- **(12):** 우선순위는 `+`, `>`, `?:`, `=`의 순서이므로 `y = (((x + 1) > z) ? y : (y - 1))`이다. `x + 1 > z`는 2 > 3으로 거짓이므로 `y - 1` = 1이 선택되어 `y`에 대입된다([4장 8.1절](Concepts_Lecture.ko.md#81-삼항-연산자), [10.1절](Concepts_Lecture.ko.md#101-우선순위-표)).

관계 연산자와 논리 연산자의 값을 출력하는 비슷한 문제는 [HW03 문제 1](../../Coursework/HW03_Control-Statements-I/Assignment-Explanation.ko.md#2-문제-1-연산자의-결과값)에, 증감 연산과 대입을 문장마다 추적하는 문제는 [HW03 문제 3](../../Coursework/HW03_Control-Statements-I/Assignment-Explanation.ko.md#4-문제-3-증감-연산과-대입)에 있다.

## 연습 문제 10: 관계 연산자와 논리 연산자에 대한 설명

**교재 문항:** 4장 연습 문제 6번

**문제:** 관계 연산자와 논리 연산자에 대한 여덟 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 10](Exercises.ko.md#연습-문제-10-관계-연산자와-논리-연산자에-대한-설명)에 있다.

### 풀이

**정답:** ②, ⑤, ⑥, ⑦

**해설:** 관계 연산자는 두 값을 비교하여 참이면 1, 거짓이면 0을 내고, 논리 연산자는 0이 아닌 값을 참, 0을 거짓으로 보고 결과를 1 또는 0으로 낸다([4장 4.2절](Concepts_Lecture.ko.md#42-결과-타입), [5.4절](Concepts_Lecture.ko.md#54-c에서의-참과-거짓)).

- **① (옳음):** `>`, `<`, `>=`, `<=`, `==`, `!=`처럼 두 값을 비교하는 연산자가 관계 연산자이다([4장 4.1절](Concepts_Lecture.ko.md#41-비교-연산자)).
- **② (잘못됨):** `=`은 대입 연산자이고, 두 값이 같은지 비교하는 연산자는 `==`이다([4장 4.3절](Concepts_Lecture.ko.md#43-흔한-실수-와-)).
- **③ (옳음):** `!`, `&&`, `||`의 결과는 피연산자의 값과 관계없이 항상 `int`형 0 또는 1이다.
- **④ (옳음):** 관계 연산자(우선순위 6, 7)가 이항 논리 연산자 `&&`(11), `||`(12)보다 우선순위가 높으므로, `a > 0 && b > 0`은 `(a > 0) && (b > 0)`으로 계산된다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)).
- **⑤ (잘못됨):** `~`은 모든 비트를 반전하는 비트 NOT 연산자이고, 논리 NOT 연산자는 `!`이다. 2의 보수 표현에서 `~1`은 -2이지만 `!1`은 0이다([4장 6.1절](Concepts_Lecture.ko.md#61-비트-and-or-xor-not)).
- **⑥ (잘못됨):** C에서는 0이 아닌 모든 값을 참으로 간주한다. 2나 -5도 참이므로 `2 && -5`는 1이다.
- **⑦ (잘못됨):** `!expr`은 `expr`이 0일 때 1이 되므로 `expr == 0`을 대신한다. `expr != 0`은 `expr`이 0이 아닐 때 1이 되므로, 조건으로 쓸 때는 `expr`만 써도 같은 뜻이다.
- **⑧ (옳음):** `&&`(우선순위 11)가 `||`(12)보다 우선순위가 높으므로 `a || b && c`는 `a || (b && c)`로 묶인다.

> **참고:** **우선순위와 평가 순서.** ④와 ⑧이 말하는 수행 순서는 연산자의 우선순위, 즉 피연산자가 어느 연산자에 먼저 묶이는지를 뜻한다. 논리 연산자 중 단항 연산자 `!`는 관계 연산자보다 우선순위가 높으므로 `!x < y`는 `(!x) < y`로 계산되며, ④는 이항 논리 연산자 `&&`, `||`에 대한 설명이다. 또 `&&`와 `||`는 항상 왼쪽 피연산자부터 평가하므로, `a || b && c`는 `a || (b && c)`로 묶이지만 `a`가 먼저 평가되고 `a`가 참이면 `b && c`는 평가되지 않는다([4장 5.3절](Concepts_Lecture.ko.md#53-단락-평가)).

## 연습 문제 11: 특정 비트값을 조작하기 위한 데이터

**교재 문항:** 4장 연습 문제 7번

**문제:** 비트 논리 연산에서 특정 비트값을 조작하는 데 쓰는 데이터의 이름을 쓰라. 문제 전문은 [연습 문제 11](Exercises.ko.md#연습-문제-11-특정-비트값을-조작하기-위한-데이터)에 있다.

### 풀이

**정답:** 비트마스크(bitmask) 또는 마스크(mask)

**해설:** 비트마스크는 비트 논리 연산자 `&`, `|`, `^`의 한쪽 피연산자로 쓰여, 다른 피연산자의 특정 비트만 꺼내거나 켜거나 끄거나 반전하는 값이다([4장 6.3절](Concepts_Lecture.ko.md#63-실전-예제-rgb-색상)). 마스크의 1인 비트가 조작할 자리를 나타낸다.

- **비트 꺼내기:** `x & 0xFF`는 마스크 `0xFF`(이진수 `1111 1111`)의 1인 자리, 즉 하위 8비트만 남기고 나머지 비트를 0으로 만든다.
- **비트 켜기:** `x | 0x80`은 비트 7을 1로 만들고 나머지 비트는 그대로 둔다.
- **비트 끄기:** `x & ~0x80`은 비트 7만 0으로 만들고 나머지 비트는 그대로 둔다.
- **비트 반전:** `x ^ 0x0F`는 하위 4비트만 반전한다.

## 연습 문제 12: 연산 순서대로 괄호로 묶기

**교재 문항:** 4장 연습 문제 8번

**문제:** 열 개의 연산식을 연산이 수행되는 순서대로 `()`로 묶어 표시하라. 연산식은 [연습 문제 12](Exercises.ko.md#연습-문제-12-연산-순서대로-괄호로-묶기)에 있다.

### 풀이

**정답:** 각 연산식을 묶은 결과는 표 2와 같다.

| 항목 | 연산식 | 괄호로 묶은 식 | 묶는 순서 (우선순위) |
|:-----|:-----|:-----|:-----|
| (1) | `x - y / 3` | `(x - (y / 3))` | `/`(3), `-`(4)의 순서이다. |
| (2) | `x < 0 \|\| x > 100` | `((x < 0) \|\| (x > 100))` | `<`, `>`(6), `\|\|`(12)의 순서이다. |
| (3) | `x == 0 \|\| y == 0 && z == 1` | `((x == 0) \|\| ((y == 0) && (z == 1)))` | `==`(7), `&&`(11), `\|\|`(12)의 순서이다. |
| (4) | `x = a > b` | `(x = (a > b))` | `>`(6), `=`(14)의 순서이다. |
| (5) | `!x && !y` | `((!x) && (!y))` | `!`(2), `&&`(11)의 순서이다. |
| (6) | `x += y * 2` | `(x += (y * 2))` | `*`(3), `+=`(14)의 순서이다. |
| (7) | `~x & y` | `((~x) & y)` | `~`(2), `&`(8)의 순서이다. |
| (8) | `x < 0 \|\| ! y && z` | `((x < 0) \|\| ((!y) && z))` | `!`(2), `<`(6), `&&`(11), `\|\|`(12)의 순서이다. |
| (9) | `x = x > 0 ? y + 1 : z + 2` | `(x = ((x > 0) ? (y + 1) : (z + 2)))` | `+`(4), `>`(6), `?:`(13), `=`(14)의 순서이다. |
| (10) | `z = (double) x / y` | `(z = (((double) x) / y))` | 캐스트(2), `/`(3), `=`(14)의 순서이다. |

*표 2. 연산 순서대로 괄호로 묶은 연산식*

**해설:** 우선순위가 높은 연산자부터 피연산자와 묶고, 우선순위가 같으면 결합 방향을 따른다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표), [10.2절](Concepts_Lecture.ko.md#102-결합-방향)). 표 2의 괄호 안 숫자는 4장 10.1절의 우선순위 표에 매긴 순위이며, 각 식의 가장 바깥쪽 괄호는 마지막에 수행되는 연산을 나타내므로 생략해도 된다.

- **(3)과 (8):** 왼쪽부터 차례로 묶기 쉽지만, `&&`가 `||`보다 우선순위가 높으므로 오른쪽의 `&&`가 먼저 묶인다. (3)을 `((x == 0) || (y == 0)) && (z == 1)`로 묶으면 `x`가 0이고 `z`가 1이 아닐 때 결과가 달라진다.
- **(10):** 캐스트는 바로 뒤의 피연산자 `x`에만 적용되므로, `x`를 `double`로 바꾼 뒤 실수 나눗셈을 한다([4장 9.2절](Concepts_Lecture.ko.md#92-캐스트-연산자)).

## 연습 문제 13: 조건 연산자를 이용한 입장료 계산

**교재 문항:** 4장 연습 문제 9번

**문제:** 성수기(6~8월)이면 70,000원, 아니면 35,000원이 되도록 `fee = ____;`의 빈칸을 조건 연산자로 채우라. 문제 전문과 코드는 [연습 문제 13](Exercises.ko.md#연습-문제-13-조건-연산자를-이용한-입장료-계산)에 있다.

### 풀이

**정답:** `(month >= 6 && month <= 8) ? 70000 : 35000`

**해설:** 6월 이상이면서 8월 이하라는 조건은 두 관계식을 `&&`로 이은 `month >= 6 && month <= 8`이고, 조건 연산자는 조건이 참이면 70000을, 거짓이면 35000을 수식의 값으로 낸다([4장 8.1절](Concepts_Lecture.ko.md#81-삼항-연산자)). 관계 연산자가 `&&`보다, `&&`가 조건 연산자보다 우선순위가 높으므로 괄호 없이 `month >= 6 && month <= 8 ? 70000 : 35000`으로 써도 같다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)). 수학처럼 `6 <= month <= 8`로 쓰면 `(6 <= month) <= 8`로 계산되어, 0 또는 1인 왼쪽 비교 결과가 항상 8 이하이므로 조건이 항상 참이 된다. 범위 조건을 수식으로 쓰는 비슷한 문제는 [HW03 문제 2](../../Coursework/HW03_Control-Statements-I/Assignment-Explanation.ko.md#3-문제-2-조건의-수식-표현)에 있다.

빈칸을 채운 코드는 다음과 같다.

```c
#define _CRT_SECURE_NO_WARNINGS    // Visual Studio 2022에서 scanf 사용 시 필요
#include <stdio.h>

int main(void)
{
    int month;
    int fee;

    printf("what month? ");
    scanf("%d", &month);            // 몇 월인지 입력받는다.
    fee = (month >= 6 && month <= 8) ? 70000 : 35000;

    printf("entrance fee = %d\n", fee);
}
```

**실행 결과:** `gcc -std=c99 -Wall entrance_fee.c -o entrance_fee`로 경고 없이 컴파일되며, 성수기인 7월과 성수기가 아닌 12월을 입력한 결과는 다음과 같다.

```text
what month? 7
entrance fee = 70000
```

```text
what month? 12
entrance fee = 35000
```

## 연습 문제 14: 비트 연산 프로그램의 실행 결과

**교재 문항:** 4장 연습 문제 10번

**문제:** `unsigned char` 변수 `a = 0xcd`, `b = 0xf0`으로 `a ^ b`와 `~a | b << 2`를 계산하여 `%02x`로 출력하는 프로그램의 실행 결과를 쓰라. 프로그램은 [연습 문제 14](Exercises.ko.md#연습-문제-14-비트-연산-프로그램의-실행-결과)에 있다.

### 풀이

**정답:** 첫 줄에 `z = 3d`, 둘째 줄에 `z = f2`가 출력된다.

**해설:** 각 단계의 값은 표 3과 같다. `~a`와 `b << 2`는 `int`로 승격된 32비트 값이므로 가운데의 같은 비트를 `...`로 줄여 썼다.

| 단계 | 2진수 | 16진수 |
|:-----|:-----|:-----|
| `a` | `1100 1101` | `0xcd` |
| `b` | `1111 0000` | `0xf0` |
| `a ^ b` | `0011 1101` | `0x3d` |
| `~a` | `1111 ... 1111 0011 0010` | `0xffffff32` |
| `b << 2` | `0000 ... 0011 1100 0000` | `0x000003c0` |
| `~a \| b << 2` | `1111 ... 1111 1111 0010` | `0xfffffff2` |
| `c` (하위 8비트) | `1111 0010` | `0xf2` |

*표 3. 연습 문제 14의 비트 연산 단계별 값*

- **첫 번째 출력:** `^`는 두 비트가 다를 때 1이므로 `a ^ b`는 `0011 1101` = `0x3d`이다([4장 6.1절](Concepts_Lecture.ko.md#61-비트-and-or-xor-not)). `%02x`는 소문자 16진수를 최소 2자리로 출력하므로 `z = 3d`가 출력된다([3장 5.2절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#52-출력-폭과-정렬)).
- **우선순위:** 두 번째 식은 단항 `~`(우선순위 2), 시프트 `<<`(5), 비트 OR `|`(10), 대입 `=`(14)의 순서로 묶이므로 `c = ((~a) | (b << 2))`이다([4장 10.1절](Concepts_Lecture.ko.md#101-우선순위-표)).
- **정수 승격:** `unsigned char`형인 `a`와 `b`는 연산 전에 `int`로 승격된다([4장 9.1절](Concepts_Lecture.ko.md#91-묵시적-승격)). 따라서 `~a`는 32비트 전체를 반전하여 상위 24비트가 모두 1이 되고, `b << 2`는 8비트를 넘는 `0x3c0`이 된다.
- **대입:** 결과 `0xfffffff2`를 `unsigned char`형인 `c`에 대입하면 상위 비트가 잘리고 하위 8비트 `1111 0010`만 남는다([3장 1.1절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#오버플로와-언더플로)). 하위 8비트만 보면 `~a`의 `0011 0010`과 `b << 2`의 `1100 0000`을 OR한 값이므로, `z = f2`가 출력된다.

문제의 프로그램을 `gcc -std=c99 -Wall bitwise.c -o bitwise`로 컴파일하면 경고가 없으며, 실행 결과는 다음과 같다.

```text
z = 3d
z = f2
```

## 연습 문제 15: 밀도 계산

**교재 문항:** 4장 프로그래밍 과제 1번

**문제:** 질량(g)과 부피($\text{cm}^3$)를 실수로 입력받아 질량을 부피로 나눈 밀도를 출력하라. 문제 전문과 실행 예시는 [연습 문제 15](Exercises.ko.md#연습-문제-15-밀도-계산)에 있다.

### 풀이

**접근 방법:** 질량과 부피를 `double` 변수에 읽고, 실수 나눗셈 한 번으로 밀도를 구한다([4장 2.2절](Concepts_Lecture.ko.md#22-정수-나눗셈-vs-실수-나눗셈)).

- **입력:** `scanf`에서 `double`은 `%lf`로 읽는다([2장 2.3절](../Ch02_C-Program-Basics/Concepts_Lecture.ko.md#23-scanf)). `33`처럼 소수점 없이 입력해도 33.0으로 저장된다.
- **계산:** 두 피연산자가 모두 `double`이므로 `mass / volume`은 실수 나눗셈이다. 33 / 400 = 0.0825이다.
- **출력:** `%f`는 소수점 아래 6자리를 출력하므로 `0.082500`이 된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double mass;     // mass in grams
    double volume;   // volume in cubic centimeters
    double density;  // density in g/cm^3

    printf("질량(g)? ");
    scanf("%lf", &mass);
    printf("부피(세제곱센티미터)? ");
    scanf("%lf", &volume);

    density = mass / volume;
    printf("밀도: %f\n", density);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall density.c -o density`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
질량(g)? 33
부피(세제곱센티미터)? 400
밀도: 0.082500
```

> **주의:** 부피로 0을 입력하면 0으로 나누게 된다. IEEE 754 실수를 쓰는 환경에서 실수 나눗셈은 0으로 나누어도 프로그램이 멈추지 않고 무한대를 내므로 `inf`가 출력된다. 실제 물체의 부피는 0보다 크므로, 입력을 검사하려면 5장의 `if`문을 쓴다.

```text
질량(g)? 33
부피(세제곱센티미터)? 0
밀도: inf
```

## 연습 문제 16: 전기 요금 계산

**교재 문항:** 4장 프로그래밍 과제 2번

**문제:** 월 사용량(kWh)을 입력받아 사용량 × 190원으로 전기 요금을 계산하라. 문제 전문과 실행 예시는 [연습 문제 16](Exercises.ko.md#연습-문제-16-전기-요금-계산)에 있다.

### 풀이

**접근 방법:** 단가 190원을 매크로 상수 `PRICE_PER_KWH`로 정의하고, 사용량에 곱한다([3장 4.2절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#42-매크로-상수-define)).

- **매크로 상수:** 코드에 190을 직접 쓰는 대신 이름을 붙이면 수의 의미가 드러나고, 단가가 바뀔 때 한 곳만 고치면 된다.
- **계산:** 사용량은 실행 예시처럼 정수로 읽으므로 `usage * PRICE_PER_KWH`는 `int` 곱셈이다. 375 × 190 = 71250이다.
- **출력:** `%d` 뒤에 `원`을 붙여 `전기 요금: 71250원`으로 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

#define PRICE_PER_KWH 190  // charge per kWh in won

int main(void)
{
    int usage;  // monthly usage in kWh
    int fee;    // electricity bill in won

    printf("월 사용량(kWh)? ");
    scanf("%d", &usage);

    fee = usage * PRICE_PER_KWH;
    printf("전기 요금: %d원\n", fee);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall electric_bill.c -o electric_bill`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
월 사용량(kWh)? 375
전기 요금: 71250원
```

## 연습 문제 17: 기본 요금을 포함한 전기 요금 계산

**교재 문항:** 4장 프로그래밍 과제 3번

**문제:** 기본 요금과 월 사용량(kWh)을 입력받아 기본 요금 + 사용량 × 190원으로 전기 요금을 계산하라. 기본 요금을 위한 변수를 따로 두지 않고 복합 대입 연산자를 쓸 수 있다. 문제 전문과 실행 예시는 [연습 문제 17](Exercises.ko.md#연습-문제-17-기본-요금을-포함한-전기-요금-계산)에 있다.

### 풀이

**접근 방법:** 요금 변수 `fee`에 기본 요금을 먼저 읽은 뒤, 복합 대입 연산자 `+=`로 사용량 요금을 더한다([4장 7.1절](Concepts_Lecture.ko.md#71-단순-대입과-복합-대입)). 단가는 연습 문제 16과 같이 매크로 상수로 둔다.

- **입력:** `scanf("%d", &fee);`로 기본 요금을 `fee`에 바로 읽는다. 이 시점의 `fee`는 기본 요금이다.
- **복합 대입:** `fee += usage * PRICE_PER_KWH;`는 `fee = fee + usage * PRICE_PER_KWH;`와 같다. `+=`는 `*`보다 우선순위가 낮으므로 사용량 요금 71250이 먼저 계산되고, 2500 + 71250 = 73750이 `fee`에 저장된다.
- **출력:** 연습 문제 16과 같은 형식이다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

#define PRICE_PER_KWH 190  // charge per kWh in won

int main(void)
{
    int fee;    // starts as the basic charge, then the usage charge is added
    int usage;  // monthly usage in kWh

    printf("기본 요금? ");
    scanf("%d", &fee);
    printf("월 사용량(kWh)? ");
    scanf("%d", &usage);

    fee += usage * PRICE_PER_KWH;  // fee = fee + usage * PRICE_PER_KWH
    printf("전기 요금: %d원\n", fee);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall electric_bill_basic.c -o electric_bill_basic`으로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
기본 요금? 2500
월 사용량(kWh)? 375
전기 요금: 73750원
```

## 연습 문제 18: 월 값의 유효성 판별

**교재 문항:** 4장 프로그래밍 과제 4번

**문제:** 월을 입력받아 1~12이면 올바른 값, 아니면 잘못된 값이라고 출력하라. 조건 연산자의 피연산자 위치에 `printf` 호출을 쓸 수 있다. 문제 전문과 실행 예시는 [연습 문제 18](Exercises.ko.md#연습-문제-18-월-값의-유효성-판별)에 있다.

### 풀이

**접근 방법:** 1 이상 12 이하라는 범위 조건을 `month >= 1 && month <= 12`로 쓰고, 조건 연산자의 두 번째와 세 번째 피연산자 자리에 서로 다른 메시지를 출력하는 `printf` 호출을 둔다([4장 8.1절](Concepts_Lecture.ko.md#81-삼항-연산자)).

- **범위 조건:** 연습 문제 13과 같이 두 관계식을 `&&`로 잇는다. `month`가 15이면 `month <= 12`가 거짓이므로 조건 전체가 0이다.
- **`printf`를 피연산자로 쓰기:** `printf`는 출력한 문자(바이트)의 수를 반환하는 함수이므로 그 호출은 값을 가진 수식이고, 조건 연산자의 피연산자가 될 수 있다. 조건 연산자는 두 번째와 세 번째 피연산자 중 선택된 하나만 평가하므로, 두 메시지 중 하나만 출력된다.
- **수식 문장:** 조건 연산자 수식 끝에 `;`를 붙이면 문장이 되며, 수식의 값인 출력 바이트 수는 쓰지 않고 버린다.

같은 동작을 `printf((month >= 1 && month <= 12) ? "올바른 값입니다.\n" : "잘못된 값입니다.\n");`처럼 조건 연산자로 출력할 문자열을 고르는 방식으로도 쓸 수 있다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int month;

    printf("몇 월? ");
    scanf("%d", &month);

    // printf returns a value, so a call can be an operand of ?:
    (month >= 1 && month <= 12) ? printf("올바른 값입니다.\n")
                                : printf("잘못된 값입니다.\n");

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall month_check.c -o month_check`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
몇 월? 15
잘못된 값입니다.
```

경계값인 12와 0을 입력하면 각각 올바른 값과 잘못된 값으로 판별된다.

```text
몇 월? 12
올바른 값입니다.
```

```text
몇 월? 0
잘못된 값입니다.
```

## 연습 문제 19: 화씨 온도를 섭씨 온도로 변환

**교재 문항:** 4장 프로그래밍 과제 5번

**문제:** 화씨 온도를 실수로 입력받아 (화씨 온도 - 32) × 5/9로 섭씨 온도를 구해 출력하라. `5/9`는 정수 나눗셈으로 0이 되므로 `5.0/9.0`을 쓴다. 문제 전문과 실행 예시는 [연습 문제 19](Exercises.ko.md#연습-문제-19-화씨-온도를-섭씨-온도로-변환)에 있다.

### 풀이

**접근 방법:** 공식의 분수 $\frac{5}{9}$를 C로 옮길 때 정수 나눗셈이 일어나지 않게 실수 리터럴로 `5.0 / 9.0`이라고 쓴다([4장 2.4절](Concepts_Lecture.ko.md#24-수학-공식의-c-변환)).

- **정수 나눗셈의 함정:** `5 / 9`는 두 피연산자가 정수이므로 0이 되고, `(fahrenheit - 32) * (5 / 9)`는 입력과 관계없이 0이다.
- **계산:** `(fahrenheit - 32) * (5.0 / 9.0)`에 72를 입력하면 40 × 0.5555... = 22.222...이다.
- **계산 순서:** 괄호 없이 `(fahrenheit - 32) * 5 / 9`로 쓰면 `double`인 `(fahrenheit - 32) * 5`가 먼저 계산되므로 결과가 맞다. 그러나 `5 / 9 * (fahrenheit - 32)`처럼 순서를 바꾸면 `5 / 9`가 먼저 계산되어 0이 되므로, 상수를 `5.0 / 9.0`으로 써 두면 계산 순서와 관계없이 안전하다.
- **출력:** 섭씨 온도는 `%.2f`로 소수점 아래 2자리까지 반올림하여 `22.22`로 출력한다. 화씨 온도는 `%g`로 출력한다. `%g`는 기본 유효숫자 6자리 안에서 뒤쪽의 0과 소수점을 빼고 출력하므로, 72는 `72`로, 98.6은 `98.6`으로 출력된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double fahrenheit;  // temperature in degrees Fahrenheit
    double celsius;     // temperature in degrees Celsius

    printf("화씨온도? ");
    scanf("%lf", &fahrenheit);

    celsius = (fahrenheit - 32) * (5.0 / 9.0);  // 5 / 9 would be 0
    printf("%g F = %.2f C\n", fahrenheit, celsius);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall fahrenheit.c -o fahrenheit`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다. 소수가 있는 화씨 온도 98.6을 입력하면 입력값이 그대로 출력된다.

```text
화씨온도? 72
72 F = 22.22 C
```

```text
화씨온도? 98.6
98.6 F = 37.00 C
```

## 연습 문제 20: 운동 에너지 계산

**교재 문항:** 4장 프로그래밍 과제 6번

**문제:** 질량(kg)과 속력(m/s)을 실수로 입력받아 운동 에너지 = 1/2 × 질량 × 속력의 제곱을 구하라. 문제 전문과 실행 예시는 [연습 문제 20](Exercises.ko.md#연습-문제-20-운동-에너지-계산)에 있다.

### 풀이

**접근 방법:** 공식의 $\frac{1}{2}$을 실수 나눗셈 `1.0 / 2.0`으로 쓰고, 속력의 제곱은 곱셈을 반복하여 `speed * speed`로 쓴다([4장 2.4절](Concepts_Lecture.ko.md#24-수학-공식의-c-변환)).

- **분수 상수:** `1 / 2`는 정수 나눗셈으로 0이 되므로, 이렇게 쓰면 운동 에너지가 항상 0이 된다. `1.0 / 2.0`이나 `0.5`를 쓴다.
- **제곱:** C에는 거듭제곱 연산자가 없고 `^`는 비트 XOR 연산자이므로 `speed ^ 2`로 쓸 수 없다. `speed`가 `double`이면 `^`의 피연산자가 될 수 없어 컴파일 에러가 난다. `speed * speed`로 쓰거나 `<math.h>`의 `pow(speed, 2)`를 쓴다.
- **계산과 출력:** 0.5 × 5.5 × 4 × 4 = 44이며, `%.2f`로 `44.00`을 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    double mass;    // mass in kg
    double speed;   // speed in m/s
    double energy;  // kinetic energy in J

    printf("질량(kg)? ");
    scanf("%lf", &mass);
    printf("속력(m/s)? ");
    scanf("%lf", &speed);

    energy = 1.0 / 2.0 * mass * speed * speed;  // 1 / 2 would be 0
    printf("운동에너지: %.2f J\n", energy);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall kinetic_energy.c -o kinetic_energy`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
질량(kg)? 5.5
속력(m/s)? 4
운동에너지: 44.00 J
```

## 연습 문제 21: 퍼센트 농도 계산

**교재 문항:** 4장 프로그래밍 과제 7번

**문제:** 용매와 용질의 질량(g)을 정수로 입력받아 퍼센트 농도 = 용질 / (용매 + 용질) × 100을 구하라. 문제 전문과 실행 예시는 [연습 문제 21](Exercises.ko.md#연습-문제-21-퍼센트-농도-계산)에 있다.

### 풀이

**접근 방법:** 입력이 정수이므로 캐스트 연산자로 분자를 `double`로 바꾸어 실수 나눗셈이 되게 한다([4장 9.2절](Concepts_Lecture.ko.md#92-캐스트-연산자)).

- **정수 나눗셈의 함정:** `solute / (solvent + solute) * 100`은 24 / 224 = 0이 먼저 계산되어 0이 된다. `solute * 100 / (solvent + solute)`는 2400 / 224 = 10이 되어 소수 부분을 잃는다.
- **캐스트:** `(double)solute / (solvent + solute) * 100`에서 캐스트는 `solute`에만 적용되지만, 나눗셈의 한쪽이 `double`이므로 `(solvent + solute)`도 `double`로 변환되어 실수 나눗셈이 된다. 24.0 / 224 × 100 = 10.714...이다. `(double)(solute / (solvent + solute))`처럼 나눗셈 전체를 캐스트하면 정수 나눗셈이 먼저 끝난 0을 변환하므로 0.0이 된다.
- **`%` 출력:** 형식 문자열에서 `%`는 변환 지정의 시작이므로, 글자 `%`를 출력하려면 `%%`로 쓴다([3장 5.1절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#51-주요-지정자)). `"%.2f %%"`는 `10.71 %`를 출력한다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int solvent;           // mass of the solvent in grams
    int solute;            // mass of the solute in grams
    double concentration;  // percent concentration

    printf("용매(g)? ");
    scanf("%d", &solvent);
    printf("용질(g)? ");
    scanf("%d", &solute);

    // the cast makes the division a floating-point division
    concentration = (double)solute / (solvent + solute) * 100;
    printf("농도: %.2f %%\n", concentration);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall concentration.c -o concentration`으로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
용매(g)? 200
용질(g)? 24
농도: 10.71 %
```

> **주의:** 용매와 용질을 모두 0으로 입력하면 0.0을 0으로 나누므로, IEEE 754 환경에서 결과가 `nan`(Not a Number)이 된다. 용액의 질량은 0보다 크다고 가정한다.

```text
용매(g)? 0
용질(g)? 0
농도: nan %
```

## 연습 문제 23: 할인가와 에누리 금액 계산

**교재 문항:** 4장 프로그래밍 과제 9번

**문제:** 제품의 가격과 할인율(%)을 입력받아 할인가와 에누리 금액을 출력하라. 문제 전문과 실행 예시는 [연습 문제 23](Exercises.ko.md#연습-문제-23-할인가와-에누리-금액-계산)에 있다.

### 풀이

**접근 방법:** 에누리 금액은 가격 × 할인율 / 100이고, 할인가는 가격에서 에누리 금액을 뺀 값이다. 계산은 캐스트로 `double`에서 하고, 원 단위의 결과는 다시 캐스트로 정수로 만든다([4장 9.2절](Concepts_Lecture.ko.md#92-캐스트-연산자)).

- **정수 나눗셈의 함정:** `rate / 100 * price`로 쓰면 25 / 100 = 0이 먼저 계산되어 에누리 금액이 항상 0이 된다.
- **계산:** `(double)price * rate / 100`은 캐스트한 `price`가 `double`이므로 곱셈과 나눗셈이 모두 `double`로 계산된다. 12000.0 × 25 / 100 = 3000.0이다. `int`끼리 곱하면 가격이 1억 원이고 할인율이 25%일 때 곱 25억이 `int`의 최댓값(약 21억)을 넘지만, `double`로 계산하면 이런 오버플로가 없다.
- **원 단위 변환:** 바깥쪽 `(int)` 캐스트는 계산 결과의 소수 부분을 버리고 `int`로 변환한다. 캐스트 없이 `double` 값을 `int` 변수에 대입해도 같은 변환이 일어나지만, 캐스트로 쓰면 소수 부분을 버리는 의도가 코드에 드러난다.
- **출력:** 할인가는 12000 - 3000 = 9000이다. 입력 안내의 `%`는 `printf`의 형식 문자열 안에 있으므로 `%%`로 쓴다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    int price;       // price of the product in won
    int rate;        // discount rate in percent
    int discount;    // discount amount in won
    int sale_price;  // discounted price in won

    printf("제품의 가격? ");
    scanf("%d", &price);
    printf("할인율(%%)? ");
    scanf("%d", &rate);

    // compute in double, then drop the fraction of a won
    discount = (int)((double)price * rate / 100);
    sale_price = price - discount;
    printf("할인가: %d원 (%d원 할인)\n", sale_price, discount);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall discount.c -o discount`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
제품의 가격? 12000
할인율(%)? 25
할인가: 9000원 (3000원 할인)
```

> **참고:** 에누리 금액에 1원 미만이 생기면 `(int)` 캐스트가 소수 부분을 버린다. 9999원에서 15%를 할인하면 에누리 금액은 1499.85원이 아니라 1499원이 되고 할인가는 8500원이다. 반올림하려면 `(int)((double)price * rate / 100 + 0.5)`처럼 0.5를 더한 뒤 소수 부분을 버린다.

```text
제품의 가격? 9999
할인율(%)? 15
할인가: 8500원 (1499원 할인)
```

## 연습 문제 24: 바이트 단위의 16진수 출력

**교재 문항:** 4장 프로그래밍 과제 10번

**문제:** 부호 없는 정수를 16진수로 입력받아 최하위 바이트부터 각 바이트의 값을 16진수로 출력하라. `&` 연산자로 비트마스크를 적용한다. 문제 전문과 실행 예시는 [연습 문제 24](Exercises.ko.md#연습-문제-24-바이트-단위의-16진수-출력)에 있다.

### 풀이

**접근 방법:** 원하는 바이트를 오른쪽 시프트로 최하위 바이트 자리에 옮긴 뒤, 비트마스크 `0xFF`와 `&` 연산하여 그 8비트만 남긴다([4장 6.3절](Concepts_Lecture.ko.md#63-실전-예제-rgb-색상)). 연습 문제 4에서 RGB 값의 채널을 꺼낸 방법과 같다.

- **입력:** `%x`는 16진수를 읽어 `unsigned int` 변수에 저장하며, 앞에 붙은 `0x`나 `0X`도 받아들인다. 따라서 `0xa1b2c3d4`와 `a1b2c3d4`는 같은 값으로 읽힌다.
- **바이트 n:** 바이트 n은 비트 8n부터 8n + 7까지에 있으므로 `(data >> (8 * n)) & 0xFF`로 꺼낸다. 바이트 0은 시프트 없이 `data & 0xFF`로 `0xd4`를 얻고, 바이트 1은 `(data >> 8) & 0xFF`로 `0xa1b2c3`의 하위 8비트 `0xc3`을 얻는다.
- **바이트 3:** `unsigned int`가 32비트이면 `data >> 24`는 왼쪽이 0으로 채워지므로 마스크가 없어도 같은 값이지만, 네 바이트를 같은 형태로 꺼내도록 `& 0xFF`를 붙였다.
- **출력:** `%02x`는 소문자 16진수를 최소 2자리로, 빈자리를 0으로 채워 출력하므로 `0x05` 같은 바이트도 `05`로 출력된다([3장 5.2절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#52-출력-폭과-정렬)).

마스크를 먼저 적용하는 `(data & 0x0000FF00) >> 8`도 바이트 1을 꺼낸다. 마스크를 원하는 바이트 자리로 옮겨 두고 남은 비트를 오른쪽으로 옮기는 방식이다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    unsigned int data;  // 32-bit data read in hexadecimal

    printf("16진수로 데이터를 입력하세요: ");
    scanf("%x", &data);

    // shift the wanted byte down to bits 0-7, then keep only those bits
    printf("byte 0 : %02x\n", data & 0xFF);
    printf("byte 1 : %02x\n", (data >> 8) & 0xFF);
    printf("byte 2 : %02x\n", (data >> 16) & 0xFF);
    printf("byte 3 : %02x\n", (data >> 24) & 0xFF);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall bytes.c -o bytes`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
16진수로 데이터를 입력하세요: 0xa1b2c3d4
byte 0 : d4
byte 1 : c3
byte 2 : b2
byte 3 : a1
```

> **참고:** 입력이 8자리보다 짧으면 위쪽 바이트는 0이다. `1f`를 입력하면 바이트 1~3이 `00`으로 출력된다. 시프트와 마스크는 값의 비트 자리에 대한 연산이므로, 결과는 메모리에 바이트가 저장되는 순서(엔디언)와 관계없다.

```text
16진수로 데이터를 입력하세요: 1f
byte 0 : 1f
byte 1 : 00
byte 2 : 00
byte 3 : 00
```

## 연습 문제 25: 오버플로를 처리하는 RGB 색상 만들기

**교재 문항:** 4장 프로그래밍 과제 11번

**문제:** red, green, blue를 입력받아 연습 문제 3의 그림 2와 같은 배치(비트 0\~7에 red, 8\~15에 green, 16\~23에 blue)로 RGB 색상을 만들고 16진수로 출력하라. 255보다 큰 값은 오버플로로 처리하여, 256은 0으로 저장한다. 문제 전문과 실행 예시는 [연습 문제 25](Exercises.ko.md#연습-문제-25-오버플로를-처리하는-rgb-색상-만들기)에 있다.

### 풀이

**접근 방법:** 각 채널을 `& 0xFF`로 하위 8비트만 남겨 오버플로를 처리한 뒤, 왼쪽 시프트와 비트 OR로 합친다([4장 6.3절](Concepts_Lecture.ko.md#63-실전-예제-rgb-색상)). 비트 배치는 [연습 문제 3의 풀이](#연습-문제-3-red-green-blue-값을-16진수-rgb-값으로-변환)와 같지만, 범위를 넘는 값을 처리한다는 점과 출력 형식이 다르다.

- **입력:** 세 값을 `unsigned int` 변수에 `%u`로 읽는다. `%hhu`로 `unsigned char`에 바로 읽으면 범위를 넘는 입력에 대한 결과가 C 표준에서 정의되지 않으므로, 넓은 형으로 읽은 뒤 마스크로 줄인다.
- **오버플로 처리:** `red &= 0xFF;`는 `red = red & 0xFF;`이며 비트 8 이상을 모두 0으로 만든다. 256(`0x100`)은 하위 8비트가 모두 0이므로 0이 되고, 300(`0x12C`)은 `0x2C`(44)가 된다. 이것은 값을 `unsigned char` 변수에 저장할 때 상위 비트가 잘려 256으로 나눈 나머지가 남는 오버플로와 같은 결과이다([3장 1.1절](../Ch03_Data-Types-and-Variables/Concepts_Lecture.ko.md#오버플로와-언더플로)).
- **처리하지 않을 때:** 연습 문제 3의 풀이처럼 마스크 없이 합치면 red의 256이 비트 8을 켜서 green의 값을 바꾼다. 마스크를 먼저 적용하면 각 채널이 자기 8비트 안에 머문다.
- **결합:** `(blue << 16) | (green << 8) | red`는 `0xFF`, `0x80`, `0x00`을 각각 비트 16, 8, 0의 자리에 놓아 `0xFF8000`을 만든다.
- **출력:** `%06X`는 대문자 16진수를 최소 6자리로, 빈자리를 0으로 채워 출력한다. 연습 문제 3의 `%#08X`와 달리 `0X` 접두사가 없으며, 값이 0이어도 `000000`으로 6자리가 유지된다.

**코드:**

```c
#define _CRT_SECURE_NO_WARNINGS  // allows scanf in Visual Studio
#include <stdio.h>

int main(void)
{
    unsigned int red, green, blue;  // color channels
    unsigned int rgb;               // 0x00BBGGRR

    printf("red? ");
    scanf("%u", &red);
    printf("green? ");
    scanf("%u", &green);
    printf("blue? ");
    scanf("%u", &blue);

    // keep only the lower 8 bits, as storing into unsigned char would
    red &= 0xFF;
    green &= 0xFF;
    blue &= 0xFF;

    rgb = (blue << 16) | (green << 8) | red;
    printf("RGB 색상: %06X\n", rgb);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall rgb_color.c -o rgb_color`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다. red에 입력한 256은 0으로 저장된다.

```text
red? 256
green? 128
blue? 255
RGB 색상: FF8000
```

red에 300, blue에 511을 입력하면 각각 하위 8비트인 `0x2C`와 `0xFF`가 남는다.

```text
red? 300
green? 0
blue? 511
RGB 색상: FF002C
```
