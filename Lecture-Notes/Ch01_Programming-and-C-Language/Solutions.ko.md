## 연습 문제 1: 소프트웨어를 가리키는 용어

**교재 문항:** 1장 연습 문제 1번

**문제:** 소프트웨어를 가리키는 용어를 모두 쓰라. 문제 전문은 [연습 문제 1](Exercises.ko.md#연습-문제-1-소프트웨어를-가리키는-용어)에 있다.

### 풀이

**정답:** 프로그램, 응용 프로그램(application), 앱(app)

**해설:** 소프트웨어는 하드웨어에서 실행되어 하드웨어에게 무엇을 할지 지시하는 프로그램의 집합이다([1장 1.1절](Concepts_Lecture.ko.md#11-소프트웨어와-프로그램)). 따라서 소프트웨어를 가리킬 때는 프로그램이라는 말을 함께 쓰며, 사용자의 작업을 처리하는 소프트웨어는 응용 프로그램(application)이라고 하고, 스마트폰에서 실행되는 응용 프로그램은 흔히 앱(app)이라고 부른다.

- **프로그램:** 특정 작업을 수행하도록 프로그래밍 언어로 작성된 명령어의 집합이다.
- **응용 프로그램:** 운영체제 같은 시스템 소프트웨어 위에서 사용자의 목적(문서 작성, 게임 등)을 위해 실행되는 소프트웨어이다.
- **앱:** application을 줄인 말로, 스마트폰과 태블릿에서 쓰는 응용 프로그램을 주로 가리킨다.

## 연습 문제 2: 프로그래밍 언어에 대한 설명

**교재 문항:** 1장 연습 문제 2번

**문제:** 기계어, 어셈블리어, 고급 언어, 컴파일러에 대한 일곱 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 2](Exercises.ko.md#연습-문제-2-프로그래밍-언어에-대한-설명)에 있다.

### 풀이

**정답:** ①, ③, ⑦

**해설:** 기계어와 어셈블리어는 저급 언어이고 특정 CPU에 종속되며, 고급 언어는 기계 독립적이다([1장 1.2절](Concepts_Lecture.ko.md#12-프로그래밍-언어), [1.3절](Concepts_Lecture.ko.md#13-기계-종속-vs-기계-독립)).

- **① (잘못됨):** 기계어 명령어는 특정 CPU가 직접 실행하는 2진 코드이고, CPU 아키텍처마다 명령어 집합이 다르다. 기계어 프로그램은 그 CPU에서만 실행되므로 CPU가 달라지면 프로그램을 다시 작성해야 한다.
- **② (옳음):** 어셈블리어는 `MOV`, `ADD` 같은 니모닉으로 기계어 명령어를 나타내며, 니모닉 하나가 기계어 명령어 하나에 대응한다.
- **③ (잘못됨):** 어셈블리어는 기계어와 일대일로 대응하므로 기계어와 마찬가지로 기계 종속적이다. x86용 어셈블리어 프로그램은 ARM CPU에서 실행할 수 없다.
- **④ (옳음):** 고급 언어로 작성한 소스 코드는 각 시스템의 컴파일러로 번역하면 여러 플랫폼에서 실행할 수 있다.
- **⑤ (옳음):** C, C++, Java, Python은 모두 사람의 언어에 가까운 문법을 쓰는 고급 언어이다.
- **⑥ (옳음):** 컴파일러는 고급 언어로 된 소스 코드를 실행 전에 한꺼번에 기계어로 번역하는 프로그램이다(연습 문제 3).
- **⑦ (잘못됨):** 기계어와 어셈블리어는 하드웨어에 가까운 저급 언어이다.

## 연습 문제 3: 소스 파일을 기계어로 번역하는 프로그램

**교재 문항:** 1장 연습 문제 3번

**문제:** 고급 언어로 작성된 소스 파일을 기계어로 번역하는 프로그램의 이름을 쓰라. 문제 전문은 [연습 문제 3](Exercises.ko.md#연습-문제-3-소스-파일을-기계어로-번역하는-프로그램)에 있다.

### 풀이

**정답:** 컴파일러(compiler)

**해설:** 컴파일러는 전체 소스 코드를 실행하기 전에 한꺼번에 기계어로 번역한다([1장 1.2절](Concepts_Lecture.ko.md#12-프로그래밍-언어)). 실행 시점에 한 줄씩 번역하며 실행하는 인터프리터(interpreter)와 구분된다. C는 컴파일러를 쓰는 대표적인 언어이다.

> **참고:** **넓은 의미와 좁은 의미의 컴파일.** 이 문제의 컴파일러는 소스 코드를 기계어로 만드는 번역기 전체를 가리킨다. C의 빌드 과정을 단계별로 나누면, 좁은 의미의 컴파일러는 전처리된 C 코드를 어셈블리 코드로 번역하고, 어셈블러가 이를 기계어로 된 오브젝트 파일로 바꾸며, 링커가 오브젝트 파일과 라이브러리를 결합하여 실행 파일을 만든다([1장 3.2절](Concepts_Lecture.ko.md#32-빌드-과정)). `gcc` 같은 컴파일러 드라이버는 이 단계들을 한 번에 수행한다.

## 연습 문제 4: C 언어를 배우는 이유

**교재 문항:** 1장 연습 문제 4번

**문제:** C 언어를 배워야 하는 이유에 대한 다섯 가지 설명 중 이유가 아닌 것을 모두 고르라. 보기는 [연습 문제 4](Exercises.ko.md#연습-문제-4-c-언어를-배우는-이유)에 있다.

### 풀이

**정답:** ③, ⑤

**해설:** C를 배우는 이유는 기초 체력, 시스템 프로그래밍의 공용어, 다른 언어의 기반이라는 세 가지로 정리된다([1장 2.4절](Concepts_Lecture.ko.md#24-c를-배워야-하는-이유)).

- **① (이유임):** OS API, 하드웨어 인터페이스, 수많은 알고리즘과 라이브러리가 C로 개발되어 공개되어 있으므로 C는 프로그래머 사이의 공용어 역할을 한다.
- **② (이유임):** C로 작성된 자료와 라이브러리가 많으므로 C를 알면 이러한 프로그래밍 정보를 쉽게 활용할 수 있다.
- **③ (이유가 아님):** 개발할 응용 프로그램마다 적합한 언어가 따로 있으므로 C만으로 모든 문제를 해결할 수는 없다. C를 알면 C의 문법과 의미론을 차용한 C++, Java, C# 같은 다른 언어를 배우기가 쉬워질 뿐이다.
- **④ (이유임):** C는 제어 구조, 함수, 사용자 정의형 같은 프로그래밍의 기본 개념을 직접 다루게 한다.
- **⑤ (이유가 아님):** 사실은 반대이다. C는 메모리 구조, 포인터, 수동 자원 관리를 직접 다루므로, 다른 언어에서는 숨겨진 프로그램의 내부 동작 원리를 이해하게 해 준다.

## 연습 문제 5: C 언어의 활용 분야

**교재 문항:** 1장 연습 문제 5번

**문제:** C 언어의 활용 분야에 대한 다섯 가지 설명 중 잘못된 것을 고르라. 보기는 [연습 문제 5](Exercises.ko.md#연습-문제-5-c-언어의-활용-분야)에 있다.

### 풀이

**정답:** ③

**해설:** 임베디드 시스템은 시스템 자원이 충분한 환경이 아니라 제한된 환경이다. 가전제품이나 자동차의 제어 장치에 들어가는 컴퓨터는 메모리, 처리 능력, 전력이 제한되어 있으며, C는 메모리 사용량이 작고 효율적인 기계어로 컴파일되므로 이런 환경에 적합하다([1장 2.2절](Concepts_Lecture.ko.md#22-특징), [2.3절](Concepts_Lecture.ko.md#23-활용-분야)).

- **① (옳음):** C는 표준 C로 작성하면 거의 모든 플랫폼에서 컴파일할 수 있어 운영체제 같은 시스템 프로그램 개발에 쓰인다.
- **② (옳음):** C는 런타임 오버헤드가 작아 성능이 최우선인 프로그램에 적합하다.
- **④ (옳음):** 그래픽, 수치 해석 같은 고성능 라이브러리는 C로 개발되는 경우가 많다.
- **⑤ (옳음):** 게임 엔진(예: Unreal Engine)은 주로 C/C++로 개발된다.

## 연습 문제 6: C 언어의 장점

**교재 문항:** 1장 연습 문제 6번

**문제:** C 언어의 특징에 대한 여섯 가지 설명 중 장점이 아닌 것을 모두 고르라. 보기는 [연습 문제 6](Exercises.ko.md#연습-문제-6-c-언어의-장점)에 있다.

### 풀이

**정답:** ②, ④

**해설:** C의 장점은 간결한 문법, 유연성, 고성능, 이식성, 고수준과 저수준 기능의 동시 지원이고, 단점은 배우기와 사용하기가 어렵다는 점이다([1장 2.2절](Concepts_Lecture.ko.md#22-특징)).

- **① (장점):** C는 키워드가 적고 언어 설계가 최소한으로 이루어진 간결한 언어이다.
- **② (장점이 아님):** C는 프로그램을 함수 단위로 나누어 작성하는 절차적 언어이며 객체지향 프로그래밍을 지원하지 않는다. 객체지향 프로그래밍은 C++, C#, Java, Python 등이 지원한다.
- **③ (장점):** C는 포인터를 통한 직접 메모리 접근과 비트 연산 같은 어셈블리어 수준의 저수준 기능을 제공하면서도, 고급 언어이므로 표준 C로 작성한 프로그램은 기계 독립적이다. 이 두 성질을 함께 갖춘 것이 C의 대표적인 장점이다.
- **④ (장점이 아님):** C는 저수준 기능과 적은 제약 때문에 배우기도 사용하기도 어렵다. 배열 범위 검사나 가비지 컬렉터가 없으므로 포인터와 메모리를 다룰 때 프로그래머가 각별히 주의해야 한다.
- **⑤ (장점):** C는 제약이 적어 프로그래머가 세밀하게 제어할 수 있는 유연한 언어이다.
- **⑥ (장점):** C는 효율적인 기계어로 컴파일되므로 성능이 우수한 프로그램을 만들 수 있다.

## 연습 문제 7: 특수 목적 장치에서 수행되는 프로그램

**교재 문항:** 1장 연습 문제 7번

**문제:** 가전제품, 자동차, 네트워크 장비처럼 특수 목적의 컴퓨터를 내장한 장치에서 수행되는 프로그램의 이름을 쓰라. 문제 전문은 [연습 문제 7](Exercises.ko.md#연습-문제-7-특수-목적-장치에서-수행되는-프로그램)에 있다.

### 풀이

**정답:** 임베디드 프로그램(embedded program)

**해설:** 특수 목적의 컴퓨터를 내장한 장치 자체는 임베디드 시스템(embedded system)이고, 그 장치에서 수행되는 프로그램이 임베디드 프로그램이다([1장 2.3절](Concepts_Lecture.ko.md#23-활용-분야)). 문제는 장치가 아니라 프로그램을 묻고 있으므로 두 용어를 구분해야 한다. 임베디드 프로그램은 시스템 자원이 제한된 환경에서 동작하므로 C로 작성되는 경우가 많다(연습 문제 5).

## 연습 문제 8: C 언어와 C++ 언어

**교재 문항:** 1장 연습 문제 8번

**문제:** C와 C++의 관계에 대한 다섯 가지 설명 중 잘못된 것을 고르라. 보기는 [연습 문제 8](Exercises.ko.md#연습-문제-8-c-언어와-c-언어)에 있다.

### 풀이

**정답:** ②

**해설:** 호환성의 방향이 반대이다. C++이 C를 이어받아 만들어졌으므로 C++이 C와의 호환성을 제공하며, C 프로그램이 C++ 프로그램의 범주에 들어간다. 따라서 유효한 C 프로그램은 C++ 프로그램으로 다룰 수 있지만, 클래스처럼 C++에만 있는 기능을 쓴 C++ 프로그램은 C 프로그램이 아니다.

- **① (옳음):** C++은 C에 클래스와 상속 같은 객체지향 기능을 더한 언어이다.
- **③ (옳음):** GCC나 Visual C++ 같은 컴파일러는 소스 파일의 확장자가 `.c`이면 C로, `.cpp`이면 C++로 컴파일하므로 확장자를 바꾸면 같은 코드가 C++ 프로그램으로 컴파일된다([1장 3.2절](Concepts_Lecture.ko.md#32-빌드-과정)).
- **④ (옳음):** 대부분의 C 컴파일러는 C 컴파일러와 C++ 컴파일러의 역할을 함께 제공한다.
- **⑤ (옳음):** C로 개발된 라이브러리는 C++ 프로그램에서도 호출할 수 있다.

> **참고:** **C와 C++의 호환성의 한계.** 교재는 C를 C++의 부분집합처럼 설명하지만, 두 언어는 별도로 표준화되어 일부 차이가 있다. 예를 들어 C에서는 `int *p = malloc(sizeof(int));`처럼 `void *`를 다른 포인터형에 묵시적으로 대입할 수 있지만 C++에서는 형 변환을 써야 하고, `class`나 `new`를 변수 이름으로 쓴 C 코드는 C++에서 컴파일되지 않는다. 또 C++에서 C 라이브러리 함수를 호출하려면 함수 선언에 `extern "C"` 링크 지정이 필요하며, 표준 C 헤더는 이를 미리 갖추고 있다. 따라서 ③의 확장자 변경은 대부분의 C 코드에 통하는 간단한 방법이지만 모든 C 코드가 그대로 C++ 코드가 되는 것은 아니다.

## 연습 문제 9: C 프로그램의 개발 과정

**교재 문항:** 1장 연습 문제 9번

**문제:** 일반적인 C 프로그램의 개발 과정에서 소스 코드 작성 앞의 단계 (가)와 실행 앞의 단계 (나)를 쓰라. 문제 전문과 그림은 [연습 문제 9](Exercises.ko.md#연습-문제-9-c-프로그램의-개발-과정)에 있다.

### 풀이

**해설:** C 프로그램은 설계, 코드 작성, 컴파일, 실행의 순서로 개발하고, 오류가 있으면 디버깅을 거쳐 앞 단계로 돌아간다([1장 3.1절](Concepts_Lecture.ko.md#31-개발-과정)).

## 연습 문제 10: 개발 과정에 대한 설명

**교재 문항:** 1장 연습 문제 10번

**문제:** C 프로그램의 개발 과정에 대한 일곱 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 10](Exercises.ko.md#연습-문제-10-개발-과정에-대한-설명)에 있다.

### 풀이

**정답:** ②, ⑤, ⑥

**해설:** 설계 단계의 산출물은 특정 언어에 묶이지 않은 알고리즘이고, 컴파일은 소스 파일 단위로 이루어지며, 실행 파일을 만들려면 항상 링크가 필요하다([1장 3.1절](Concepts_Lecture.ko.md#31-개발-과정), [3.2절](Concepts_Lecture.ko.md#32-빌드-과정)).

- **① (옳음):** 설계 단계에서 문제를 분석하여 알고리즘을 도출한다.
- **② (잘못됨):** 설계 단계에서는 알고리즘을 자연어, 순서도, 의사 코드로 표현한다. 알고리즘을 특정 프로그래밍 언어로 기술하는 것은 다음 단계인 코드 작성이다.
- **③ (옳음):** 소스 코드는 텍스트 편집기나 IDE의 소스 코드 편집기로 작성한다.
- **④ (옳음):** 전처리기는 컴파일 전에 `#include`로 지정한 헤더 파일을 포함하고 `#define` 매크로를 대치하며 주석을 제거하여, 소스 파일이 컴파일될 수 있게 준비한다.
- **⑤ (잘못됨):** 소스 파일은 하나로 합쳐지지 않고 파일마다 따로 컴파일되어 소스 파일 하나당 오브젝트 파일이 하나씩 만들어진다. 여러 오브젝트 파일을 하나의 실행 파일로 결합하는 것은 링커의 일이다.
- **⑥ (잘못됨):** 오브젝트 파일이 하나뿐이어도 `printf`처럼 라이브러리에 정의된 함수에 대한 외부 참조가 해결되지 않은 상태이므로, 라이브러리와 링크해야 실행 파일이 만들어진다.
- **⑦ (옳음):** 링크 단계에서 링커가 오브젝트 파일과 라이브러리를 연결하여 실행 파일을 만든다.

## 연습 문제 11: Visual Studio의 프로젝트와 솔루션

**문제:** Visual Studio의 프로젝트와 솔루션에 대한 여섯 가지 설명 중 잘못된 것을 모두 고르라. 보기는 [연습 문제 11](Exercises.ko.md#연습-문제-11-visual-studio의-프로젝트와-솔루션)에 있다.

### 풀이

**정답:** ①, ⑥

**해설:** 프로젝트는 프로그램 하나를 만드는 데 필요한 정보를 담고, 솔루션은 서로 관련된 프로젝트를 모아 관리하는 작업 공간이다([1장 3.5절](Concepts_Lecture.ko.md#35-통합-개발-환경)).

- **⑤ (옳음):** 한 솔루션에 관련된 프로젝트를 여러 개 추가하여 함께 관리할 수 있다.
- **⑥ (잘못됨):** 솔루션 하나에 프로젝트를 여러 개 넣을 수 있으므로 둘은 일대일로 대응하지 않는다.

## 연습 문제 12: 버전 정보를 출력하는 프로그램

**교재 문항:** 1장 프로그래밍 과제 1번

**문제:** Visual Studio에서 `C:\work\chap01` 위치에 빈 프로젝트 `second`를 만들고, 주어진 내용의 소스 파일 `second.c`를 추가하여 빌드하고 실행하라. 문제 전문과 소스 코드는 [연습 문제 12](Exercises.ko.md#연습-문제-12-버전-정보를-출력하는-프로그램)에 있다.

### 풀이

**접근 방법:** 문제가 소스 코드를 모두 제시하므로, Visual Studio에서 프로젝트를 만들고 빌드하여 실행하는 절차를 익히는 것이 목적이다([1장 3.5절](Concepts_Lecture.ko.md#35-통합-개발-환경)).

1. **프로젝트 생성:** [새 프로젝트 만들기]에서 C++, Windows, 콘솔 조건의 빈 프로젝트를 고르고, 프로젝트 이름에 `second`, 위치에 `C:\work\chap01`을 입력한다. 이때 솔루션이 함께 만들어진다.
2. **소스 파일 추가:** 솔루션 탐색기의 [소스 파일]에 새 항목을 추가하면서 이름을 `second.c`로 지정한다. 확장자가 `.c`이므로 C++ 파일 항목을 골라도 C로 컴파일된다.
3. **빌드:** [빌드] → [솔루션 빌드]로 전처리, 컴파일, 어셈블, 링크를 한 번에 수행하여 실행 파일 `second.exe`를 만든다.
4. **실행:** [디버그] → [디버그하지 않고 시작]으로 실행하면 콘솔 창에 결과가 나타난다.

소스 코드의 각 줄이 하는 일은 다음과 같다([2장 1.1절](../Ch02_C-Program-Basics/Concepts_Lecture.ko.md#11-프로그램-구조)).

- **`#include <stdio.h>`:** 전처리기가 표준 입출력 헤더 파일의 내용을 포함하여 `printf` 함수의 선언을 제공한다.
- **`int main(void)`:** 프로그램이 시작될 때 처음 호출되는 진입점 함수이다.
- **`printf(...)`:** 큰따옴표 안의 문자열을 그대로 출력하고, `\n`에서 줄을 바꾼다. `Date` 뒤의 공백 네 칸은 `Version` 줄과 콜론의 위치를 맞추기 위한 것이다.
- **`return 0;`:** `main`이 0을 반환하여 운영체제에 정상 종료를 알린다.

**코드:**

```c
#include <stdio.h>

int main(void)
{
    printf("Second C Program\n");
    printf("Date    : 2022.1.1\n");
    printf("Version : 1.0\n");

    return 0;
}
```

**실행 결과:** 같은 코드를 `gcc -std=c99 -Wall second.c -o second`로 컴파일하면 경고 없이 컴파일되고, 실행하면 실행 예시와 같은 세 줄이 출력된다.

```text
Second C Program
Date    : 2022.1.1
Version : 1.0
```

## 연습 문제 13: 사칙연산 결과를 출력하는 프로그램

**교재 문항:** 1장 프로그래밍 과제 2번

**문제:** Visual Studio에서 `C:\work\chap01` 위치에 빈 프로젝트 `calculator`를 만들고, 55와 33의 사칙연산 결과를 출력하는 소스 파일 `calculator.c`를 추가하여 빌드하고 실행하라. 문제 전문과 소스 코드는 [연습 문제 13](Exercises.ko.md#연습-문제-13-사칙연산-결과를-출력하는-프로그램)에 있다.

### 풀이

**접근 방법:** 프로젝트를 만들고 빌드하여 실행하는 절차는 연습 문제 12와 같다. 이 프로그램에서는 `printf`가 형식 문자열 안의 `%d` 자리에 뒤따르는 인자의 값을 10진 정수로 바꾸어 출력한다는 점을 확인한다([2장 2.2절](../Ch02_C-Program-Basics/Concepts_Lecture.ko.md#22-printf)).

- **형식 문자열:** `"55 + 33 = %d\n"`에서 `%d`를 뺀 나머지 글자 `55 + 33 = `는 그대로 출력된다. 이 부분은 문자열이므로 계산되지 않는다.
- **인자:** 두 번째 인자 `55 + 33`은 수식이므로 함수가 호출되기 전에 계산되어 88이 `%d` 자리에 들어간다.
- **정수 나눗셈:** `55 / 33`은 두 피연산자가 모두 정수이므로 몫만 남기고 소수 부분을 버린 1이 된다([4장 2.2절](../Ch04_Operators/Concepts_Lecture.ko.md#22-정수-나눗셈-vs-실수-나눗셈)). 55 = 33 × 1 + 22이므로 나머지 22는 `55 % 33`으로 구할 수 있다.

**코드:**

```c
#include <stdio.h>

int main(void)
{
    printf("55 + 33 = %d\n", 55 + 33);
    printf("55 - 33 = %d\n", 55 - 33);
    printf("55 * 33 = %d\n", 55 * 33);
    printf("55 / 33 = %d\n", 55 / 33);

    return 0;
}
```

**실행 결과:** `gcc -std=c99 -Wall calculator.c -o calculator`로 경고 없이 컴파일되며, 실행 예시와 같은 결과가 출력된다.

```text
55 + 33 = 88
55 - 33 = 22
55 * 33 = 1815
55 / 33 = 1
```
